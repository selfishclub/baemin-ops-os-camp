# 10월 2일 중간 점검 · 10월 14일 최종 발표 — 과제 안내

**현재 일정(2026년): 10월 2일(금) 온라인 중간 점검 전 v2 완성 → 10월 2일 결과물·만든 과정 공유, 서로 피드백, 개인 저장소로 옮기기 → 10월 14일(수) 피드백 반영한 최종 버전 공유·발표.**

이번 과제의 목적은 **내가 만든 도구가 실제 장사와 가게 운영에 도움이 되게 만드는 것**입니다.
손님에게 더 빨리 답하기, 주문·예약 놓치지 않기, 직원의 반복 일 줄이기처럼 **내 가게에서 바꾸고 싶은 장면** 하나를 기준으로 삼습니다.

## 먼저 — 내 가게에서 무엇이 좋아져야 하나요?

"**누가, 언제 이 도구를 쓰고, 어떤 일이 더 잘되기를 바라나요?**"에 한 문장으로 답합니다. 이 답을 기준으로 만들 기능과 볼 숫자를 고릅니다.
아래는 고르는 예시입니다. 전부 만들거나 잴 필요는 없습니다.

| 내가 겪는 문제 | 도구를 쓰고 할 행동 | 도움이 됐는지 볼 것 |
|---|---|---|
| 리뷰·문의에 답하는 걸 놓쳐요 | 아직 답 안 한 리뷰를 찾아 답하기 | 답하기까지 걸린 시간, 안 단 리뷰 건수 |
| 직원마다 일하는 방법이 달라요 | 매뉴얼·체크리스트 보고 그대로 하기 | 물어보는 횟수, 빠뜨린 일 건수 |
| 급여·정산·원가 계산에 손이 많이 가요 | 숫자만 넣고 결과 확인하기 | 한 번 계산하는 데 걸린 시간, 틀린 횟수 |
| 날씨·요일에 따라 준비량을 감으로 정해요 | 준비 체크리스트 보고 정하기 | 남거나 모자란 날 수 |

## 1. 10/2 전까지 — v2 완성하고, 만든 과정 정리하기

**v2는 10/2 점검 전까지 완성해 옵니다.** 점검 시간에는 새로 만들지 않고, 보여 주고 서로 써 봅니다.

1. **계획부터 고칩니다.** `v1/사용메모.md`(써 본 기록)와 `v2/PRD.md`를 AI에게 주고 v2 계획을 다듬습니다. → [계획 수정 프롬프트](프롬프트.md#1-v2-계획-고치기)
   AI가 더 제안한 것은 **'추천'**으로 따로 받고, 내가 고른 것만 넣습니다. **계획을 읽고 확인한 다음에 만듭니다.**
2. **만듭니다.** `v2/프로젝트/`에서 만들고 한 기능 될 때마다 커밋·push합니다.
3. **직접 써 봅니다.** 된 것과 아직 안 된 것을 나눕니다. 실제 가게에 아직 못 썼으면 예시로 시험하고 **'예시 시험'**이라고 적습니다.
4. **Vercel 주소로 열리는지** 폰에서 확인합니다. 다른 사장님이 10/2에 이 주소로 써 봅니다.
5. **만든 과정을 정리합니다.** `중간점검_1002.md`의 1~5번을 채웁니다. → [과정 정리 프롬프트](프롬프트.md#2-만든-과정-정리하기)

### 저장·대시보드·CLAUDE.md — 내 도구에 필요한 만큼

| 할 일 | 쉽게 말하면 | 누가 |
|---|---|---|
| Vercel에 올리기 | 다른 폰에서도 열리는 **웹 주소** 만들기 | **모두** |

## 4. 10/14(수) 최종 발표 · 공유

**제출할 것은 두 개입니다.** 내 폴더의 **`피드백_반영_1014.md`에 짧게 답하고**, **`발표자료.html`을 올립니다.** 긴 보고서는 쓰지 않습니다.
그리고 `v2/제출서.md`와 `v2/결과물/최종_첫화면.png`를 최종 버전으로 바꿉니다. 구경하기 표에 최종본이 올라갑니다.

### 발표자료.html — 담을 다섯 가지

HTML은 **브라우저에서 여는 발표 파일**입니다. → [발표자료 프롬프트](프롬프트.md#3-발표자료html-만들기)

| 꼭 담을 내용 | 이 질문에 답합니다 |
|---|---|
| **왜 만들었나요?** | 누가 어떤 일에서 불편했나요? 그 때문에 손님 응대·장사·운영에서 어떤 문제가 생겼나요? |
| **숫자로 무엇이 달라졌나요?** | 만들기 전과 후에 같은 일의 시간·비용·주문·누락 건수 등이 어떻게 달라졌나요? |
| **생각과 느낌은 어떻게 달라졌나요?** | 나와 직원의 일하는 방법, 손님과의 대화가 어떻게 달라졌나요? 직접 겪은 장면으로. |
| **10/2 피드백으로 무엇을 고쳤나요?** | 받은 의견 중 무엇을 고쳤고, 다시 써 보니 어땠나요? |
| **앞으로 무엇을 더 만들고 싶나요?** | 다음에 해결할 가게 문제, 왜 그게 먼저인지, 잘됐는지 무엇으로 확인할지. |

**전후 비교는 이렇게 적습니다.**

> 설명용 가상 예시: "같은 리뷰 답글 10건을 다는 데 예전에는 30분, 최종 버전에서는 10분이 걸렸습니다. 이틀 동안 기록했습니다. 줄어든 시간은 단골 손님 연락에 썼습니다. 주문이 늘었는지는 아직 확인하지 못했습니다."

- **무슨 일을, 어느 기간에, 몇 번** 비교했는지, After가 v2인지 최종 버전인지 적습니다.
- **직접 잰 값 / 예상한 값 / 아직 안 잰 값**을 나눕니다. 안 쟀으면 다음에 어떻게 확인할지 적습니다.
- 매출·주문이 늘었다면 같은 기간의 행사·광고·날씨 같은 다른 변화도 적습니다. 도구 하나 덕분이라고 단정하지 않습니다.
- '편해졌다'에서 한 걸음 더 — **그 덕분에 생긴 시간을 어디에 썼는지** 말합니다. 아직이면 계획이라고 적습니다.

`발표자료.html`은 **내 폴더 바로 아래**(`02_실전캠프_Day2_실습제출/[내폴더]/발표자료.html`)에 올립니다. 이미지가 따로 있으면 `발표자료_이미지/` 폴더에 같이 올립니다. 올린 뒤 내려받아 브라우저에서 열리는지 확인합니다. 분량과 시간은 따로 정하지 않습니다.

### 서로 공유

- 10/14까지 만든 코드와 `CLAUDE.md`는 **개인 저장소(Public)**에서 다른 사장님이 볼 수 있게 둡니다. **최종 발표가 끝난 뒤에는 Private(비공개)으로 바꿔도 됩니다.**
- 실제 손님 정보, 비밀번호·API 키, 실제 매출 파일은 올리지 않습니다. 이미 들어가 있으면 운영진에게 먼저 말합니다.
