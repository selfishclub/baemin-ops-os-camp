## 1. v2 계획 고치기

`v1/사용메모.md`, `v1/PRD.md`, `v2/PRD.md`를 함께 줍니다. 받은 의견이나 회의록이 있으면 같이 붙여넣습니다.

```text
내가 만든 가게 운영 도구를 v2로 고치고 싶어. 아직 만들지는 말고 계획부터 고쳐 줘.

일정은 2026년 10월 1일(목) 밤 11시 59분까지 v2 완성·push, 10월 2일에 온라인 중간 점검이야.
10월 2일에 결과물과 만든 과정을 공유하고 서로 피드백을 받은 뒤,
실제 사용 경험과 함께 반영해서 10월 10일까지 최종 버전을 완성할 거야.
이 일정에 맞춰 v2에서 완성할 것과 점검 후 고칠 것을 나눠 줘.
시간 안에 어려운 부분이 있으면 숨기지 말고 범위 조정안을 '추천'으로 제안해 줘.

내 도구: [무엇을 만들었는지]
만든 이유: [누가 어떤 일에서 겪는 문제를 해결하고 싶은지]
내 가게에서 바라는 변화: [손님 응대, 주문·예약, 비용, 직원 일 등]
v1 계획과 지금 되는 기능: v1/PRD.md, v1/제출서.md
v1을 써 본 기록과 받은 의견: v1/사용메모.md, [다른 의견이 있으면 붙여넣기]
v2 계획 초안: v2/PRD.md

1. 써 본 기록·의견 중 무엇을 v2 계획에 넣었는지 알려 줘. 안 넣은 것은 이유도.
2. 내가 놓친 것이 있으면 '추천'이라고 따로 써 줘. 내가 고른 것만 계획에 넣어 줘.
3. 데이터 저장이 필요한 도구라면 Supabase에 어떤 표와 항목이 필요하고, 왜 그렇게 나누는지 쉽게 설명해 줘.
   저장이 필요 없는 도구라면 그렇다고 말해 줘.
4. 저장한 정보로 가게 일 상태를 보는 대시보드가 필요한지, 필요하면 누가 보고 어떤 행동을 할지,
   어떤 숫자나 목록이 필요한지 계획해 줘.
5. 기능마다 어떤 가게 문제가 해결되는지, 잘되는지 확인할 방법을 적어 줘.
   v2를 누가 어떤 일에 써 볼지, 10월 2일에 다른 사장님께 무엇을 봐 달라고 할지도 정리해 줘.
   아직 재지 않은 시간 절감이나 매출 증가는 '기대 효과'로만 적어 줘.

고친 계획은 v2/PRD.md에 반영해 줘. 내가 확인한 다음에 만들기를 시작할게.
모르는 것은 추측하지 말고 물어봐 줘.
```

**그다음:** 계획 확인 → `v2/프로젝트/`에서 만들기 → 직접 써 보기 → Vercel 주소 확인 → 아래 2번으로 과정 정리.

## 2. 만든 과정 정리하기

10/1(목) 밤 11시 59분까지. 다른 사장님이 "어떻게 만들었는지" 보고 따라 할 수 있게 정리합니다.

```text
10월 2일 중간 점검에서 내 v2 결과물과 만든 과정을 공유하려고 해.
v1/사용메모.md, v2/PRD.md, v2/제출서.md, v2/프로젝트 안의 파일과 커밋 기록을 읽고
내 폴더의 중간점검_1002.md 1~5번을 채워 줘.

- 2번 "만든 과정"은 다른 사장님이 따라 할 수 있게 순서대로 짧게 써 줘.
  내가 AI에게 한 말 중 결과를 크게 바꾼 것 두세 개는 원문 그대로 옮겨 줘.
- 된 것과 아직 안 된 것을 나눠 줘. 실제 가게에서 쓴 것과 예시로 시험한 것도 나눠 줘.
- 기록에 없는 숫자나 느낌은 지어내지 말고 빈칸으로 두고 나한테 물어봐 줘.
- 비밀번호, API 키, 실제 직원·손님 이름은 넣지 마.
다 채우면 내가 읽어 볼게. 확인하면 커밋하고 push해 줘.
```

**CLAUDE.md가 아직 없으면:**

```text
이 프로젝트에 CLAUDE.md를 만들어 줘. 이 도구가 무엇이고 누가 쓰는지,
파일 구조, 실행 방법, 지켜야 할 규칙(비밀은 .env에만, 실제 손님 정보 금지 등)을 짧게 적어 줘.
앞으로 규칙이 바뀌면 이 파일도 같이 고쳐 줘.
```
