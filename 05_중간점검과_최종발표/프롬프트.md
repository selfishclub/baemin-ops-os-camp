# 10/2 · 10/14 과제 — AI에게 붙여넣을 문장

`[ ]` 안만 내 내용으로 바꾸고, 말하는 파일을 함께 열어 둔 상태에서 붙여넣습니다.

---

## 1. v2 계획 고치기

`v1/사용메모.md`, `v1/PRD.md`, `v2/PRD.md`를 함께 줍니다. 받은 의견이나 회의록이 있으면 같이 붙여넣습니다.

```text
내가 만든 가게 운영 도구를 v2로 고치고 싶어. 아직 만들지는 말고 계획부터 고쳐 줘.

일정은 2026년 10월 2일 온라인 중간 점검 전까지 v2 완성이야.
10월 2일에 결과물과 만든 과정을 공유하고 서로 피드백을 받은 뒤,
실제 사용 경험과 함께 반영해서 10월 14일까지 최종 버전을 완성할 거야.
이 일정에 맞춰 v2에서 완성할 것과 점검 후 고칠 것을 나눠 줘.
시간 안에 어려운 부분이 있으면 숨기지 말고 범위 조정안을 '추천'으로 제안해 줘.

내 도구: [무엇을 만들었는지]
만든 이유: [누가 어떤 일에서 겪는 문제를 해결하고 싶은지]
내 가게에서 바라는 변화: [손님 응대, 주문·예약, 비용, 직원 일 등]
v1 계획과 지금 되는 기능: v1/PRD.md, v1/제출서.md
v1을 써 본 기록과 받은 의견: v1/사용메모.md, [다른 의견이 있으면 붙여넣기]
v2 계획 초안: v2/PRD.md

1. 써 본 기록·의견 중 무엇을 v2 계획에 넣었는지 알려 줘. 안 넣은 것은 이유도.
2. 내가 놓친 것이 있으면 '추천'이라고 따로 써 줘. 내가 고른 것만 계획에 넣어 줘.
3. 데이터 저장이 필요한 도구라면 Supabase에 어떤 표와 항목이 필요하고, 왜 그렇게 나누는지 쉽게 설명해 줘.
   저장이 필요 없는 도구라면 그렇다고 말해 줘.
4. 저장한 정보로 가게 일 상태를 보는 대시보드가 필요한지, 필요하면 누가 보고 어떤 행동을 할지,
   어떤 숫자나 목록이 필요한지 계획해 줘.
5. 기능마다 어떤 가게 문제가 해결되는지, 잘되는지 확인할 방법을 적어 줘.
   v2를 누가 어떤 일에 써 볼지, 10월 2일에 다른 사장님께 무엇을 봐 달라고 할지도 정리해 줘.
   아직 재지 않은 시간 절감이나 매출 증가는 '기대 효과'로만 적어 줘.

고친 계획은 v2/PRD.md에 반영해 줘. 내가 확인한 다음에 만들기를 시작할게.
모르는 것은 추측하지 말고 물어봐 줘.
```

**그다음:** 계획 확인 → `v2/프로젝트/`에서 만들기 → 직접 써 보기 → Vercel 주소 확인 → 아래 2번으로 과정 정리.

## 2. 만든 과정 정리하기

10/2 전날까지. 다른 사장님이 "어떻게 만들었는지" 보고 따라 할 수 있게 정리합니다.

```text
10월 2일 중간 점검에서 내 v2 결과물과 만든 과정을 공유하려고 해.
v1/사용메모.md, v2/PRD.md, v2/제출서.md, v2/프로젝트 안의 파일과 커밋 기록을 읽고
내 폴더의 중간점검_1002.md 1~5번을 채워 줘.

- 2번 "만든 과정"은 다른 사장님이 따라 할 수 있게 순서대로 짧게 써 줘.
  내가 AI에게 한 말 중 결과를 크게 바꾼 것 두세 개는 원문 그대로 옮겨 줘.
- 된 것과 아직 안 된 것을 나눠 줘. 실제 가게에서 쓴 것과 예시로 시험한 것도 나눠 줘.
- 기록에 없는 숫자나 느낌은 지어내지 말고 빈칸으로 두고 나한테 물어봐 줘.
- 비밀번호, API 키, 실제 직원·손님 이름은 넣지 마.
다 채우면 내가 읽어 볼게. 확인하면 커밋하고 push해 줘.
```

**CLAUDE.md가 아직 없으면:**

```text
이 프로젝트에 CLAUDE.md를 만들어 줘. 이 도구가 무엇이고 누가 쓰는지,
파일 구조, 실행 방법, 지켜야 할 규칙(비밀은 .env에만, 실제 손님 정보 금지 등)을 짧게 적어 줘.
앞으로 규칙이 바뀌면 이 파일도 같이 고쳐 줘.
```

## 3. 발표자료.html 만들기

10/14까지. `피드백_반영_1014.md`, `중간점검_1002.md`, `사용메모.md`, `v2/결과물/`의 화면을 함께 줍니다.
아직 모르는 것은 '모름' 또는 '아직 안 잼'이라고 적어도 됩니다.

```text
내가 만든 가게 운영 도구를 10월 14일 최종 발표에서 소개할 HTML 발표자료를 만들어 줘.
10월 2일 중간 점검에서 받은 피드백을 반영한 최종 버전이 기준이야.
듣는 사람들은 서로 다른 가게 사장님이고, 개발 용어를 잘 몰라.
중학생도 이해할 수 있는 쉬운 말로 설명해 줘.

이번 발표의 중심은 실제 장사와 가게 운영에 어떤 도움이 됐는지야.
어떤 문제가 있었는지, 도구를 어떻게 썼는지, 일이 어떻게 달라졌는지 이어서 보여 줘.
기능을 많이 만들었다는 이유만으로 성공이라고 쓰지 마.

[내 자료]
- 내 가게와 도구 이름:
- 누가 언제 쓰는 도구인지:
- 해결하고 싶은 가게 문제와 만든 이유:
- 내 기록: 중간점검_1002.md, 피드백_반영_1014.md, v1/사용메모.md
- 직접 확인한 전후 숫자, 비교 기간과 횟수:
- 내가 느낀 점, 직원·손님에게 실제로 들은 말:
- 보여 줄 기능과 화면 파일: v2/결과물/
- 앞으로 더 만들고 싶은 기능과 이유:
- Vercel 주소와 개인 GitHub 저장소 주소:

[꼭 들어갈 내용]
1. 왜 만들었는지 — 만들기 전 가게 장면과 불편, 그게 손님 응대·주문·비용·직원 일 중 어디에 영향을 줬는지.
   모든 영역에 효과가 있는 것처럼 쓰지 말고 내 목적에 맞게 골라 줘.
2. 만들기 전과 후의 숫자 — 같은 일의 전후, 비교한 기간·횟수·버전(v2/최종).
   직접 잰 값, 예상한 값, 아직 안 잰 값을 구분해 줘. 시간을 돈으로 바꾼 값과 실제 줄어든 지출도 구분해 줘.
   매출·주문이 늘었어도 도구 하나 덕분이라고 단정하지 마. 숫자가 없으면 지어내지 말고 확인할 방법을 적어 줘.
3. 생각과 느낌의 변화 — '편해졌다' 대신 내가 겪은 구체적인 장면으로.
   아낀 시간을 어디에 썼는지 자료에 있으면 넣고, 안 해 본 것은 계획이라고 표시해 줘.
4. 자랑하고 싶은 기능과 10/2 피드백 반영 — 실제 화면과 쓰는 순서로.
   대시보드를 보여 준다면 누가 보고 무슨 행동을 하는지.
   10월 2일 피드백 중 무엇을 고쳤고 다시 써 보니 어땠는지. v1·v2·최종의 가장 큰 차이 한 줄씩.
   실제 가게에서 쓴 것과 예시로 시험한 것을 구분해 줘.
5. 앞으로 더 만들고 싶은 것 — 다음에 해결할 가게 문제, 먼저 만드는 이유, 잘됐는지 확인할 방법.
   예정인 기능은 이미 된 기능과 구분해 줘.

[작성과 파일]
- 내 기록에 없는 숫자, 손님 반응, 내 생각을 만들지 마. 핵심 자료가 빠졌으면 먼저 질문을 모아 줘.
- 한 화면에 글을 너무 많이 넣지 말고 글자를 크게 써 줘.
- 실제 손님 정보와 비밀번호·API 키는 넣지 마.
- 공동 저장소 내 폴더에 발표자료.html로 저장하고, 가능하면 파일 하나로 열리게 만들어 줘.
  이미지를 따로 쓰면 발표자료_이미지/ 폴더에 넣어 줘.
- 처음부터 끝까지 넘기며 글자가 잘리거나 이미지가 빠지지 않는지 확인해 줘.
```

**AI가 만든 뒤 내가 확인할 것:** 숫자와 경험이 내 것인지, 실제로 된 기능인지 읽어 봅니다. 과장되거나 사실과 다른 부분은 고친 뒤 커밋·push합니다.
