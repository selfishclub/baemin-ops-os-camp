## 1. 저장소 기본 설계

- **이름(안)**: `baemin-ops-os-camp` (조직 `selfishclub`, private)
- **용어 통일**: 문서 전체에서 "워크숍" 사용 안 함. **"실전 캠프"**로 통일. (Day 1 = 가게 홍보 편, Day 2 = 가게 운영 편)
- **작업 방식**: 브랜치·PR 없이 **main에 바로 저장**. 자기 폴더만 수정.
  - GitHub 실습(자기소개): GitHub **웹사이트**에서 새 파일 만들기 (설치 없음, 내용 미리 채운 링크)
  - 실습 제출: **AI에게 말로 시켜서** clone → 파일 넣기 → commit → push
- **코드는 개인 저장소에**, 공동 저장소에는 PRD·제출서·스크린샷·링크만.
- **금지**: `.env`, API 키, Supabase service_role 키, 로그인 세션 파일, 직원·손님 실명, 실제 매출 원본

## 4-1. 제출물 확정 — "PRD인가, 링크인가?" → 둘 다

| 어디에 | 무엇을 | 왜 |
|---|---|---|
| **개인 GitHub 저장소 (Public)** | 실제 코드·화면·설정 전체 | 각자 작업실. Vercel이 여기서 읽어 배포. 공개로 두어야 다른 사장님이 볼 수 있음 |
| **Vercel** | 인터넷에서 열리는 주소 | 누구나 폰으로 열어 확인 |
| **공동 저장소 `02_.../내폴더/v1/`** | ① `PRD.md` ② `제출서.md`(공개 개인 저장소 링크 + Vercel 링크 + 아티팩트 링크) ③ `결과물/` 스크린샷 | 교실 게시판. 링크만 있으면 누구나 코드와 화면으로 이동 가능 |

즉 공동 저장소에 제출하는 것은 **기획안(PRD) + 두 링크가 적힌 제출서 + 스크린샷**이고, 코드는 복사해 올리지 않습니다. v2도 같은 구성.

## 5. 각 문서 핵심 내용 (v1과 동일, 이름만 반영)

- **우리 가게 소개 양식**: 가게 이름 · 자랑 · 오늘 만들고 싶은 것 · 왜. 파일명 `가게이름_이름.md`. 미리 채워진 "새 파일 만들기" 링크. 영어 버튼 우리말 표.
- **GitHub 가이드**: 금고·노트 비유, 네 동작, 시작 Pull·끝 Push, 실습 두 단계, 금지 세 가지.
- **PRD 양식**: 무엇을 왜 / 누가 언제 / 지금은 어떻게 / 쓰면 뭐가 달라지나 / **v1 오늘 만들 것** / 완성 확인 / **v2 더할 것(API·외부 데이터)** / 안 만들 것.
- **제출서 양식**: 개인 GitHub 저장소 주소 · Vercel 주소 · 아티팩트 링크 · 한 줄 설명 · 스크린샷 · 되는 것 · 안 되는 것 · 소감.
- **인터넷 주소 만들기**: 개인 저장소 → Supabase(URL·anon 키만) → Vercel(GitHub 연동, 환경변수) → 주소 → 제출서. 단계마다 AI에게 말하는 문장. 체크리스트 6개.
- **프롬프트 가이드**: GitHub / PRD / 만들기 / 배포 / 막혔을 때 / 남의 PRD 참고하기 + 좋은 요청 3원칙 + S·T·I·C 틀.
- 모든 문서 중학생 눈높이. "워크숍" 없음.
