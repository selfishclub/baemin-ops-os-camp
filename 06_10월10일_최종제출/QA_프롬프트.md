# QA 프롬프트 — 실제로 써 보면서 품질 확인하기

**QA(Quality Assurance)는 내 도구를 실제로 써 보면서 어디서 헤매고 막히는지 확인하는 일입니다.**
실제 손님·직원에게 피드백을 받기 어려울 때, AI가 **가상의 사용자(페르소나)** 가 되어 실제 사이트를 폰 화면으로 직접 눌러 봅니다.

- 필요한 것: Claude 데스크톱 앱 + **Claude in Chrome**(크롬 확장). 크롬 창에서 AI가 사이트를 열고 누릅니다
- **빈칸을 채우지 않아도 됩니다.** AI가 이 대화와 내 폴더 기록에서 주소·쓰는 사람·목표·누르면 안 되는 버튼을 먼저 찾아서 확인받습니다
- 가상 QA는 진짜 사용자 피드백을 **대신하지 않습니다.** 진짜 사용자에게 묻기 전에 미리 걸러 보는 단계입니다. 그래서 마지막에 실제 직원·손님에게 물어볼 질문을 뽑습니다
- 결과는 `사용메모.md`에 붙이고, 고친 것은 `최종제출_1010.md` 4번 "QA" 줄에 적습니다

> Claude in Chrome이 없으면 같은 프롬프트로 "화면 순서만 보고 하는 QA"가 됩니다. 정확도는 떨어지지만 막힐 곳을 미리 짚어 볼 수 있습니다.

## 1. 모든 사장님 공통 — 내 도구 QA

```text
Claude in Chrome으로 내가 만든 가게 도구를 "실제로 쓸 사람의 눈으로" 직접 써 보고 QA(실제로 써 보면서 품질 확인)를 해 줘.

[먼저 스스로 찾기 — 나에게 묻기 전에]
이 대화에서 내가 한 말과, 지금 열려 있는 프로젝트 폴더를 먼저 읽어 줘.
공동 저장소(baemin-ops-os-camp)가 이 컴퓨터에 있으면 02_실전캠프_Day2_실습제출 안에서 내 가게 이름이 들어간 폴더도 찾아 읽어 줘.
(PRD_전체.md, v2/PRD.md, v2/제출서.md, 사용메모.md, 중간점검_1002.md, 최종제출_1010.md, CLAUDE.md, 결과물 화면, 커밋 기록)
그리고 아래 표를 스스로 채워서 보여 줘. 칸마다 "어디서 찾았는지"를 옆에 적어 줘.
- 테스트할 주소 — 데모 주소가 있으면 데모 주소를 먼저 (실제 데이터가 있는 주소는 피하기)
- 이 도구가 하는 일 한 줄
- 실제로 쓰는 사람과 장면 (누가, 언제, 어디서)
- 쓰는 기기 (휴대폰 / 아이패드 / PC)
- 그 사람이 끝까지 해야 하는 일(목표)
- 누르면 실제 기록이 남거나 알림·메시지가 나가는 버튼, 삭제 버튼, 로그인·PIN 화면
- 중간점검_1002.md 5번 "다른 사장님이 써 볼 때 봐 줬으면 하는 것"
끝내 못 찾은 것만 한 번에 물어봐 줘. 내가 "맞아"라고 하면 다음으로 넘어가 줘.

[안전 규칙]
- 누르면 실제 기록이 남거나 알림·메시지가 나가는 버튼, 삭제·제출·결제 버튼은 누르기 직전에서 멈추고 "여기서 멈췄습니다"라고 보고해 줘
- 비밀번호·PIN 입력이 필요하면 멈추고 나에게 직접 입력해 달라고 해 줘. 네가 입력하지 마
- 실제 직원·손님 이름은 고르지 마. 시험용 이름이 있으면 그걸 써

[화면 준비]
- 쓰는 기기가 휴대폰이면 크롬 창을 가로 390 × 세로 844로, 아이패드면 820 × 1180으로 줄여 줘. 줄일 수 없으면 먼저 말해 줘
- 화면이 바뀔 때마다 스크린샷을 찍고, 엄지로 누르는 느낌으로 판단해 줘 (버튼이 작거나 붙어 있으면 기록)

[페르소나 3명 — 위에서 찾은 내용을 보고 네가 골라 줘]
① 핵심 사용자 — 이 도구를 매일 쓸 사람 (정상 흐름이 되는지)
② 디지털에 서툰 사람 — 나이 많은 직원, 처음 온 알바 등 (작은 글씨·아이콘·어려운 말에서 막히는지)
③ 바쁘거나 의심 많은 사람 — "원래 하던 대로 하면 되는데 굳이?" 하는 사람 (안 쓰는 이유가 나오는지)
고른 3명의 이름·나이·하는 일·성격·목표를 먼저 보여 주고, 내가 "좋아"라고 하면 시작해 줘.
한 번에 한 명씩, 이름표를 붙여서 진행해 줘. 서로의 반응을 섞지 마.

[각 화면에서 페르소나가 스스로 답할 것]
- 지금 뭘 하라는 화면이에요?
- 다음에 뭘 눌러야 해요?
- 하고 싶어요? (할 수 있는데 하고 싶지 않으면 그게 가장 중요한 발견)
반응은 넷 중 하나: 통과 / 머뭇 / 막힘 / 이탈
- 이탈하면 그 사람은 거기서 끝. 뒤 단계를 상상해서 채우지 마
- 통과한 곳도 "왜 쉬웠는지" 한 줄 (고칠 때 건드리면 안 되는 부분)
- 페르소나는 버그를 찾으러 다니지 않아. 자기 목표만 보고 움직여
- 고치는 방법은 페르소나가 말하지 않아. 증상은 페르소나가, 고칠 방향은 리포트가

[막힌 이유 분류]
B1 못 찾음 · B2 못 알아봄(말이 어려움) · B3 못 믿음(불안함) · B4 눌러도 안 됨 · B5 할 수 있는데 굳이 안 함 · B6 오류·로딩 실패
심각도: S1 여기서 그만둠 / S2 헤맸지만 해냄 / S3 했는데 찜찜함

[결과 — 이 순서로]
1. 단계별 통과 현황 표 (페르소나 × 단계)
2. 막힘 상세 표 — 유형 · 심각도 · 어느 화면 · 누가 · 그 사람이 한 말 · 고칠 방향 (B5가 있으면 맨 위)
3. 10/10(금)까지 먼저 고칠 것 3개 (S1부터)
4. 잘 된 것 3개 (고칠 때 건드리지 말 것)
5. 확인하지 못한 것 (누르지 않은 버튼, 실제 데이터로만 볼 수 있는 화면 등)
6. 실제 직원이나 손님 한 명에게 직접 물어볼 질문 2개
7. 마지막 줄에 그대로: "가상 사용자 대상 정성 점검입니다. 비율로 해석하지 않으며, 실제 직원·손님의 반응을 대체하지 않습니다."

결과를 사용메모.md에 오늘 날짜와 함께 붙여 줘.
내가 고칠 것을 고르면 고친 뒤 같은 페르소나로 한 번 더 확인하고, 최종제출_1010.md 4번 "QA" 줄에 적어 줘.
```

## 2. 가영이네용 — 외국인 손님 모바일 QA

외국인 손님이 자기 폰으로 여는 메뉴 안내 사이트라, 손님 페르소나를 미리 정해 두었습니다. 사이트의 실제 버튼 이름(`Find a menu`, `Spice level`, `Guest favorites`, `Ingredient details`, `Show to staff`)을 넣었습니다.

```text
Claude in Chrome으로 우리 가게 외국인 메뉴 안내 사이트를 "외국인 손님 눈으로" 직접 써 보고 QA(실제로 써 보면서 품질 확인)를 해 줘.

[먼저 스스로 찾기 — 나에게 묻기 전에]

(v2/제출서.md, v2/PRD.md, 중간점검_1002.md, 사용메모.md, 프로젝트/REVIEW.md, 커밋 기록)
그리고 아래를 표로 보여 줘. 칸마다 어디서 찾았는지 적어 줘.

[사이트 정보]

[각 화면에서 페르소나가 스스로 답할 것]

- 통과한 곳도 "왜 쉬웠는지" 한 줄

[막힌 이유 분류]
B1 못 찾음 · B2 못 알아봄(말이 어려움) · B3 못 믿음(불안함) · B4 눌러도 안 됨 · B5 할 수 있는데 굳이 안 함 · B6 오류·로딩 실패
```

## 3. 가게별 — 누르면 안 되는 것

실제로 써 보다가 진짜 기록이 남거나 알림이 나가는 도구가 있습니다. AI가 스스로 찾지만, 아래 표와 다르면 고쳐 주세요.

| 가게 | 주로 볼 기기 | 조심할 것 |
|---|---|---|
| 해모닉 | 아이패드 · 폰 | 할 일을 체크하면 **사장님 텔레그램으로 진짜 알림이 감** → 체크 직전에서 멈추게 |
| 떡기리 | 폰 | 체크를 누르는 즉시 **서버에 저장**돼 사장 점검표에 남음 → 시험용 이름을 따로 만들거나 체크 직전에서 멈추게 |
| 본노엘 | 매장폰 | 이름 고르기·"확인했어요"가 **실제 직원 명단과 기록** → 퀴즈 풀기까지만, 또는 데모 사이트로 |
| 부찌대학 | 매장폰 | 시연 아티팩트는 브라우저에만 저장돼 안전함. 실사용본으로는 하지 않기 |
| 숯불에닭 | 폰 · PC | 시연 모드라 안전함. 가짜 자료를 넣으면 다른 사람 화면도 바뀜 |
| 김씨육면 | PC | 브라우저에만 저장돼 안전함. "시연 자료 넣기"로 시작 |
| 빈숲카페 | 폰 | 둘러보기 모드라 안전함. "직원 눈 / 사장 눈" 두 번 돌리기 |
| 마선생얼큰국밥 | 폰 | 접속 비밀번호는 사장님이 직접 입력 |
| 가영이네 | 폰 | 보기 전용이라 안전함 → 2번 프롬프트 |
| 카페스이 · 바삭마차 | — | v2가 아직 없으면 v1 화면이나 기획안으로 "화면 순서만 보고 하는 QA"부터 |

## 4. 진짜 사용자에게 받기 — 5분 버전

가상 QA로 큰 막힘을 고친 다음, 직원·가족·손님 한 명에게 직접 써 보게 합니다.

1. 설명하지 않고 폰을 건넨 뒤 "○○ 해 보세요" 한 문장만 말합니다
2. 도와주지 않고, 멈추는 곳과 혼잣말을 그대로 적습니다
3. 끝나면 두 가지만 묻습니다: "어디가 제일 헷갈렸어요?" "내일도 쓸 것 같아요? 왜요?"
4. AI에게 적은 메모를 주고 "위 QA 결과와 합쳐서 고칠 것 3개로 정리해 줘"라고 합니다
