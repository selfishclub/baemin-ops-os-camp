# 10/10 최종 제출 — AI에게 붙여넣을 문장

**빈칸을 채우지 않아도 됩니다.** 내 프로젝트 폴더(또는 공동 저장소)를 연 상태에서 그대로 붙여넣으면, AI가 이 대화와 내 기록에서 필요한 것을 먼저 찾아 표로 보여 주고 끝내 못 찾은 것만 묻습니다.
AI가 찾아 온 표가 맞는지 한 번 읽고 "맞아" 또는 고칠 것을 말해 주세요.

> QA(실제로 써 보면서 품질 확인하기) 프롬프트는 따로 있습니다 → [QA_프롬프트.md](QA_프롬프트.md)

```text
끝내 못 찾은 것만 한 번에 모아서 물어봐 줘. 기록에 없는 숫자·손님 반응·내 생각은 지어내지 마.
```

```text
[먼저 스스로 찾기 — 나에게 묻기 전에]
이 대화에서 내가 한 말과, 지금 열려 있는 프로젝트 폴더를 먼저 읽어 줘.

피드백은 공동 저장소 baemin-ops-os-camp의 06_10월10일_최종제출/젬마쌤_피드백_1002.md에 있어. "1. 모두에게"와 "2. 가게별 원포인트"에서 내 가게 부분을 읽어 줘. 내 가게 부분이 없으면 "모두에게"를 기준으로 해 줘.
이 대화나 내 폴더(중간점검_1002.md 6번, 사용메모.md 등)에 따로 받은 피드백이 있으면 그것도 합쳐 줘.

   우리 가게에서 실제로 쓰는 사람(나·직원·손님)에게 도움이 되는 순서로 골라 줘.

4. 다 고치면 폰 화면 크기로 열어서 확인하고, 개인 저장소에 커밋·push 해 줘.
```

### 1-2. 다른 사장님 저장소에서 배우기

```text

[할 일]
공동 저장소 baemin-ops-os-camp를 pull 받고, 02_실전캠프_Day2_실습제출 아래 다른 사장님 폴더를 읽어 줘.
(제출서.md, 중간점검_1002.md, PRD, v2/프로젝트 안의 코드와 문서)

1. 내 도구와 비슷한 문제를 푼 곳, 내가 가져다 쓸 수 있는 기능·화면·방법·AI에게 한 말을 찾아서 표로 정리해 줘.
   "누구 것(가게 이름) · 무엇 · 내 도구에 어떻게 쓰면 되나 · 10/10까지 할 수 있나"
2. 그대로 베끼는 것보다 우리 가게 상황에 맞게 바꾸는 방법을 제안해 줘.
3. 내가 고른 것만 내 개인 저장소에서 만들어 줘. 다른 사장님 폴더는 읽기만 하고 절대 고치지 마.
4. 최종제출_1010.md 4번 표의 "다른 사장님 저장소" 줄에 어느 가게에서 무엇을 배웠는지 출처와 함께 적어 줘.
```

### 1-3. 내 AI 대화로 나를 파악하고, 바깥 지식으로 넓히기

```text
[먼저 스스로 찾기 — 나에게 묻기 전에]
이 대화와 지금 열린 프로젝트 폴더의 기록(PRD·제출서·사용메모·중간점검·CLAUDE.md·커밋 메시지)을 읽어 줘.
그동안 이 프로젝트에서 나눈 이전 대화 기록을 찾을 수 있으면 그것도 읽어 줘.
(Claude Code라면 이 프로젝트의 지난 세션 기록, Claude 앱이라면 과거 대화 검색)

[1단계 — 나를 파악하기]
다음을 표로 정리해 줘. 각 줄에 근거가 된 내 말이나 기록을 짧게 붙여 줘.
- 내가 여러 번 말한 불편과 바람
- 내가 무언가를 정할 때 쓰는 기준 (예: 직원이 바로 쓸 수 있나, 돈이 드나, 손님 앞에서 빨라지나)
- 내가 미뤄 둔 것과 그 이유
- 말은 했는데 아직 도구에 안 들어간 것

[2단계 — 바깥 지식으로 넓히기]
같은 업종의 가게, 비슷한 도구(근태·급여, 매뉴얼·교육, 손익·정산, 메뉴 안내, 리뷰 관리 등),
사람들이 새 도구를 쓰다가 그만두는 흔한 이유, 소상공인 운영에 대해 알려진 패턴을 바탕으로
내가 혼자서는 떠올리기 어려운 개선 아이디어 5개를 줘.
각 아이디어마다:
- 근거 — 일반적으로 알려진 패턴인지, 내 기록에서 나온 것인지 구분 (웹 검색을 쓸 수 있으면 출처 링크)
- 우리 가게에 맞는 이유 — 1단계의 내 기준과 연결해서
- 10/10까지 해 볼 수 있는 작은 실험 하나
- 잘됐는지 볼 숫자나 장면 하나
확실하지 않은 것은 '추측'이라고 표시해 줘.

[3단계]
내가 고른 것만 계획으로 정리하고, 내가 확인하면 만들기 시작해 줘.
최종제출_1010.md 4번 표의 "AI 대화 기반 인사이트" 줄에 고른 아이디어와 결과를 적어 줘.
이전 대화 기록 원문은 GitHub에 올리지 마.
```

## 2. 써 보니 어땠나 — 전과 후

```text
[먼저 스스로 찾기 — 나에게 묻기 전에]
이 대화와 내 폴더 기록(사용메모.md, 중간점검_1002.md 3번, 제출서의 소감, 커밋 기록)에서
"도구 전에는 어떻게 했고, 지금은 어떻게 하는지"에 대한 내 말과 숫자를 모두 찾아 표로 보여 줘.

[할 일]
내 도구를 쓰기 전과 후를 같은 일 기준으로 비교하고 싶어.
1. 비교할 일을 1~3개 골라 줘. (예: 주급 계산·보내기, 마감 체크 확인, 월 정산, 외국인 손님 메뉴 설명)
2. 일마다 "전 · 후 · 어떻게 알았나 · 기간과 횟수" 표를 만들어 줘.
   어떻게 알았나는 넷 중 하나로: 직접 잼 / 느낌 / 예상 / 아직 안 잼
3. 아직 안 잰 것은 10/10(금)까지 며칠 동안 어떻게 재면 되는지 아주 간단한 방법을 알려 줘.
   (예: 내일부터 3일간 마감 때 시작·끝 시각을 사용메모.md에 한 줄씩)
4. 시간을 돈으로 바꾼 값과 실제로 줄어든 지출은 따로 적어 줘.
5. 줄어든 시간에 무엇을 했는지 기록이 있으면 넣고, 없으면 나에게 물어봐 줘.
6. 직원·손님 반응은 내가 말했거나 기록에 있는 것만 넣어 줘.
7. 매출·주문이 늘었어도 도구 하나 덕분이라고 단정하지 마. 같은 기간의 행사·날씨·광고 같은 다른 변화도 함께 적어 줘.
결과는 최종제출_1010.md 5번에 넣어 줘.
```

## 3. 데모 사이트 새로 배포하기

10/14 공유회에서 다른 사장님이 패드로 직접 눌러 봅니다. **비어 있는 데모는 아무것도 보여 주지 못합니다.** 그래서 이 프롬프트는 AI가 우리 가게에 맞는 **생생한 가상 데이터를 스스로 설계해서 채우고**, 화면이 비지 않는지까지 확인하게 되어 있습니다. 데이터 설정은 묻지 않고 AI가 정한 뒤 표로 보여 줍니다.

```text
[먼저 스스로 찾기 — 나에게 묻기 전에]
이 대화와 프로젝트 폴더(PRD, 제출서, 사용메모, 중간점검, 최종제출_1010.md, 코드, 기존 시연 모드·예시 버튼)를 읽고 다음을 표로 보여 줘.
- 지금 쓰는 배포 주소와 Vercel 프로젝트 이름, 도구가 여러 개인지 (각각 주소)
- 실제 데이터가 들어 있는 곳 (Supabase, 브라우저 저장, 파일, 아티팩트)
- 로그인·비밀번호·PIN이 필요한 화면
- 우리 가게 모습: 업종, 매장 수, 영업 요일·시간, 직원 규모와 역할, 메뉴·상품, 쓰는 배달앱·결제 수단, 바쁜 요일·시간대
- 도구의 화면(탭·메뉴) 목록과 각 화면이 보여 주는 숫자·목록

[할 일 1 — 데모 사이트 만들기]
다른 사장님과 배민아카데미가 로그인 없이, 내 실제 데이터 없이 바로 눌러 볼 수 있는 데모 사이트를 새 주소로 따로 만들어 줘.
- 지금 실제로 쓰는 주소와 데이터는 건드리지 마.
- 저장이 필요한 도구라면 데모판은 브라우저에만 저장하거나 데모 전용 저장소를 써서, 누가 눌러도 실제 기록에 남지 않게 해 줘.
- 비밀번호·PIN이 필요하면 데모용 값을 정해서 화면에 적어 줘.
- 첫 화면에 "데모입니다 · 가상 데이터" 표시와 "여기부터 눌러 보세요" 안내를 넣어 줘.

[할 일 2 — 생생한 가상 데이터 채우기. 나에게 묻지 말고 네가 정해서 진행해]
위에서 찾은 우리 가게 모습을 바탕으로, 실제로 몇 주 써 온 가게처럼 보이는 가상 데이터를 설계하고 채워 줘.
1. 규모와 기간 — 우리 가게와 비슷한 규모로. 기록은 오늘 날짜 기준 지난 4~8주가 쌓여 있고 오늘 것도 일부 들어 있게.
   날짜는 고정하지 말고 "오늘 기준"으로 계산해서, 언제 열어도 최근 기록처럼 보이게 해 줘.
2. 리듬 — 요일·시간대별 차이(주말·점심·저녁 피크), 공휴일·날씨에 따른 변화가 숫자에 드러나게. 매일 같은 숫자 금지.
3. 사람과 이름 — 직원·손님은 자연스러운 가상 이름(예: 김하늘, 박도윤)과 역할·근무 패턴(오전·마감·주말 알바 등)을 줘.
   실제 직원·손님 이름과 겹치지 않는지 확인해 줘.
4. 현실적인 범위 — 업종에 맞는 숫자로. (예: 음식점 원가율 30~40%, 배달앱 수수료, 시급은 올해 최저임금 이상, 메뉴 가격대)
   실제 매출·시급·금액을 복사하지 말고 비슷한 크기의 새 숫자로 만들어 줘.
5. 일부러 넣는 "일" — 도구가 쓸모 있어 보이는 장면이 나오게. 예: 지각·결근·대타, 빠진 마감 체크, 미입금·수수료 차이, 원가율이 튄 날,
   품절·재고 부족, 불만 리뷰, 안 읽은 매뉴얼, 외국인 손님의 알레르기 질문. 도구가 그걸 잡아내거나 보여 주는 화면이 있어야 해.
6. 앞뒤가 맞게 — 화면끼리 숫자가 맞아야 해. (근무 기록 합계 = 급여, 일별 매출 합 = 월 매출, 체크 기록 = 점검표)
7. 시연 장면 3개 — 다른 사장님이 3분 안에 "아, 이래서 쓰는구나" 하게 되는 장면을 3개 정하고, 그 장면에 필요한 데이터를 꼭 넣어 줘.
8. 되돌리기 — 누가 눌러서 데이터가 바뀌어도 "데모 데이터 다시 채우기" 버튼 하나로 처음 상태로 돌아가게 해 줘.
9. 데이터 만드는 코드는 한 파일에 모아서, 나중에 숫자를 바꾸기 쉽게 해 줘.
다 정하면 "정한 설정" 표를 보여 줘: 가게 설정 · 기간 · 사람 수 · 숫자 범위 · 일부러 넣은 일 · 시연 장면 3개.

[할 일 3 — 배포하고 확인하기]
1. 새 Vercel 프로젝트로 배포하고 주소를 알려 줘. GitHub 저장소와 연결해서 push하면 자동으로 반영되게 해 줘.
   Vercel 가입·로그인처럼 내가 직접 해야 하는 단계는 순서대로 알려 주고 기다려 줘.
2. 폰 화면(가로 390)과 패드 화면(가로 820)으로 열어서 모든 화면을 한 번씩 눌러 봐 줘.
   비어 있는 화면, 0원·0건만 나오는 칸, "데이터 없음"이 뜨는 곳이 있으면 데이터를 더 채워서 고쳐 줘.
3. 실제 데이터가 섞이지 않았는지 마지막으로 검사해 줘. (실제 직원 이름, 실제 금액, 전화번호·이메일, 키·비밀번호)
4. 도구가 여러 개면 전부 데모 주소를 만들어 줘.
최종제출_1010.md 1번 표에 "무엇 · 데모 주소 · 써 보는 법(데모 PIN, 먼저 누를 곳)"을 적고, 3번 시연 소개 흐름에 시연 장면 3개를 넣어 줘.
```

## 4. 발표자료와 발표 흐름 만들기

```text
[먼저 스스로 찾기 — 나에게 묻기 전에]
이 대화와 내 폴더 기록(PRD_전체.md, v1·v2 제출서, 사용메모.md, 중간점검_1002.md, 최종제출_1010.md, 결과물 폴더의 화면)을 읽고
아래 발표 다섯 단계에 들어갈 재료를 "단계 · 찾은 내용 · 어디서" 표로 먼저 보여 줘. 비어 있는 칸은 나에게 물어봐 줘.

[발표 형식 — 배민아카데미 성과 발표 가이드, 1인 10분 내외]
흐름: 우리 가게 문제 → AI로 만들어 적용 → 변화
① 우리 가게 이야기 — 가게 소개 · AI 장사스쿨 참여 전 AI에 대한 생각
② 우리 가게의 문제 — "저희 가게는 ○○가 불편했어요 / ○○에 시간이 많이 들었어요"
③ AI로 이렇게 만들어 써 봤어요 + 시연 — 문제에 AI를 어떻게 접목했나, 무엇을 만들었고 어느 수준까지 됐나, 실제 시연(입력 → 결과가 나오는 장면까지)
④ 매장 적용 & 변화 — 한 문장 요약 "저는 ○○ 문제를 ○○로 풀었고, ○○가 달라졌어요", 직원과 실제로 써 봤는지·시행착오, 효율·편리함(시간·비용 숫자가 있으면 가장 좋음)
⑤ 마음의 변화 & 한마디 — 참여 전후 나의 변화(AI에 대한 자신감·태도), 가게·직원의 변화, 앞으로 더 해 보고 싶은 것

[만들어 줄 것]
1. 발표 대본 — 다섯 단계별로 내가 말할 문장과 시간 배분(합쳐서 10분 안).
   듣는 사람은 다른 가게 사장님과 배민아카데미야. 개발 용어 없이 중학생도 알아듣는 말로.
2. 발표자료 — 단계마다 1~3장, 한 장에 글은 적게, 글자는 크게.
   PPT 파일(.pptx)로 만들어 줘. 그게 어려운 환경이면 HTML 발표자료로 만들고 PDF로 저장하는 방법을 알려 줘.
   내 폴더 바로 아래 발표자료.pptx(또는 .pdf, .html)로 저장해 줘.
3. 시연 소개 흐름 — 데모 주소를 열고 카테고리(메뉴·탭)를 하나씩 짚어 가며 "어디를 누르고 · 무엇이 나오고 · 무슨 말을 할지" 순서표.
   최종제출_1010.md 3번에 넣어 줘.
4. 캡처·녹화 목록 — 어떤 화면을 찍거나 녹화할지, 각각 어디를 흐리게 가릴지(직원 이름, 전화번호, 손님 정보, 매출 숫자).
   데모 사이트(가짜 데이터)에서 찍을 수 있는 건 데모에서 찍자고 해 줘.
   실제 화면을 써야 하는데 이미지를 편집할 수 있으면 가릴 곳을 직접 흐리게 처리해 줘.

[지킬 것]
- 내 기록에 없는 숫자, 손님 반응, 내 생각을 만들지 마. 직접 잰 값 / 느낌 / 예상을 구분해 줘.
- 기능을 많이 만들었다는 것만으로 성공이라고 쓰지 마. 가게 일이 어떻게 달라졌는지가 중심이야.
- 아직 안 된 기능은 "앞으로 할 것"으로 따로 보여 줘.
- 비밀번호·API 키·실제 손님 정보는 넣지 마.
다 만들면 처음부터 끝까지 넘기며 글자가 잘리거나 이미지가 빠진 곳이 없는지 확인해 줘.
```

**AI가 만든 뒤 내가 확인할 것:** 숫자와 경험이 내 것인지, 실제로 된 기능인지 읽어 봅니다. 과장되거나 사실과 다른 부분을 고친 뒤 커밋·push 합니다.

## 5. GitHub에 무엇을 올릴지 고르기 — 실제 운영 중인 도구

직원 운영에 실제로 쓰고 있어서 **매출 추이·직원 개인정보가 들어 있는 도구**에 씁니다.
다른 사장님과 배민아카데미가 "실제로 이렇게 쓰고 있구나"를 생생하게 볼 수 있게 하면서, 민감한 정보는 지키는 것이 목표입니다.
**AI는 먼저 제안만 하고, 내가 승인한 것만 올립니다.**

```text
[먼저 스스로 찾기 — 나에게 묻기 전에]
이 대화와 지금 열린 프로젝트 폴더, 개인 저장소, 공동 저장소의 내 폴더를 읽고
내가 그동안 만든 것을 전부 목록으로 만들어 줘: 기능·화면, 운영 기록, 문서, 스크린샷, 데이터(표·파일), 설정.

[목표]
내 도구는 실제로 직원 운영에 쓰고 있어서 매출 추이와 직원 개인정보가 들어 있어.
다른 사장님과 배민아카데미가 "이 가게는 이렇게까지 쓰고 있구나"를 생생하게 볼 수 있게 GitHub에 올리고 싶어.
하지만 매출·직원 정보는 지켜야 해.

[1단계 — 제안만 하기. 아직 파일을 만들거나 커밋하지 마]
만든 것 하나하나를 셋으로 나눠서 표로 보여 줘.
- 그대로 공개해도 됨 — 코드, 화면 구조, 매뉴얼 틀, 만든 과정, AI에게 한 말
- 바꾸면 공개해도 됨 — 어떻게 바꿀지까지 적어 줘
  예: 직원 이름 → "직원 A", 매출 금액 → 지난달 대비 증감률(%)이나 지수, 실제 화면 → 가짜 데이터로 다시 찍기 또는 흐리게 가리기, 지점 주소 → 지역 이름만
- 공개하면 안 됨 — 직원 이름·전화번호·주민번호·계좌, 실제 매출 금액, 손님 정보, 비밀번호·API 키·관리자 PIN, .env, 실제 데이터 백업 파일
표 칸: 무엇 · 지금 어디 있나 · 분류 · 바꾸는 방법 · 공개하면 보여 줄 수 있는 것(왜 의미가 있나)

그리고 "실제 운영 이야기"를 생생하게 보여 줄 공개용 묶음을 제안해 줘.
- 운영사례.md — 누가(직원 몇 명, 매장 몇 곳 같은 숫자만), 언제, 어떻게 쓰는지, 전후 변화
- 가짜 데이터로 채운 데모 화면과 데모 주소
- 흐리게 처리한 실제 화면 캡처 몇 장
- 만든 과정 요약과 AI에게 한 말 원문 몇 개
어디에 올릴지도 나눠 줘: 공동 저장소 내 폴더 / 개인 저장소.

[2단계 — 내 승인을 기다리기]
"이 목록대로 올릴까요?"라고 묻고 멈춰 줘. 내가 빼거나 바꾸라고 한 것은 반영해서 표를 다시 보여 줘.

[3단계 — 승인한 것만 올리기]
1. 승인한 것만 공개용 파일로 만들어 줘. 실제 데이터 파일을 복사하지 말고 가짜 데이터를 새로 만들어.
2. 올리기 전 검사:
   - 직원 이름 목록(내 컴퓨터에서만 보고 저장소에는 넣지 마), 전화번호·이메일·계좌번호 모양, 큰 금액 숫자, 키·토큰·비밀번호 모양을 새 파일에서 찾아 줘
   - .env, 백업 파일, 실제 데이터 파일이 올라가지 않는지
   - 이미 예전 커밋 기록에 민감한 것이 들어가 있는지도 확인해 줘. 있으면 지우려고 하지 말고 나에게 먼저 알려 줘(키는 새로 발급해야 할 수 있어)
3. 올라갈 파일 목록과 바뀐 내용(git diff --cached 요약)을 보여 주고 "올릴까요?"라고 한 번 더 물어봐 줘.
4. 내가 "올려"라고 하면 커밋하고 push해 줘. 공동 저장소는 내 폴더 밖을 건드리지 마.
5. 올린 뒤 GitHub 웹 주소를 알려 주고, 최종제출_1010.md 6번에 공개한 것과 공개하지 않은 것을 한 줄씩 적어 줘.
```

## 6. 마지막 — 저장소 두 곳에 올리기

```text
[먼저 스스로 찾기 — 나에게 묻기 전에]
이 컴퓨터에서 내 개인 저장소 폴더와 공동 저장소(baemin-ops-os-camp)의 내 폴더를 찾아 경로를 보여 줘.

1. 개인 저장소에서 pull 하고, 바뀐 코드를 커밋·push 해 줘. 실제 주소와 데모 주소가 모두 새로워졌는지 열어서 확인해 줘.
2. 공동 저장소에서 pull 하고, 내 폴더의 최종제출_1010.md · 발표자료 파일 · v2/제출서.md · v2/결과물/최종_첫화면.png만 바뀌었는지 확인해 줘.
3. 올리기 전에 키·비밀번호·실제 직원·손님 정보·매출 파일이 없는지 검사하고, 바뀐 파일 목록을 보여 준 뒤 커밋·push 해 줘.
4. 다 올리면 GitHub 웹에서 두 곳이 보이는 주소를 알려 줘.
```
