## 1. 개선하기 — 네 가지 방향

하나만 해도 되고 여러 개를 해도 됩니다. 무엇을 해서 무엇을 고쳤는지는 `최종제출_1010.md` 4번에 적습니다.

| 방향 | 이렇게 합니다 |
|---|---|
| **1-1. 젬마쌤 직접 피드백** | **[젬마쌤_피드백_1002.md](젬마쌤_피드백_1002.md)** 에서 "모두에게"와 내 가게 원포인트를 읽고, 고칠 것과 안 고칠 것을 나눈 뒤 고칩니다 |
| **1-2. 다른 사장님 저장소에서 배우기** | 공동 저장소의 다른 사장님 폴더를 AI가 읽고, 내 도구에 가져올 만한 기능·방법을 찾습니다. 남의 폴더는 읽기만 합니다 |
| **1-3. 내 AI 대화로 나를 파악 + 바깥 지식으로 넓히기** | 그동안 AI와 나눈 대화와 기록에서 내가 반복해서 말한 것과 판단 기준을 찾고, 비슷한 가게·도구에서 알려진 패턴으로 내가 떠올리기 어려운 개선점을 받습니다 |
| **1-4. 써 보게 하고 피드백 받기** | 가상의 페르소나가 실제 사이트를 폰 화면으로 눌러 보는 QA, 또는 직원·손님 한 명에게 직접 써 보게 하기 → [QA 프롬프트](QA_프롬프트.md) |

## 2. 써 보니 어땠나 — 전과 후

같은 일을 도구 전과 후에 비교합니다. **직접 잰 값 / 느낌 / 예상 / 아직 안 잰 값**을 나눠 적습니다. 숫자가 없으면 10/10까지 며칠만이라도 재 봅니다.

> 설명용 가상 예시: "주급 계산과 명세서 보내기가 예전엔 30분, 지금은 10분입니다. 지난주 한 번 시계로 쟀습니다. 줄어든 시간에 마감 정리를 일찍 끝냅니다."

## 3. 데모 사이트 새로 배포

다른 사장님과 배민아카데미가 **로그인이나 내 실제 데이터 없이 바로 눌러 볼 수 있는 주소**를 따로 만듭니다.

- 실제로 쓰는 주소는 그대로 두고, **가짜 데이터로 채운 데모판을 새 Vercel 주소로** 배포합니다
- **비어 있는 데모는 보여 줄 게 없습니다.** 프롬프트를 쓰면 AI가 우리 가게에 맞는 생생한 가상 데이터(몇 주치 기록, 요일별 차이, 지각·미입금 같은 일, 시연 장면 3개)를 스스로 만들어 채웁니다
- 도구가 여러 개면 모두 링크를 냅니다
- 비밀번호·PIN이 필요하면 데모용 값을 정해 함께 적습니다

## 4. 발표자료와 발표 흐름 — 1인 10분 내외

**우리 가게 문제 → AI로 만들어 적용 → 변화**

| 순서 | 내용 | 담을 것 |
|---|---|---|
| ① | **우리 가게 이야기** | 가게 소개 · AI 장사스쿨 참여 전 AI에 대한 생각 |
| ② | **우리 가게의 문제** | "저희 가게는 ○○가 불편했어요 / ○○에 시간이 많이 들었어요" |
| ③ | **AI로 이렇게 만들어 써 봤어요 + 시연** | 문제에 AI를 어떻게 접목했나 · 무엇을 만들었고 어느 수준까지 됐나 · **실제 시연**(입력 → 결과가 나오는 장면까지) |
| ④ | **매장 적용 & 변화** | 한 문장 요약 "저는 ○○ 문제를 ○○로 풀었고, ○○가 달라졌어요" · 직원과 함께 실제로 써 봤는지, 시행착오 · 효율·편리함이 얼마나 생겼나(시간·비용 숫자가 있으면 가장 좋음) |
| ⑤ | **마음의 변화 & 한마디** | 참여 전후 나의 변화(AI에 대한 자신감·태도) · 우리 가게·직원의 변화 · 앞으로 더 해 보고 싶은 것 |

**화면 캡처·녹화**를 넣습니다. **직원 이름·전화번호·손님 정보·매출 숫자는 흐리게(블러) 가립니다.** 데모 사이트에서 찍으면 가릴 것이 줄어듭니다.
