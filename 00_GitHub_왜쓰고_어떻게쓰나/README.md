# GitHub, 왜 쓰고 어떻게 쓰나

> 발표 자료: [GitHub, 왜 쓰고 어떻게 쓰나 (슬라이드)](../04_실전캠프_Day2_수업자료/발표자료/01_GitHub_왜쓰고_어떻게쓰나.html)
> 이 문서는 그 발표를 글로 정리한 것입니다. 나중에 혼자 볼 때 읽으세요.

## 이런 일, 있으셨죠?

- "어제 AI로 만든 거 어디 갔지?" — 파일이 바탕화면, 다운로드, 카톡에 흩어져 있다.
- "가게 컴퓨터에는 있는데 집에는 없네." — 이어서 만들 수가 없다.
- "이게 최신 버전 맞나?" — `최종`, `최종2`, `진짜최종` 파일이 쌓인다.

GitHub은 이 세 가지를 한 번에 없애려고 있는 서비스입니다.

## 한 줄로 말하면

**GitHub = 내 프로젝트를 보관하는 온라인 금고 + 고친 기록이 남는 노트**

가게 레시피 노트를 금고에 넣어 두면, 가게에서도 집에서도 같은 노트를 꺼내 이어 쓸 수 있습니다.
게다가 이 금고는 "언제, 무엇을, 왜 고쳤는지"를 자동으로 적어 둡니다.

## GitHub이 있는 이유 네 가지

| 이유 | 뜻 |
|---|---|
| **안 잃어버린다** | 컴퓨터가 고장 나도 금고에 그대로 있다 |
| **어디서든 이어한다** | 가게에서 만들고, 집에서 받아서 이어 만든다 |
| **되돌릴 수 있다** | 고친 기록이 남아서 어제 버전으로 돌아갈 수 있다 |
| **같이 본다** | 다른 사장님 기획안을 보고 내 것에 참고한다. AI에게 "저 폴더 읽고 알려 줘"도 된다 |

## 이번 캠프에서 GitHub의 역할

| 저장소 | 비유 | 무엇을 넣나 |
|---|---|---|
| **이 공동 저장소** | 교실 겸 공동 작업실 | 자기소개, 기획안(PRD), **만든 앱(코드)**, 제출서, 스크린샷 — 오늘은 전부 여기. 12명이 서로 앱을 열어 보고 끌어다 쓴다 |
| **내 개인 저장소** (완성 후, 10/17 이후에 만듦) | 내 창고 | 완성한 앱을 옮겨 두는 곳. Vercel이 여기서 읽어 인터넷 주소를 만든다 |

```

```

## 기억할 말 네 개

| 말 | 쉬운 뜻 | 언제 |
|---|---|---|
| **Clone** (클론) | 금고에서 프로젝트를 **처음 한 번** 복사해 오기 | 새 컴퓨터에서 처음 |
| **Pull** (풀) | 금고의 **최신 내용 받아오기** | 작업 시작할 때 |
| **Commit** (커밋) | 고친 내용에 **메모 붙여 저장**하기 | 작업 끝낼 때 |
| **Push** (푸시) | 저장한 걸 **금고에 올리기** | Commit 바로 다음 |

**시작할 때 Pull, 끝낼 때 Commit + Push.** 이 한 줄만 기억하면 됩니다.

내 컴퓨터에 저장만 하면 금고에는 안 들어갑니다. **Push까지 해야 올라갑니다.**

## 직접 안 쳐도 됩니다 — AI에게 말로 시키기

명령어를 외울 필요가 없습니다. Claude에게 이렇게 말하면 됩니다.

처음 가져올 때:
> 이 GitHub 저장소를 내 컴퓨터에 처음 가져와 줘. 주소는 https://github.com/selfishclub/baemin-ops-os-camp 야.

작업 시작할 때:
> 이 프로젝트에 아직 저장 안 한 수정이 있는지 먼저 확인해 줘. 없으면 GitHub의 최신 내용을 pull해 줘.

작업 끝낼 때:
> 오늘 바꾼 내용을 확인하고, 비밀번호나 API 키가 들어가지 않았는지 본 다음, 커밋하고 GitHub에 push해 줘.

## 하지 말 것 세 가지

1. 다른 사장님 폴더 수정하기 (끌어다 쓸 때는 내 폴더로 복사)
2. 비밀번호, API 키, 로그인 파일, 직원·손님 실명 올리기
4. 내 폴더 안에서 `git init` 하기 — 이미 저장소 안이라 꼬입니다
3. "강제로 올려 줘(force push)" — 남의 작업을 지울 수 있습니다. 막히면 운영진 호출.
