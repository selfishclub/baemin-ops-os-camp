# 1단계 · 내 GitHub 저장소 만들기

내 컴퓨터의 프로젝트 폴더를 **내 GitHub 계정의 새 저장소**에 올립니다. 5분.
공동 저장소 안에서 만들기 시작했다면 [0단계](0_공동저장소에서_옮기기.md)로 먼저 밖으로 옮깁니다.

## AI에게 이렇게 말합니다

프로젝트 폴더를 Claude에서 연 상태에서:

> 이 프로젝트를 내 GitHub 계정에 새 저장소로 올려 줘.
> 저장소 이름은 `[내도구이름]`, **Public**으로 만들어 줘.
> 올리기 전에 `.gitignore`에 `.env*`, `node_modules`, `.vercel`이 있는지 확인하고, 비밀번호나 키가 들어간 파일이 없는지 봐 줘.

AI가 GitHub 로그인이 필요하다고 하면 브라우저가 열립니다. 거기서 로그인하고 "허용"을 누릅니다.

끝나면 AI가 저장소 주소를 알려 줍니다. 예: `https://github.com/내아이디/staff-schedule`
**이 주소를 제출서에 적습니다.**

## 직접 확인하기

1. 브라우저에서 그 주소를 엽니다.
2. 파일들이 보이고, 이름 옆에 **Public**이라고 써 있으면 성공입니다.
3. `.env` 같은 파일이 보이면 **바로 멈추고** AI에게 "방금 올린 .env 파일을 기록에서 지우고 .gitignore에 넣어 줘"라고 말한 뒤 운영진에게 알립니다. 그 키는 새로 발급합니다.

## 저장소 이름은 어떻게 짓나

- 영어 소문자, 단어 사이는 `-`. 예: `staff-schedule`, `monthly-settlement`, `recipe-book`
- 한글은 피합니다. 인터넷 주소에 들어가면 깨져 보입니다.

## Private으로 만들어졌으면

저장소 페이지 → **Settings** → 맨 아래 **Danger Zone** → **Change visibility** → **Public**.
또는 AI에게 "이 저장소를 Public으로 바꿔 줘"라고 말합니다.

## 왜 Public인가

- 다른 사장님이 내 코드를 보고 배울 수 있습니다. 나도 남의 것을 봅니다.
- Vercel 무료 플랜과 궁합이 좋습니다.
- 비밀은 어차피 환경변수에만 있으므로 코드가 공개돼도 안전합니다. (그래서 위 확인이 중요합니다)
