# 인터넷에서 접근 가능하게 만들기 — 오늘 합니다

> 발표 자료: [슬라이드 03](../04_실전캠프_Day2_수업자료/발표자료/03_v1만들기_개인저장소와_Vercel.html)

내 컴퓨터에서만 열리는 화면은 나만 봅니다. **인터넷 주소**가 생기면 다른 사장님도, 직원도, 강사도 폰으로 엽니다.
이걸 "배포"라고 부릅니다. 여기서는 "인터넷에서 접근 가능하게 만들기"라고 하겠습니다.

## 왜 코드를 내 개인 저장소에 두나요?

- **내 것이라서.** 캠프가 끝나도 계속 내가 씁니다.
- **Vercel은 저장소 하나 = 사이트 하나.** 내 저장소를 연결해 두면 push만 해도 자동으로 새 버전이 올라갑니다.
- **공개(Public)로 두면 서로 힌트가 됩니다.** 다른 사장님이 내 코드를 보고 "저런 것도 되는구나" 하고, 나도 남의 것을 봅니다.
- 12명 코드가 공동 저장소 한곳에 섞이면 서로 건드려서 깨집니다. 공동 저장소에는 **요약과 링크**만 올립니다.

## 저장소 두 개, 폴더는 나란히

공동 저장소는 이미 내 컴퓨터에 받아 두었습니다. 개인 저장소는 **그 폴더 안이 아니라 옆에** 둡니다. 한 폴더 안에 저장소 두 개를 겹치면 GitHub에 내용이 안 올라가고 AI가 어디에 push할지 헷갈립니다.

```
홈 폴더/
├── baemin-ops-os-camp/          ← 공동 저장소 (이미 받은 것). 여기엔 PRD·제출서·스크린샷만
│   └── 02_실전캠프_Day2_실습제출/1조_이범례_부찌대학/v1/제출서.md  ← 두 링크를 적는 곳
└── projects/
    └── staff-schedule/           ← 내 프로젝트 = 내 개인 저장소. 코드는 전부 여기
```

AI에게 일을 시킬 때 **어느 폴더를 열고 말하는지**만 구분하면 됩니다. 코드 작업은 프로젝트 폴더에서, 제출서 작성은 공동 저장소 폴더에서.

## 전체 흐름 — 세 단계

```
[1] 내 컴퓨터의 프로젝트 (공동 저장소 밖 별도 폴더)
        │  push
        ▼
[2] 내 GitHub 저장소 (Public)  ◀── Supabase 주소·anon 키는 환경변수로 (코드에 안 적음)
        │  Vercel이 자동으로 읽음
        ▼
[3] Vercel 인터넷 주소  https://내프로젝트.vercel.app
        │
        └──▶ 공동 저장소 제출서에 [2]와 [3] 링크 적기
```

|---|---|---|

| 1 | [내 GitHub 저장소 만들기](1_내GitHub저장소만들기.md) | 5분 |

| 3 | [Vercel로 인터넷 주소 받기](3_Vercel_인터넷주소받기.md) | 10분 |

데이터를 저장할 필요가 없는 도구(계산기, 체크리스트 화면 등)는 2단계를 건너뜁니다.
GitHub 연동이 당장 안 될 때는 [부록: AI가 내 폴더에서 바로 올리기](부록_급할때_CLI로_올리기.md)로 임시 주소를 만들 수 있습니다.

## 한 번 해 두면

그 다음부터는 **push만 하면 인터넷 주소가 자동으로 새로워집니다.** v2도, 10/17 최종본도 같은 주소에 올라갑니다.

## 세 가지 계정

| 서비스 | 하는 일 | 가입 | 비용 |
|---|---|---|---|
| GitHub | 코드 보관 | 이미 있음 | 무료 |
| Vercel | 인터넷 주소 만들기 | **GitHub 계정으로 로그인** | 무료로 시작 |
| Supabase | 데이터 저장 | **GitHub 계정으로 로그인** | 무료로 시작 |

셋 다 GitHub 계정 하나로 로그인됩니다. 새 비밀번호를 만들 필요가 없습니다.

## 절대 규칙

- **service_role 키, 비밀번호는 코드에도 GitHub에도 넣지 않습니다.** 환경변수 칸에만 넣습니다.
- 개인 저장소를 **Public**으로 만들기 전에 `.gitignore`에 `.env*`가 있는지 AI에게 확인시킵니다.
- 실제 직원·손님 정보, 실제 매출 파일은 넣지 않습니다. 시연용 가짜 데이터를 씁니다.
