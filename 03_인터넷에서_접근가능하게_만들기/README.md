# 인터넷에서 접근 가능하게 만들기

> 발표 자료: [슬라이드](../04_실전캠프_Day2_수업자료/발표자료/03_인터넷에서_접근가능하게.html)

내 컴퓨터에서만 열리는 화면은 나만 봅니다. **인터넷 주소**가 생기면 다른 사장님도, 직원도, 강사도 폰으로 엽니다.
이걸 "배포"라고 부릅니다. 여기서는 "인터넷에서 접근 가능하게 만들기"라고 하겠습니다.

## 왜 공동 저장소에 코드를 안 올리고 따로 하나요?

- 12명 코드가 한곳에 섞이면 서로 건드려서 깨집니다.
- Vercel은 저장소 **하나 = 사이트 하나**로 연결합니다. 12개 프로젝트가 한 저장소에 있으면 연결이 안 됩니다.
- 내 저장소는 내 것이라 캠프가 끝나도 계속 씁니다.

그래서 **코드는 내 개인 저장소에, 공동 저장소에는 링크만** 올립니다.

## 전체 흐름 — 세 단계

```
[1] 내 컴퓨터의 프로젝트
        │  push
        ▼
[2] 내 GitHub 저장소 (Public)  ◀── Supabase 주소·anon 키는 환경변수로 (코드에 안 적음)
        │  Vercel이 자동으로 읽음
        ▼
[3] Vercel 인터넷 주소  https://내프로젝트.vercel.app
        │
        └──▶ 공동 저장소 제출서에 [2]와 [3] 링크 적기
```

| 단계 | 문서 | 걸리는 시간 |
|---|---|---|
| 1 | [내 GitHub 저장소 만들기](1_내GitHub저장소만들기.md) | 5분 |
| 2 | [Supabase 데이터 창고 연결하기](2_Supabase_데이터창고연결.md) — 저장이 필요한 도구만 | 10분 |
| 3 | [Vercel로 인터넷 주소 받기](3_Vercel_인터넷주소받기.md) | 10분 |
| ✔ | [제출 전 체크리스트](제출전_체크리스트.md) | 2분 |

데이터를 저장할 필요가 없는 도구(계산기, 체크리스트 화면 등)는 2단계를 건너뜁니다.

## 한 번 해 두면

그 다음부터는 **push만 하면 인터넷 주소가 자동으로 새로워집니다.** v2도 같은 주소에 올라갑니다.

## 세 가지 계정

| 서비스 | 하는 일 | 가입 | 비용 |
|---|---|---|---|
| GitHub | 코드 보관 | 이미 있음 | 무료 |
| Vercel | 인터넷 주소 만들기 | **GitHub 계정으로 로그인** | 무료로 시작 |
| Supabase | 데이터 저장 | **GitHub 계정으로 로그인** | 무료로 시작 |

셋 다 GitHub 계정 하나로 로그인됩니다. 새 비밀번호를 만들 필요가 없습니다.

## 절대 규칙

- **service_role 키, 비밀번호는 코드에도 GitHub에도 넣지 않습니다.** 환경변수 칸에만 넣습니다.
- 개인 저장소를 **Public**으로 만들기 전에 `.gitignore`에 `.env*`가 있는지 AI에게 확인시킵니다.
- 실제 직원·손님 정보, 실제 매출 파일은 넣지 않습니다. 시연용 가짜 데이터를 씁니다.
