# 인터넷에서 접근 가능하게 만들기

> 발표 자료: [슬라이드](../04_실전캠프_Day2_수업자료/발표자료/03_v1만들기_내폴더에_같이.html)

> **이 문서는 10/2 중간 점검 때 씁니다.** 10/2까지는 코드가 공동 저장소 내 폴더에 있고, 10/2에 각자 개인 저장소로 흩어집니다.
> 오늘 임시 주소가 필요하면 [부록: AI가 내 폴더에서 바로 올리기](부록_CLI로_바로_올리기.md).

내 컴퓨터에서만 열리는 화면은 나만 봅니다. **인터넷 주소**가 생기면 다른 사장님도, 직원도, 강사도 폰으로 엽니다.
이걸 "배포"라고 부릅니다. 여기서는 "인터넷에서 접근 가능하게 만들기"라고 하겠습니다.

## 왜 10/2에 개인 저장소로 흩어지나요?

- 10/2까지는 공동 저장소가 편합니다. 서로 어떻게 만들었는지 폴더를 열어 보고 힌트를 얻을 수 있습니다.
- Vercel은 저장소 **하나 = 사이트 하나**로 연결합니다. 12개 앱이 한 저장소에 있으면 각자 주소를 만들기 불편합니다.
- 내 저장소는 내 것이라 캠프가 끝나도 계속 씁니다.

그래서 **10/2까지는 공동 저장소 내 폴더에, 10/2부터는 내 개인 저장소에서** 작업합니다.

## 전체 흐름 — 네 단계

```
[0] 공동 저장소 · 내 폴더 · v2/프로젝트/  ──복사──▶  새 폴더 (독립 프로젝트)
        │
        ▼
[1] 내 컴퓨터의 프로젝트
        │  push
        ▼
[2] 내 GitHub 저장소 (Public)  ◀── Supabase 주소·anon 키는 환경변수로 (코드에 안 적음)
        │  Vercel이 자동으로 읽음
        ▼
[3] Vercel 인터넷 주소  https://내프로젝트.vercel.app
        │
        └──▶ 공동 저장소 제출서에 [2]와 [3] 링크 적기
```

## 한 번 해 두면

그 다음부터는 **push만 하면 인터넷 주소가 자동으로 새로워집니다.** 10/17 최종본도 같은 주소에 올라갑니다.

## 세 가지 계정

| 서비스 | 하는 일 | 가입 | 비용 |
|---|---|---|---|
| GitHub | 코드 보관 | 이미 있음 | 무료 |
| Vercel | 인터넷 주소 만들기 | **GitHub 계정으로 로그인** | 무료로 시작 |
| Supabase | 데이터 저장 | **GitHub 계정으로 로그인** | 무료로 시작 |

셋 다 GitHub 계정 하나로 로그인됩니다. 새 비밀번호를 만들 필요가 없습니다.

## 절대 규칙

- **service_role 키, 비밀번호는 코드에도 GitHub에도 넣지 않습니다.** 환경변수 칸에만 넣습니다.
- 개인 저장소를 **Public**으로 만들기 전에 `.gitignore`에 `.env*`가 있는지 AI에게 확인시킵니다.
- 실제 직원·손님 정보, 실제 매출 파일은 넣지 않습니다. 시연용 가짜 데이터를 씁니다.
