# 2단계 · Supabase 데이터 창고 연결하기

**데이터를 저장해야 하는 도구만** 합니다. (근무표 저장, 정산 기록 누적, 매뉴얼 내용 수정 등)
화면만 있고 저장이 없으면 건너뜁니다.

Supabase(수파베이스)는 **엑셀 시트 같은 온라인 창고**입니다. 어느 컴퓨터, 어느 폰에서 열어도 같은 데이터를 봅니다.

## 누가 무엇을 하나

**대부분은 Claude가 크롬에서(Claude in Chrome) 대신 합니다.** 사장님은 세 번만 직접 하면 됩니다.

| 순서 | 할 일 | 누가 |
|---|---|---|
| ① | Supabase 가입·로그인 | **사장님** |
| ② | 새 프로젝트 만들기 (서울 지역) | Claude in Chrome |
| ③ | 테이블 만들기 + 잠금(RLS) 켜기 | Claude in Chrome |
| ④ | 열쇠 두 개가 있는 화면 열어 두기 | Claude in Chrome |
| ⑤ | 열쇠 두 개를 복사해서 **내 컴퓨터 파일**에 붙여넣기 | **사장님** |
| ⑥ | 같은 열쇠를 **Vercel 환경변수 칸**에 붙여넣기 (3단계에서) | **사장님** |

로그인과 열쇠 붙여넣기를 사장님이 하는 이유: 계정과 열쇠는 사장님 것이라 AI가 대신 입력하지 않습니다.

## 시작하기 — AI에게 이렇게 말합니다

> Supabase 연결을 Claude in Chrome으로 진행해 줘. PRD를 보고 필요한 테이블도 만들고 RLS도 켜 줘.
> 가입·로그인과 열쇠 붙여넣기는 내가 할게. 내 차례가 오면 멈추고, 무엇을 어디에 하면 되는지 알려 줘.
> 열쇠 값을 채팅에 적거나 대신 입력하지는 마.

Claude가 크롬 탭을 열고 진행합니다. **사장님 차례**가 오면 Claude가 멈추고 알려 줍니다.

---

## ① 사장님 차례 — 가입·로그인 (1분)

Claude가 크롬에 https://supabase.com 을 열어 두면:

1. **Start your project** (또는 **Sign in**) 클릭
2. **Continue with GitHub** 클릭
3. GitHub 허용 화면이 나오면 **Authorize** 클릭
4. Supabase 대시보드가 보이면 Claude에게 **"로그인했어"**라고 말합니다

> 💡 크롬에서 Claude 확장 권한을 묻는 창이 뜨면 **허용**을 누릅니다. 이 창도 사장님만 누를 수 있습니다.

## ②~④ Claude 차례 — 기다리기

Claude가 크롬에서 다음을 합니다. 화면이 움직이는 걸 지켜보기만 하면 됩니다.

- **새 프로젝트**: 이름은 도구 이름(예: `staff-schedule`), 지역은 **Northeast Asia (Seoul)**. 데이터베이스 비밀번호는 **Generate a password** 버튼으로 자동 생성합니다. 이 도구에서는 쓸 일이 없으니 따로 적어 두지 않아도 됩니다. (필요하면 나중에 재설정 가능)
- 프로젝트가 준비될 때까지 1~2분 기다립니다.
- **테이블 만들기**: PRD를 보고 필요한 표를 **SQL Editor**에서 만듭니다. 초록색 "Success"가 뜨면 성공입니다.
- **잠그기(RLS)**: 열쇠 하나(anon)는 공개용이라, 표마다 잠금을 걸어야 남이 내 데이터를 못 봅니다. 시연용 가짜 데이터만 넣더라도 켭니다.
- **열쇠 화면 열기**: **Project Settings → API** 화면을 열어 두고 멈춥니다.

## ⑤ 사장님 차례 — 열쇠 두 개 붙여넣기 (2분)

Claude가 두 가지를 준비해 두고 멈춥니다.
- 크롬에는 **열쇠 화면**(Project Settings → API)
- 내 컴퓨터에는 **`.env.local` 파일**이 텍스트 편집기로 열려 있습니다. 안에 이름만 적혀 있고 `=` 뒤가 비어 있습니다.

| 크롬 열쇠 화면의 이름 | 붙여넣을 줄 (`.env.local`) | 공개해도 되나 |
|---|---|---|
| **Project URL** | `NEXT_PUBLIC_SUPABASE_URL=` 뒤 | 됨 |
| **anon public** 키 | `NEXT_PUBLIC_SUPABASE_ANON_KEY=` 뒤 | 됨 (공개용 열쇠) |
| **service_role** 키 | — | **절대 안 됨. 복사하지 않습니다** |

순서:
1. 크롬 열쇠 화면에서 **Project URL** 옆 복사 버튼 → 편집기의 첫 줄 `=` 바로 뒤에 붙여넣기
2. **anon public** 옆 복사 버튼 → 둘째 줄 `=` 바로 뒤에 붙여넣기
3. 앞뒤에 빈칸이 없는지 보고 **저장(⌘S)** → 편집기 닫기
4. Claude에게 **"붙여넣고 저장했어"**라고 말합니다

Claude는 값을 읽지 않고, 두 줄이 채워졌는지와 `.env.local`이 `.gitignore`에 들어 있는지만 확인한 뒤 연결을 시험합니다.

> 💡 편집기가 안 열렸으면: "`.env.local`을 텍스트 편집기로 열어 줘"라고 말합니다.
> 💡 파일 이름이 다르게 되어 있으면(예: `VITE_...`) Claude가 알려 준 이름 그대로 따릅니다.

## ⑥ Vercel에도 같은 값을 — 3단계에서

내 컴퓨터의 `.env.local`은 Vercel이 못 봅니다. 3단계에서 **Vercel 환경변수 칸**에 같은 두 값을 **사장님이 직접** 붙여넣습니다. (방법은 [3단계](3_Vercel_인터넷주소받기.md)의 "환경변수 넣기")

## 막힐 때

- **Claude가 크롬을 못 연다** → 크롬 오른쪽 위 퍼즐 조각에서 Claude 확장이 켜져 있는지 봅니다. 그래도 안 되면 운영진을 부릅니다.
- **"Invalid API key"** → anon 키를 잘못 붙여넣음. 앞뒤 공백 없이 다시 붙여넣고 저장.
- **화면은 뜨는데 저장이 안 됨** → 잠금(RLS) 규칙이 너무 엄격. 오류 메시지를 그대로 AI에게 붙여넣기.
- **service_role 키를 붙여넣은 것 같다** → 바로 AI에게 말합니다. 파일에서 지우고, GitHub에 올라갔다면 Supabase에서 키를 새로 발급합니다.
