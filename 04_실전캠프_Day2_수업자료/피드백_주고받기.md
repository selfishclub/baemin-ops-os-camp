# 피드백 주고받기 — 10/2 점검 시간에

10/2 온라인 중간 점검 시간에 **다른 사장님 도구를 직접 써 보고 쪽지를 남깁니다.** 서로 써 보는 건 이날 한 번입니다. 10/2부터 10/14까지는 받은 쪽지를 반영하고 내 가게에서 더 써 보며 최종본을 만드는 기간입니다.
쪽지는 GitHub의 **Issue(이슈)** 기능으로 씁니다. 저장소에 붙은 게시판이라고 생각하면 됩니다. 파일을 고치는 게 아니라서 남의 폴더를 건드릴 일이 없습니다.

## 10/2 순서

1. 각자 `중간점검_1002.md`로 v2 상태 공유
2. **개인 저장소로 흩어지기** — 내 폴더 앱을 옆 폴더로 복사 → 개인 저장소(Public) → Vercel 연결 → 제출서에 두 링크 ([03 폴더](../03_인터넷에서_접근가능하게_만들기/README.md))
3. 그 Vercel 주소로 서로 써 보고 Issue 남기기 (아래)

## 얼마나

- 점검 시간 안에 같은 조 사장님 도구 **2개 이상**. 시간이 남으면 다른 조도.
- 한 쪽지에 도구 하나. 길게 안 써도 됩니다. 써 보고 느낀 것 세 줄이면 충분합니다.
- 점검 전에 내 Vercel 주소가 열리는지 한 번 확인해 둡니다.

## 써 보는 방법 — Vercel 주소로

1. [구경하기](../02_실전캠프_Day2_실습제출/README.md#구경하기) 표에서 사장님을 고릅니다.
2. 그 칸의 **열어 보기(Vercel 주소)**를 누릅니다. 설치도 실행도 없습니다. 폰으로 열어도 됩니다.
3. 그분 `중간점검_1002.md` 5번 "봐 줬으면 하는 것"을 먼저 읽습니다.
4. 실제로 눌러 봅니다. 폰과 컴퓨터 둘 다 보면 좋습니다.

폴더(코드)는 "어떻게 만들었나" 힌트용입니다. 써 보는 데는 열 필요가 없습니다.

## 쪽지 남기는 방법 — 웹에서 3분

1. 저장소 위쪽 **Issues** 탭 → 초록색 **New issue**
2. **피드백** 양식을 고릅니다.
3. 제목: `[가게이름] 도구 써 봤어요 — 내 이름`  예) `[빈숲카페] 레시피북 써 봤어요 — 이범례`
4. 칸을 채웁니다. 좋았던 것, 불편했던 것, 있었으면 하는 것.
5. **Submit new issue**.

AI에게 시켜도 됩니다.
> 이 저장소에 Issue를 하나 만들어 줘. 제목은 "[빈숲카페] 레시피북 써 봤어요 — 이범례". 내용은 피드백 양식대로: 좋았던 것 [ ], 불편했던 것 [ ], 있었으면 하는 것 [ ].

## 받은 쪽지 보는 방법

- **Issues** 탭에서 제목에 내 가게 이름이 있는 것을 찾습니다.
- 답을 달고 싶으면 아래 댓글 칸에 씁니다. "고쳤어요"라고 답하고 **Close issue**를 누르면 정리됩니다.
- 점검이 끝나면 `피드백_반영_1014.md` 1번 표에 옮겨 적고, 10/14까지 반영합니다. AI에게 "Issues에서 내 도구 피드백 모아서 표에 정리해 줘"라고 하면 됩니다.

## 좋은 피드백 세 가지

1. **상황을 적는다.** "불편해요"보다 "근무표에 알바 셋을 넣으니 화면이 잘려요".
2. **좋은 것도 적는다.** 그게 지켜야 할 것을 알려 줍니다.
3. **바라는 것 하나.** "이게 있으면 우리 가게에서도 쓸 것 같아요".
