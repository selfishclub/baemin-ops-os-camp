제일 중요한 것

10/2까지 만든 건 내 폴더 v1/프로젝트에 통째로

AI에게 · 시작할 때v1/PRD.md를 읽고 v1 범위만 만들어 줘. 02_실전캠프_Day2_실습제출/[내폴더]/v1/프로젝트 폴더 안에 만들어. 이 폴더는 이미 GitHub 저장소 안이니 git init은 하지 마.

이렇게 돼요

  • 내 폴더 안에 프로젝트/가 생기고 그 안에 코드 · 프롬프트 기록 · 이미지 · 문서 전부
  • node_modules · .env는 자동으로 빠져요 (.gitignore)
  • 사장님마다 package.json이 있어도 폴더가 달라서 안 부딪혀요

이러면 꼬여요

  • 내 폴더 안에서 git init — 저장소 안의 저장소
  • 다른 데서 만든 폴더를 .git째로 복사해 넣기
  • 저장소 맨 위(루트)나 남의 폴더에 파일 만들기
  • 영상 파일 올리기 — 링크로

꼬였으면 AI에게 "방금 만든 .git 폴더 지워 줘" 또는 "내 폴더 밖에 만든 파일을 v1/프로젝트으로 옮겨 줘". 운영진도 불러요.

같이 만들기

자주 pull, 자주 push — 서로 끌어다 써요

시작할 때

pull

"GitHub 최신 내용 pull해 줘." 다른 사장님이 올린 앱이 내 컴퓨터에 들어와요.

한 기능 될 때마다

push

"지금까지 된 것 커밋하고 push해 줘." 30분에 한 번은 올려요. 컴퓨터가 꺼져도 안 잃어요.

남의 것 볼 때

읽고 복사만

"[2조_양진서_빈숲카페]/v1/프로젝트을 읽고 메뉴 카드 화면을 내 앱에 맞게 가져와 줘. 그 폴더는 고치지 마."

같은 조가 같은 주제를 만들어요. 폴더는 "어떻게 만들었나" 힌트, 써 보는 건 그분 Vercel 주소로. 옆 사장님이 먼저 만든 화면을 가져오면 30분이 줄어요.

열쇠 이야기

공개 저장소예요 — 절대 안 되는 열쇠

올라가도 돼요

  • 코드 전부
  • 시연용 가짜 데이터
  • Supabase Project URL과 anon 키 — 단, 환경변수(.env.local)에만. 어차피 자동으로 빠져요

절대 안 돼요공개 저장소라 전 세계가 봐요

  • Supabase service_role 키 · DB 비밀번호
  • .env 파일 자체 · 로그인 세션 파일
  • 실제 직원 · 손님 이름, 연락처, 실제 매출 파일

push 전에 AI에게 "키 들어간 파일 없는지 확인해 줘". 실수로 올렸으면 파일 삭제가 아니라 키 재발급이에요. 운영진에게 바로 알려요.

제출 전

네 개만 확인 — 주소가 먼저

#확인방법
1Vercel 주소가 열리나내 폰 + 옆 사람 폰
2만든 폴더가 내 폴더 v1/프로젝트 안에 있나GitHub 웹에서 내 폴더 → v1 → 프로젝트
3.env · 키 · node_modules가 안 올라갔나프로젝트 폴더 파일 목록에 없음
4제출서(주소) + 결과물/첫화면.png + pushGitHub 웹에서 보이면 끝

제출서 맨 아래 확인 칸으로 셀프 체크. 오늘 임시 Vercel 주소가 필요하면 AI에게 "이 프로젝트를 Vercel에 배포해 줘, npx vercel로" 한마디.
