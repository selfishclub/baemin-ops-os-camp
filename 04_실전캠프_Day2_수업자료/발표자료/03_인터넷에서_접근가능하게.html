나에게

집에서도, 가게에서도, 폰에서도.

인터넷 주소가 있으면 어디서든 같은 걸 열어요.

왜 공동 저장소에 코드를 안 올리나

저장소 하나 = 사이트 하나

이유 1

섞이면 깨져요

12명 코드가 한곳에 있으면 서로 건드려요. 내 것만 있는 곳이 안전해요.

이유 2

Vercel은 저장소 하나에 사이트 하나

12개 프로젝트가 한 저장소에 있으면 연결이 안 돼요.

이유 3

내 저장소는 내 거예요

캠프가 끝나도 계속 씁니다. v2도, 그 다음도 같은 곳에.

그래서 코드는 내 개인 저장소에, 공동 저장소에는 링크만 올려요.

세 단계

한 번 해 두면 push만 하면 자동이에요

1 · 5분

내 GitHub 저장소

"이 프로젝트를 내 GitHub에 새 저장소로, Public으로 올려 줘. .gitignore에 .env* 있는지 확인하고." AI가 주소를 알려 줘요.

2 · 10분 · 저장이 필요할 때만

Supabase 창고

GitHub 계정으로 가입 → 새 프로젝트(Seoul) → URL과 anon 키만 복사 → AI에게 "연결해 줘, 코드에 직접 적지 마". 테이블은 AI가 SQL로.

3 · 10분

Vercel 주소

GitHub 계정으로 가입 → Import 내 저장소 → 환경변수(Supabase 값) → Deploy → 주소. 내 폰에서 열리면 성공.

셋 다 GitHub 계정 하나로 로그인돼요. 새 비밀번호 안 만들어도 돼요. 무료로 시작합니다.

열쇠 이야기

공개해도 되는 열쇠, 절대 안 되는 열쇠

공개해도 돼요코드 · 환경변수에

  • Supabase Project URL
  • Supabase anon 키 — 공개용으로 만들어진 열쇠
  • 단, 테이블에 잠금(RLS)을 켜야 남이 내 데이터를 못 봐요

절대 안 돼요코드 · GitHub · 카톡 어디에도

  • Supabase service_role 키 — 관리자 열쇠
  • Database 비밀번호
  • .env 파일 자체
  • 로그인 세션 파일

개인 저장소는 Public이라 올라가면 전 세계가 봐요. 올리기 전에 AI에게 "키 들어간 파일 없는지 확인해 줘"를 꼭. 실수로 올렸으면 파일 삭제가 아니라 키 재발급이에요.

제출 전

여섯 개만 확인

#확인방법
1개인 저장소가 Public인가저장소 이름 옆 Public
2비밀이 안 올라갔나.env, 키가 파일 목록에 없음
3Vercel 주소가 열리나내 폰 + 옆 사람 폰
4제출서에 두 링크개인 저장소 + Vercel
5스크린샷결과물/ 폴더에 1장 이상

AI에게 "제출 전 체크리스트 여섯 개 확인하고 v1 제출로 커밋·push해 줘". 여섯 개 다 되면 v1 완료예요.
