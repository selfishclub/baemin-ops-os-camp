v1이 일찍 끝나면 같은 저장소에서 v2까지 시작해도 돼요. push하면 Vercel에 자동으로 올라가요.

제일 중요한 것

폴더는 나란히, 저장소는 따로

홈 폴더/
├── baemin-ops-os-camp/    ← 공동 저장소 (이미 받은 것) · PRD · 제출서 · 스크린샷만
└── projects/
    └── staff-schedule/     ← 내 프로젝트 = 내 개인 저장소 · 코드는 전부 여기

이렇게 해요

  • 코드 작업은 프로젝트 폴더를 열고 AI에게
  • 제출서는 공동 저장소 폴더를 열고 AI에게
  • 이미 공동 저장소 안에서 만들던 분은 복사해서 옆으로 (03 폴더 0단계)

이러면 꼬여요

  • 공동 저장소 폴더 안에 프로젝트 만들기
  • 한 폴더 안에 저장소 두 개 겹치기 (git init 두 번)
  • 공동 저장소에 코드 통째로 올리기

저장소 안의 저장소는 GitHub에 빈 껍데기로만 보이고, AI가 어디에 push할지 헷갈려요. 옆에 두면 아무 문제 없어요.

세 단계 · 15분

한 번 해 두면 push만 하면 자동이에요

1 · 5분

내 GitHub 저장소

"이 프로젝트를 내 GitHub에 새 저장소로, Public으로 올려 줘. .gitignore에 .env* 있는지 확인하고." AI가 주소를 알려 줘요.

2 · 10분 · 저장이 필요할 때만

Supabase 창고

사장님: GitHub 계정으로 가입·로그인 → Claude in Chrome: 새 프로젝트(Seoul)·테이블·잠금(RLS) → 사장님: URL과 anon 키를 .env.local에 붙여넣기.

3 · 10분

Vercel 주소

GitHub 계정으로 가입 → Import 내 저장소 → 환경변수(Supabase 값) → Deploy → 주소. 내 폰에서 열리면 성공.

셋 다 GitHub 계정 하나로 로그인돼요. 무료로 시작. 그 뒤로는 push만 하면 같은 주소에 새 버전 — v2도, 10/17 최종도.

열쇠 이야기

내 저장소는 공개예요 — 절대 안 되는 열쇠

올라가도 돼요

  • 코드 전부 — 다른 사장님이 보고 힌트를 얻어요
  • 시연용 가짜 데이터
  • Supabase URL과 anon 키 — 단, 환경변수(.env.local)에만. 자동으로 빠져요

절대 안 돼요공개 저장소라 전 세계가 봐요

  • Supabase service_role 키 · DB 비밀번호
  • .env 파일 자체 · 로그인 세션 파일
  • 실제 직원 · 손님 이름, 연락처, 실제 매출 파일

push 전에 AI에게 "키 들어간 파일 없는지 확인해 줘". 실수로 올렸으면 파일 삭제가 아니라 키 재발급이에요. 운영진에게 바로 알려요.

제출 전

다섯 개만 확인

#확인방법
1개인 저장소가 Public인가저장소 이름 옆 Public
2개인 저장소에 .env · 키가 없나파일 목록에 없음
3Vercel 주소가 열리나내 폰 + 옆 사람 폰
4제출서에 두 링크 + 결과물/첫화면.png공동 저장소 내 폴더 v1/
5공동 저장소에 push 했나GitHub 웹에서 제출서 보이면 끝

제출서 맨 아래에 이 다섯 칸이 있어요. 공동 저장소 폴더를 열고 AI에게 "제출서 채우고 다섯 개 확인하고 v1 제출로 커밋·push해 줘".
