# AI에게 말하기 — 상황별 복붙 프롬프트

명령어를 외우지 않습니다. **상황에 맞는 문장을 복사해서 붙여넣고 `[ ]`만 바꿉니다.**
Claude(클로드) 기준이지만 다른 AI도 같은 말이 통합니다.

## 좋은 요청의 틀 — 네 칸

이범례 사장님 스타터 키트의 첫 프롬프트가 쓰는 방식입니다. 길게 쓸 때는 이 네 칸을 채우면 AI가 훨씬 잘 알아듣습니다.

```
【 상황 】 나는 ○○ 가게 사장이야. 지금 ○○을 이렇게 하고 있어. 코딩은 잘 몰라.
【 할 일 】 1. ○○ 해 줘  2. ○○ 해 줘
【 의도 】 이걸로 ○○ 시간을 줄이려는 거야.
【 주의 】 ○○은 하지 마. 모르면 지어내지 말고 물어봐. 돈 드는 건 먼저 말해 줘.
```

짧게 쓸 때의 세 원칙: **상황을 말한다 · 원하는 결과를 말한다 · 하지 말 것을 말한다.**

## 1. GitHub

**처음 가져오기**
> https://github.com/selfishclub/baemin-ops-os-camp 저장소를 내 컴퓨터에 처음 가져와 줘. 홈 폴더 아래에 받아 줘.

**작업 시작**
> 이 프로젝트에 아직 저장 안 한 수정이 있는지 먼저 확인해 줘. 없으면 GitHub 최신 내용을 pull해 줘.

**내 폴더 열기**
> `02_실전캠프_Day2_실습제출` 안의 `[1조_이범례_부찌대학]` 폴더를 열고 안에 뭐가 있는지 알려 줘.

**작업 끝**
> 오늘 바꾼 내용을 보여 주고, 비밀번호나 API 키가 없는지 확인한 다음, "[v1 PRD 작성]"이라고 커밋하고 GitHub에 push해 줘.

**올라갔는지 확인**
> 방금 push한 게 GitHub에 올라갔는지 확인해 줘. 안 올라갔으면 이유를 알려 줘.

**남의 것 참고**
> `02_실전캠프_Day2_실습제출` 폴더에서 [2조] 사장님들 PRD를 읽고, 내 PRD에 빠진 것이나 참고할 점을 알려 줘.

**로그인이 필요하대요**
> GitHub 로그인부터 도와줘. 브라우저가 열리면 내가 로그인할게.

## 2. 기획안(PRD)

**순서: 전체 PRD를 먼저 그리고 → v1·v2로 나눕니다.**

**스킬이 있을 때 (운영진이 안내)**
> 운영진이 준비한 `baemin-ops-prd` 스킬로 인터뷰를 시작합니다. 전체 PRD → v1 → v2가 차례로 만들어집니다.

**처음부터 (스킬 없이)**
> 내가 하는 일은 [국밥집 운영]인데 매번 [알바 주급 계산]이 힘들어. `PRD_전체.md`를 나와 인터뷰하면서 채워 줘. 질문은 한 번에 하나씩, 내가 짧게 답하면 예를 들어 달라고 다시 물어봐 줘. 다 채우면 기능마다 [v1]/[v2]/[나중]을 붙여 줘.

**이미 쓴 게 있을 때**
> 내가 붙여넣는 기획안으로 `PRD_전체.md`를 먼저 채우고, 빈칸만 나한테 물어봐 줘. [기획안 붙여넣기]

**v1·v2로 나누기**
> `PRD_전체.md`에서 [v1] 기능은 `v1/PRD.md` 양식에, [v2] 기능은 `v2/PRD.md` 양식에 옮겨 줘. v2 맨 위에는 "초안 — v1을 써 본 뒤 고칩니다"라고 적어 줘.

**범위가 너무 클 때**
> `PRD_전체.md`에서 오늘 안에 만들 수 있는 것만 [v1]으로 남겨 줘. 나머지는 [v2]로 옮기고 이유를 한 줄씩 적어 줘.

**절대 자동화하면 안 되는 것 찾기**
> 이 도구에서 사람이 꼭 직접 확인하거나 눌러야 하는 건 뭐야? PRD 8번에 적어 줘.

## 3. 만들기 (v1)

**시작 — 어디에 만드나가 제일 중요**
> `v1/PRD.md`를 읽고 v1 범위만 만들어 줘. **내 폴더 `02_실전캠프_Day2_실습제출/[1조_이범례_부찌대학]/v1/앱/` 안에** 만들어. 이 폴더는 이미 GitHub 저장소 안이니 **git init은 하지 마.** 외부 API는 쓰지 마. 화면은 폰에서도 보이게. 시연용 가짜 데이터를 넣어 줘. 만들기 전에 화면 구성을 먼저 글로 보여 줘.

**한 기능 될 때마다 올리기**
> 지금까지 된 것을 커밋하고 push해 줘. node_modules와 .env가 빠지는지 확인하고, 내 폴더 밖 파일은 건드리지 마.

**다른 사장님 앱 끌어다 쓰기**
> `02_실전캠프_Day2_실습제출/[2조_양진서_빈숲카페]/v1/앱`을 읽고, [메뉴 카드 화면]이 어떻게 만들어졌는지 설명해 줘. 그다음 내 앱에 맞게 가져와 줘. 그 폴더는 절대 고치지 마.

**한 기능씩**
> 지금은 [근무표 입력] 기능만 만들어 줘. 되면 내가 확인하고 다음 걸 시킬게.

**확인**
> 내 컴퓨터에서 열어 볼 수 있게 실행해 주고, 주소를 알려 줘.

**고치기**
> [주급이 틀리게 나와]. 예를 들어 [시급 1만원 × 20시간]이면 [20만원]이 나와야 하는데 [18만원]이 나와. 원인을 찾고 고쳐 줘.

**디자인**
> 화면을 더 보기 쉽게 해 줘. 글자는 크게, 버튼은 손가락으로 누르기 쉽게. 색은 우리 가게 느낌으로 [따뜻한 갈색].

## 4. 완성 후 — 개인 저장소로 옮기고 인터넷 주소 (10/17 이후)

**공동 저장소에서 옮기기**
> 공동 저장소 안의 `02_실전캠프_Day2_실습제출/[내폴더]/v2/앱` 폴더를 홈 폴더 아래 `[staff-schedule]`로 복사해 줘. node_modules와 .env.local은 빼고. 복사본에서만 git init 하고, 공동 저장소 쪽은 그대로 둬.

**개인 저장소**
> 이 프로젝트를 내 GitHub 계정에 새 저장소 `[staff-schedule]`로 Public으로 올려 줘. 올리기 전에 `.gitignore`에 `.env*`가 있는지, 키가 들어간 파일이 없는지 확인해 줘.

**Supabase**
> Supabase 연결을 Claude in Chrome으로 진행해 줘. PRD를 보고 필요한 테이블도 만들고 RLS도 켜 줘. 가입·로그인과 열쇠 붙여넣기는 내가 할게. 내 차례가 오면 멈추고, 무엇을 어디에 하면 되는지 알려 줘. 열쇠 값을 채팅에 적거나 대신 입력하지는 마.

> (열쇠 붙여넣을 차례) `.env.local`을 텍스트 편집기로 열어 줘. 이름만 적어 두고 값은 비워 둬. 내가 붙여넣고 저장할게.

**Vercel 환경변수**
> Vercel 환경변수에 넣어야 할 이름을 표로 알려 주고, Claude in Chrome으로 환경변수 칸까지 열어 줘. 값은 내가 붙여넣을게. service_role 키는 빼 줘.

**배포 실패**
> Vercel 배포가 실패했어. 로그는 이거야: [붙여넣기]. 원인을 찾고 고쳐서 push해 줘.

## 5. 제출

> `v1/제출서.md`를 열어서 도구 이름, 한 줄 설명, 실행 방법 세 줄을 적어 줘. 스크린샷은 `v1/결과물/`에 넣었으니 파일명도 적어 줘. 코드가 `v1/앱` 안에 있고 .env·node_modules가 안 올라가는지 확인한 다음 "v1 제출"로 커밋·push해 줘.

## 6. 막혔을 때

**오류가 났을 때 (제일 많이 씀)**
> 이 오류가 났어: [오류 메시지 그대로 붙여넣기]. 내가 하려던 건 [○○]이야. 원인과 해결 방법을 쉬운 말로 알려 주고, 고칠 수 있으면 고쳐 줘.

**AI가 한 말을 모르겠을 때**
> 방금 설명을 중학생도 알아듣게 다시 말해 줘. 비유를 하나 들어 줘.

**뭘 시켜야 할지 모를 때**
> 내가 지금 [상황]인데, 다음에 뭘 하면 돼? 선택지를 3개 주고 추천 하나를 골라 줘.

**AI가 자꾸 다른 걸 할 때**
> 멈춰. 내가 시킨 건 [○○]뿐이야. 그것만 하고 다른 건 건드리지 마.

**돈 드는 걸 하려고 할 때**
> 이거 유료야? 무료로 되는 방법이 있으면 그걸로 해 줘.
