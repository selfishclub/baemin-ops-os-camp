## 한 줄로

**밤에는 프로그램이 모으고 초안까지, 아침에는 사장님이 확인하고 누르기만.**

## 발표 핵심 요약

### 왜 만들었나
- 매일 밤 플랫폼 세 곳을 돌며 답글을 씁니다. 리뷰 많은 날은 한 시간.
- 놓친 리뷰 하나가 "신경 안 쓰는 가게"로 보이게 합니다.
- 내용은 비슷한데 매번 찾아 들어가는 과정이 깁니다.

### 하루 한 바퀴
| 언제 | 누가 | 무엇 |
|---|---|---|
| 밤 10시 | 프로그램 | 세 곳의 새 리뷰만 모음 |
| 밤 사이 | 프로그램 | 사장님이 써 온 답글 5,426건에서 말투를 배워 초안 작성 |
| 아침 | **사장님** | 읽고 고르고 승인 |
| 승인 후 | 프로그램 | 그 리뷰의 답글칸까지 채우고 **멈춤** |

**등록 버튼은 끝까지 사장님 몫.** 쿠팡이츠는 한 번 올리면 못 고칩니다.

### 목적 세 가지
1. **고객 관리** — 모든 리뷰에 빠짐없이 답한다
2. **데이터** — 흩어진 리뷰를 한 창고에 쌓는다 ("양이 적다"가 이번 달 몇 번인지 세어진다)
3. **인사이트** — 무엇부터 고칠지 숫자로 정한다 (국물 샘 9건 → 포장 용기 교체)

### 도구 둘
| | Playwright (읽어오기) | Aside (답글 채우기) |
|---|---|---|
| 성격 | 뒷방에서 창 없이 일하는 직원 | 내 옆에서 화면 같이 보는 직원 |
| 왜 | 매일 밤 수천 건, 사람 없이, 실수해도 다시 돌리면 됨 | 손님에게 바로 보이는 일이라 사장님 눈앞에서 한 건씩 |
| 비용 | 0원 (오픈소스) | 0원으로 시작 |

### 비밀번호는 안 줍니다
사장님이 **한 번 직접 로그인**하면 생기는 "출입증(세션)"만 사장님 컴퓨터에 둡니다. 비밀번호는 어디에도 저장하지 않고, 출입증은 GitHub·카톡 어디에도 올리지 않습니다.

### 비용
Playwright 0원 · Aside 0원 시작 · Neon(창고) 0원 · Vercel 0원(가게 운영용으로 계속 쓰면 월 $20)

### 넘지 않는 선
- 등록 버튼은 사람이
- 로그인은 사람이 창에서
- 수집은 읽기 전용
- "비정상 동작" 문구가 뜨면 멈춤
- 한 건씩, 간격을 두고
- 비밀은 올리지 않음

## 이 사례에서 배울 것 — GitHub과 연결해서

1. **있는 걸 받아 내 것으로 고쳐 쓴다.** 스타터 키트가 GitHub에 있어서 가능합니다. 처음부터 만들지 않습니다.
2. **PRD 먼저.** 키트도 첫 프롬프트가 "아직 구현하지 마. PRD까지만"입니다.
3. **사람이 누르는 자리를 정한다.** 내 도구에도 "절대 자동화 안 할 것"을 PRD 8번에 적습니다.
4. **v1 / v2.** 키트도 0단계(가짜 리뷰 화면)부터 5단계까지 나눠 갑니다.
