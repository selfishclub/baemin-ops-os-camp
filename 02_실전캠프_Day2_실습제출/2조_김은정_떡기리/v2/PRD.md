# 기획안(PRD) — 떡기리 신입직원 교육 온라인 북 · v2

> 초안 — 중간 점검에서 확정

- 가게 / 이름: 떡기리 / 김은정
- 조 주제: 직원 교육 매뉴얼 온라인 북
- 이 버전의 목표 한 줄: **직원이** **오픈·마감 때** **매장·이름을 고르고 체크한 뒤 "완료"를 누르면 서버에 남고**, **사장은** **매일** **3매장의 오픈·마감이 됐는지 한눈에 보는** 온라인 북

> 전체 그림은 `../PRD_전체.md`에 있습니다. v1을 열흘 써 본 기록(`../v1/사용메모.md`)으로 9/27에 고쳤습니다. 변경 이유는 `../중간점검_1002.md` 5번.

## 1. 무엇을 왜 만들고 싶나요?

v1을 열흘 써 보니 두 가지가 나왔습니다.
- 카톡 링크로 연 직원은 체크가 풀렸다. v1은 체크를 "그 폰에만" 저장하는데, 카톡 내장 브라우저는 그 저장을 지운다.
- 체크를 해도 "누가 했는지"가 안 남는다. 오픈·마감은 매일 하는 일인데, 사장은 매장 3곳이 오늘 체크를 했는지 확인할 방법이 없다.
그래서 v2는 매뉴얼 보기는 그대로 두고, **체크리스트를 "누가·어느 매장·몇 시에 완료했는지" 서버에 남기고 사장이 보는 것**에 집중합니다.

## 2. 누가 언제 쓰나요?

- **직원**: 오픈·마감 때 체크리스트를 열면 먼저 **매장(3곳 중 하나)과 이름(목록에서 선택)**을 고른다. 폰이 한 번 기억해 다음부터는 자동. 항목을 체크하고 마지막에 **"오픈 완료" / "마감 완료"** 버튼을 누른다. 로그인은 없다.
- **사장**: 사장 화면(PIN)에서 오늘 3매장의 오픈·마감 상태를 본다. 아침·저녁에 한 번씩, 폰으로. 날짜를 넘겨 지난 기록도 본다.
- **담당 사수**: 같은 사장 화면에서 자기 매장 기록을 본다 (PIN 공유).
- 매뉴얼 12장·검색·교육표·확인 필요는 v1과 같다.

## 3. 지금은 어떻게 하고 있나요?

v1: 체크는 그 폰에만 남고 다음 날 사라진다. 누가 했는지 없다. 사장은 "마감 다 했어?"를 물어봐야 하는데, 실제로는 물어볼 방법조차 정하지 않아 확인을 못 하고 있다. 직원 대부분은 카톡 링크로 열어서 체크가 유지되지도 않는다.

## 4. 도구를 쓰면 어떤 일이 달라지나요?

한 건 기준:
- **넣는 것**: 직원이 마감 체크리스트를 열고 → 매장 "상동점", 이름 "알바 A"를 고름 → 6개 항목 체크 → "마감 완료" 누름
- **나오는 것**: 서버에 "9/28 상동점 마감 · 알바 A · 21:05 · 6/6" 기록. 사장 점검표에 상동점 마감이 초록으로 바뀌고 시각·이름이 보임. 미완료 매장은 빨간색 "아직"
- **달라지는 것**: 어느 폰·어느 브라우저로 열어도 기록이 같음. 사장은 묻지 않고 3초 안에 3매장 상태를 안다. 빠진 항목이 있으면 어떤 항목인지도 보인다

## 5. v2에서 만들 것 — 10/2 1차 마감, 10/14 최종 (API 연동·외부 데이터 등 v1에서 미룬 것)

**꼭 할 것**
- 기능 1: **매장·이름 고르기 + 완료 버튼 + 서버 저장** — 체크리스트 첫 화면에서 매장(3곳)·이름(목록) 선택 → 항목 체크(항목마다 시각 기록) → "오픈 완료"/"마감 완료" 버튼 → Supabase에 저장. 폰이 매장·이름을 기억. 완료 뒤 "오늘 상동점 마감 완료 · 알바 A · 21:05" 확인 화면
- 기능 2: **사장 점검표 (PIN)** — 오늘 날짜 기준 매장 3곳 × 오픈·마감 6칸. 완료(초록: 시각·이름·n/n), 진행 중(노랑: 몇 개 체크), 아직(빨강). 칸을 누르면 항목별 체크 시각과 빠진 항목. 날짜 이동(어제·지난주). 이름 목록·매장 목록 편집(간단)

**여유 있으면**
- 기능 3: 첫 화면에 "오늘 우리 매장 오픈/마감 상태" 한 줄 표시 (직원도 봄)
- 기능 4: 사장 관리 화면 — 12장 내용을 화면에서 수정 (Supabase). 지금은 파일 방식으로 충분해서 뒤로 미룸
- 기능 5: 신입 교육표 "읽었어요"도 서버에 (이름별) 저장 → 점검표에 신입 진행 표시

**준비물**
- Supabase: 가입·로그인, 열쇠(Project URL, anon 키) 붙여넣기는 사장이 직접. 프로젝트·테이블·RLS·열쇠 화면 열기는 Claude가 Claude in Chrome으로
- Vercel 환경변수 2개 (같은 열쇠). service_role 키는 쓰지 않음
- 시연용 가짜 이름 목록 (알바 A·B·C, 매니저 1) — 실명은 사장이 나중에 화면에서 바꿈

- **이번에 하지 않을 것:** 직원 로그인(이름 고르기로 충분한지 먼저 봄), 카톡 채널 챗봇(채널·오픈빌더 승인 필요 → [나중]), 재고 엑셀 연결, AI 응대 초안, 명절 시즌 장, 퀴즈

## 6. 완성됐다는 걸 어떻게 확인하나요?

- 시연할 예시 입력: 폰 A에서 마감 체크리스트 → "상동점"·"알바 A" 선택 → 6개 체크 → 마감 완료. 폰 B(카톡 링크로 열기)에서 오픈 체크리스트 → "공항점"·"알바 B" → 4개만 체크하고 닫음. 사장 폰에서 PIN → 점검표
- 기대하는 결과: 점검표에 상동점 마감 초록(알바 A · 시각 · 6/6), 공항점 오픈 노랑(4/7, 빠진 항목 3개 표시), 나머지 빨강 "아직". 폰 B를 다시 열어도 4개 체크가 그대로(서버에서 읽음)
- 잘못 입력했을 때: 매장·이름을 고르지 않으면 체크가 안 되고 "누구인지 골라 주세요". 인터넷이 끊기면 "저장 안 됨 — 연결 후 다시 눌러 주세요"가 뜨고 체크는 폰에 임시 보관. 틀린 PIN이면 점검표가 안 열림. 같은 날 같은 매장에서 두 번 완료를 누르면 나중 것으로 덮어쓰되 첫 완료 시각도 남김
- 다시 열었을 때 남아 있어야 할 것: 모든 매장·모든 직원의 체크·완료 기록 (다른 폰·다른 브라우저·카톡 브라우저에서도 동일). 이름·매장 목록

- 사람이 직접 판단·확인해야 할 부분: 챗봇 답변은 매뉴얼 문장만 쓰고 사장이 검수. 미완료 매장에 연락할지는 사장이 판단 (자동 알림은 [나중])

## 8. 절대 자동화하면 안 되는 것

- 손님에게 직접 보내는 메시지·답변 전송
- 알레르기·유통기한·보관 기한·위생 온도 같은 안전 정보의 자동 생성
- "완료" 버튼 (직원이 직접 누름. 항목이 다 체크됐다고 자동 완료하지 않음)
- 직원에게 "마감 안 했어요" 알림 보내기 (사장이 보고 직접 연락)
- 신입 교육 "관리자 확인" (사수가 직접)
- 직원 근무·급여와 관련된 판단 (체크 기록을 근태·급여 근거로 쓰지 않음)
