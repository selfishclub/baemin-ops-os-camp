# 떡기리 온라인북 v3 — 다점포 배포형 설계안 (코드 수정 전 검토용)

작성 2026-11-01. 코드는 아직 건드리지 않았습니다. 이 문서로 구조를 확정한 뒤 단계별로 고칩니다.

---

## 1. 지금 구조 (v2, 직영 3곳 사용 중)

### 1-1. 파일
- 정적 웹앱 1벌: `index.html` + `app.js`(해시 라우터) + `style.css` + `content.md → content.js`(매뉴얼 12장이 코드에 구워져 있음)
- 서버는 Supabase 하나. 앱이 브라우저에서 REST로 직접 읽고 씀. 열쇠는 Publishable key(공개용)
- Vercel 배포 1곳(실제) + 1곳(데모)

### 1-2. 표(테이블)
| 표 | 무엇 | 지점 구분 방법 |
|---|---|---|
| `checklist_runs` | 날짜·매장·오픈/마감별 체크 기록 (담당자, 항목별 완료시각, 특이사항, 폐기, 완료시각) | `store` 글자(매장 이름) |
| `settings` | key/value 한 묶음: stores, staff, staff_meta(소속·입사일), products, store_items(매장별 추가 항목), owner_pin_hash | 전부 한 줄에 모든 매장이 섞여 있음 |
| `training_progress` | 직원별 교육 진도(읽음·사수 확인) | `store` 글자 |
| `sales` | 준비만 됨, 미사용 | `store` 글자 |

### 1-3. 권한(RLS)
- 모든 표가 "익명(anon)이 읽기·쓰기 전부 가능". 즉 **주소와 공개 열쇠만 알면 누구나 모든 매장 기록을 읽을 수 있음.**
- 지금은 한 사장이 3곳을 다 관리하니 문제없지만, 다른 점주가 들어오는 순간 "점주끼리 기록이 보이면 안 된다"는 조건을 못 지킴. → **이것이 v3에서 바꿔야 할 핵심.**

### 1-4. 화면 흐름
- 직원: 첫 화면 → (매장 고르기 → 이름 고르기, 폰에 기억) → 오픈/마감 체크(즉시 저장, 완료 제출) · 매뉴얼 · 교육표
- 사장: 첫 화면 맨 아래 "사장 점검표" → PIN 4자리(전 매장 공용) → 날짜별 매장×오픈·마감 표 → 목록 화면(매장·이름·떡·매장별 항목·PIN)
- 본사 화면 없음. 매뉴얼 수정은 `content.md` 고쳐서 다시 배포해야 함.

### 1-5. 그대로 가져갈 것(바꾸지 않음)
- 직원 사용법: 이름 고르기 → 누르면 바로 저장 → 완료 제출. 특이사항·폐기 입력. 매뉴얼 12장·검색·교육표
- 점주 점검표의 정보: 담당자·완료시간·체크 수·미완료 항목·특이사항·폐기
- 기술: 빌드 도구 없는 정적 앱 + Supabase + Vercel. 로그인 없이 쓰는 직원 화면.

## 2. 바꿀 구조 (v3)

### 2-1. 한 줄 요약
**"매장 이름"으로 구분하던 것을 "지점 코드"로 구분하고, 앱이 표를 직접 읽지 않고 "지점 코드를 넣어야만 답하는 서버 함수"만 쓰게 한다.** 그러면 코드가 없는 지점 데이터는 애초에 받을 수 없어서 점주끼리 절대 섞이지 않는다.

### 2-2. 세 가지 역할과 들어가는 길
| 역할 | 들어가는 길 | 무엇을 봄 |
|---|---|---|
| 직원 | 지점 전용 링크/QR `…/#/s/AB7K2Q` (코드 6자리, 추측 불가) | 그 지점 직원 이름, 그 지점 체크, 공통 매뉴얼 |
| 점주 | 같은 링크에서 "점주" → PIN 6자리 | 그 지점 기록·직원·설정만 |
| 본사(김은정) | `…/#/hq` → 이메일 로그인(Supabase Auth) | 전 지점 현황, 매뉴얼 편집, 지점 관리 |

- 직원은 **매장을 고르지 않음**. 링크 자체가 매장. (매장 고르기 화면 삭제 → 더 단순해짐)
- 점주 PIN은 지점마다 따로. 김은정 사장 3곳은 같은 PIN을 넣어 두면 됨(그리고 본사 화면에서 3곳을 한 번에 봄)
- 본사 로그인만 이메일인 이유: 전 지점이 다 보이는 자리라 PIN으로는 약함. 쓰는 사람이 1~2명이라 부담 없음.

### 2-3. 데이터가 섞이지 않는 원리
① 표마다 `store_id`(지점 고유번호) 칸을 둠
② 익명 사용자는 표를 직접 못 읽음(지금의 "anon 전부 허용" 정책 삭제)
③ 대신 서버 함수(RPC)만 호출: 예) `staff_bundle('AB7K2Q')` → 그 코드의 지점 직원·설정만 돌려줌. `save_run('AB7K2Q', 날짜, 오픈, …)` → 그 지점에만 씀
④ 점주 함수는 `(코드, PIN)`을 같이 받아 PIN 해시가 맞을 때만 답함. 5번 틀리면 10분 잠금
⑤ 본사 함수는 로그인한 사람이 `hq_admins` 표에 있을 때만 답함
→ 앱 코드를 아무리 뜯어봐도 "코드 없는 지점"은 못 봄.

### 2-4. 공통 매뉴얼
- 지금: `content.md`를 고쳐 배포. v3: 매뉴얼 본문을 **DB 표 `manual_pages`에 장별로 저장**하고 앱이 열 때 받아옴. 본사 화면에서 고치면 저장 즉시 전 지점 반영(직원이 다음에 열 때)
- 장 구성은 지금 12장을 그대로 쓰되 요청하신 묶음으로 보이게: 브랜드 교육 / 고객응대 / 제품관리 / 위생 / 포장 / 기본 운영수칙 (장 번호는 유지하고 "묶음" 꼬리표만 붙임)
- DB가 비어 있으면 지금처럼 `content.js`로 보여 줌(안전장치). 첫 이전 때 content.md를 그대로 DB에 넣음
- 오픈·마감 **공통 체크 항목**도 본사 것(매뉴얼에서 뽑음). **지점 추가 항목**은 점주가 지금처럼 등록("(매주 월·목)" 주기 표기 유지)

## 3. DB 변경 (Supabase)

### 3-1. 새 표
```
stores            지점
  id uuid PK, brand text('떡기리'), name text, code text UNIQUE(6자리, 직원 링크용),
  owner_name, owner_phone, owner_pin_hash text, pin_fail_count int, locked_until timestamptz,
  active bool, created_at
staff             직원 (settings.staff + staff_meta 를 표로)
  id uuid PK, store_id FK, name text, hire_on date, active bool, UNIQUE(store_id, name)
store_settings    지점 설정 (settings.store_items + products 를 지점별로)
  store_id PK, extra_items jsonb{open:[],close:[]}, products jsonb[]
manual_pages      공통 매뉴얼
  id, chapter_no int, group text(브랜드교육/고객응대/…), title, body_md text, updated_at, updated_by
hq_admins         본사 관리자
  user_id uuid PK (Supabase Auth 사용자), name
```

### 3-2. 기존 표에 칸 추가
```
checklist_runs     + store_id uuid FK   (기존 store 글자 칸은 남겨 둠)   UNIQUE(store_id, run_date, kind)
training_progress  + store_id uuid FK, staff_id uuid FK                UNIQUE(staff_id, step)
sales              + store_id (당장 안 씀, 칸만)
```

### 3-3. 권한
- 모든 표: anon의 select/insert/update 정책 **삭제**
- 서버 함수(security definer)만 열어 둠:
  - 직원용: `staff_bundle(code)`, `get_run(code,date,kind)`, `save_run(code,…)`, `save_training(code, staff_id, step, …)`, `manual_all()`
  - 점주용(코드+PIN): `owner_runs(code,pin,date)`, `owner_staff_save(code,pin,…)`, `owner_settings_save(code,pin,…)`, `owner_pin_change(code,pin,new_pin)`
  - 본사용(로그인): `hq_overview(date)`, `hq_store_create(name, owner…)`, `hq_manual_save(chapter_no, body)`, `hq_store_toggle(id, active)`
  - 신규 점주 셀프 등록: `store_register(name, owner_name, phone, pin)` → 코드 발급 (본사 화면에 "새로 등록됨" 표시)

### 3-4. 기존 직영 데이터 이전(보존)
① `stores`에 상동본점·김포공항점·인천공항점 3줄 만들고 코드 발급, 현재 `owner_pin_hash`를 3곳에 복사
② `settings.staff`+`staff_meta` 13명 → `staff` 표(소속 매장으로 store_id 연결)
③ `checklist_runs.store` 이름 → 같은 이름의 `store_id` 채움. `training_progress`도 같은 방법(직원 이름+소속으로 staff_id)
④ `settings.store_items`·`products` → `store_settings`
⑤ `content.md` 12장 → `manual_pages`
⑥ 확인 후에도 옛 `settings` 줄과 `store` 글자 칸은 한동안 지우지 않음(되돌릴 수 있게)
- 이전은 SQL 한 벌(`migrate_v3.sql`)로 하고, 실행 전 Supabase에서 백업(표 내보내기)

## 4. 화면 변경

### 4-1. 직원 화면 (가장 적게 바뀜)
| 지금 | v3 |
|---|---|
| 첫 화면 → 매장 고르기 → 이름 고르기 | 전용 링크로 열면 **바로 이름 고르기**(매장 표시만) |
| 매뉴얼은 코드에 구운 것 | DB에서 받아옴(보기엔 동일) |
| 나머지(오픈·마감 체크, 특이사항, 폐기, 교육표, 검색) | 그대로 |
- 링크 없이 그냥 주소로 들어오면: "매장 QR이나 링크로 들어와 주세요" 안내만(지점 목록 안 보여 줌)
- 기존 직영 직원 폰: 코드가 없으므로 한 번 새 링크를 받아 열어야 함(김은정 사장이 3개 링크를 카톡으로 보냄). 그 뒤는 폰이 기억.

### 4-2. 점주 화면 (지금 "사장 점검표"를 지점 하나짜리로)
- 들어가기: 직원 링크 첫 화면 맨 아래 "점주" → PIN 6자리
- 점검표: 날짜 이동, 오늘 오픈·마감 상태, 기록 카드(담당자·완료시간·체크 수·미완료 항목·특이사항·폐기) — **매장 열이 사라지고 자기 지점만**
- 직원: 이름 추가·수정·퇴사 처리, 입사일, 교육 진도 보기(7일 배지)
- 설정: 지점 추가 항목(오픈/마감), 떡 종류, PIN 바꾸기
- **직원용 링크·QR 보기**: 링크 복사 버튼 + QR 이미지(인쇄해서 매장에 붙임)
- 삭제되는 것: 매장 목록 편집(본사 몫), 직원별 소속 선택(지점 하나니까 불필요)

### 4-3. 본사 화면 (새로 만듦, `#/hq`)
- 로그인: 이메일(매직링크 또는 비밀번호)
- 지점 목록: 지점명·점주·오늘 오픈·마감 완료 여부·교육 진행률(직원 n명 중 m명 완료)·최근 특이사항. 새 등록 지점은 "신규" 표시, 사용 중지 가능
- 지점 상세: 그 지점의 점검표를 점주와 같은 화면으로(읽기)
- 매뉴얼 편집: 장 고르기 → 본문(마크다운) 수정 → 미리보기 → 저장(즉시 전 지점 반영, 수정 시각·수정자 기록)
- 지점 등록: 이름·점주·연락처 → 코드·첫 PIN 자동 생성 → 점주에게 보낼 안내문(링크·PIN) 복사

### 4-4. 신규 점주 시작 과정(요청하신 순서 그대로)
① 지점 등록 — 본사가 등록하거나, 점주가 `#/new`에서 셀프 등록(지점명·이름·전화·PIN). 둘 다 지원, 추천은 **셀프 등록 + 본사 목록에서 확인**
② 점주 PIN 설정 — 등록 때 정함(6자리). 이후 점주 화면에서 변경
③ 직원 등록 — 점주 화면 "직원"에서 이름 입력
④ 직원용 링크/QR — 점주 화면에서 복사·저장·인쇄
⑤ 사용 시작 — 직원이 링크 열고 이름 고르면 끝. 교육표도 바로 사용

## 6. 작업 순서(승인 후 단계별 진행, 매 단계 끝에 실제 주소에서 확인)
① DB: 새 표·함수 만들기 + 직영 데이터 이전 스크립트 → **기존 v2 앱은 그대로 돌아감**(옛 정책은 마지막에 끔)
② 직원 화면을 "지점 코드 + 서버 함수" 방식으로 전환, 매뉴얼 DB 로딩 → 직영 3곳에 새 링크 배포
③ 점주 화면(지점 하나짜리) + 링크·QR
④ 본사 화면(로그인·지점 목록·매뉴얼 편집·지점 등록)
⑤ 셀프 등록 `#/new` + 안내문
⑥ 옛 anon 정책 삭제, 옛 칸 정리, 데모 사이트도 같은 코드로 갱신
- 가장 조심할 단계는 ①·②(데이터 이전과 직영점 전환). 전환 날 하루는 v2 주소를 그대로 살려 두고 새 주소를 따로 써서 비교한 뒤 바꿔 끼움.

## 7. 결정해 주실 것
① 점주 PIN 자릿수: 6자리 추천(4자리는 지점 수가 늘면 위험)
② 본사 로그인: 이메일 매직링크(비밀번호 없음) 추천. 본사 관리자는 김은정 1명으로 시작?
③ 신규 점주: 셀프 등록 허용 vs 본사만 등록
④ 매뉴얼 수정을 화면에서(DB) 할지, 지금처럼 파일 고쳐 배포할지 — 화면 편집 추천(요청 1번 "본사에서 수정하면 전 지점 반영" 때문)
⑤ 매뉴얼 묶음 이름 6개(브랜드 교육·고객응대·제품관리·위생·포장·기본 운영수칙)에 지금 12장을 어떻게 나눠 넣을지 — 제가 초안을 내고 확인받는 방식으로 할지
⑥ 직영 직원들에게 새 링크를 다시 보내는 것 괜찮은지(한 번만)
