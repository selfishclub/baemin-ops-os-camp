# 기획안(PRD) — 해모닉 운영 ERP · v1

- 가게 / 이름: 해모닉 (안산점 · 안양점) / 김민혁
- 조 주제: 매출 분석 대시보드
- 이 버전의 목표 한 줄: **직원이 매장 공용 기기에서 할 일 · 수조 · 근무 · 매출을 그때그때 기록하고, 사장님이 어디서든 진행 상황과 이달 손익을 보는 도구**

전체 그림은 [`../PRD_전체.md`](../PRD_전체.md). 이 문서는 그중 **[v1]** 꼬리표만 다룬다.

## 1. 무엇을 왜 만들고 싶나요?

두 매장(안산 · 안양)의 하루가 사장님 지시와 직원 기억에 기대어 돌아간다. 마감 후 사장님은 직원이 카톡으로 보낸 포스 사진을 보고 엑셀 월별 시트에 매출을 옮겨 적고, 월말에는 매입 영수증과 근무표를 놓고 계산기로 손익을 뽑는다. 세 시간이 걸리고 숫자가 맞는지 확신이 없다. 그 사이에 "수조 해수 교체는 했어?"를 확인하려면 전화를 걸어야 한다.

이미 만들어 둔 운영 OS(할 일 체크 · 수조 관리표 · 근무표 · 근로계약서 · 이슈 · 레시피 · 원가)에 **회계 네 가지(매출 입력 · 매출 분석 · 월 손익 · 인건비)** 를 붙여, 매장 운영과 돈 흐름이 한 앱에 있게 한다.

## 2. 누가 언제 쓰나요?

| 누가 | 여는 순간 | 기기 |
|---|---|---|
| 직원 (홀 · 주방 · 갑각류 관리자, 매장당 2~3명) | 오픈 11:00 · 미들 15:00 · 마감 20:00 시간대마다 할 일을 체크할 때, 수조를 만질 때, 입고할 때, 마감 정산할 때 | 매장 PC · 아이패드 (공용) |
| 사장님 (1명) | 아침에 어제 기록 확인, 낮에 진행률, 월말에 손익·인건비, 근무표 짤 때 | 아이폰(클라우드판), 매장 방문 시 공용 기기 |
| 매니저 (안양점) | 직원과 같음 + 근무표 | 공용 기기 |

직원 개별 로그인은 없다. 체크할 때마다 "누가 했나요?"에서 이름을 고른다.

## 3. 지금은 어떻게 하고 있나요?

| 일 | 지금 |
|---|---|
| 할 일 · 수조 · 근무표 · 계약서 · 이슈 · 레시피 · 원가 | **운영 OS 앱**(`app/` 폴더, 브라우저 저장). 2026-09-11부터 매장에서 쓰는 중 |
| 매출 | 포스 마감 사진 → 사장님이 엑셀 `매출 관리 안양점.xlsx` 월별 시트에 하루 한 줄(총주문 · 매장/배달 매출 · 대게/킹크랩/랍스터 kg · 주류) 옮겨 적음 |
| 손익 | 월말에 엑셀 + 계산기. 매입은 카톡 영수증 사진을 찾아 더함 |
| 인건비 | 근무표 보고 계산기. 주휴수당은 가끔 놓침 |
| 고정비 | 머릿속 |

## 4. 도구를 쓰면 어떤 일이 달라지나요?

한 건 기준:

- **마감 직원이** "포스 마감 · 매출 정산" 루틴을 완료하면서 총주문 12 · 매장 2,450,000원 · 배달 180,000원 · 대게 20.5kg · 킹크랩 8.2kg · 랍스터 1.5kg · 주류 60,000원을 넣는다 (1분).
- **사장님이** 아이폰에서 회계 › 매출 분석을 열면 이번 달 총매출 · 일평균 · 객단가 · 총 kg 카드와 일별 막대, 요일별 평균, 매장/배달/포장 비중, 품종별 kg이 바로 보인다.
- 월 손익을 열면 매출 − 원가(매입) − 인건비(근무표 × 시급, 예상) − 고정비(설정) = 이달 남는 돈이 나온다. 원가율 45% · 인건비율 30%를 넘으면 붉다.
- 인건비 화면에서 직원별 근무 시간 · 기본급 · 주휴수당 · 4대보험 어림을 보고 "이달 급여 확정"을 누르면 손익의 "예상"이 "확정"으로 바뀐다.
- 과거 1년치는 엑셀에서 변환한 CSV를 한 번 가져와 분석에 포함한다.

## 5. 이번 버전에서 만들 것 (v1이면 오늘 안에 되는 것만)

### 이미 만들어져 있어 v1에 그대로 들어가는 것 (검증만)

- 기능 1. **할 일** — 오픈 15 · 미들 10 · 마감 15 루틴, 완료자 이름 · 시각, 증빙(폐사 마릿수 · 매출 금액 · 카톡 확인), 역할 필터, 2인/3인 기준, 루틴 편집, 기록 통계, 앱 열려 있을 때 중요 업무 알림
- 기능 2. **직원** — 직원 명단(고용 형태 · 고정 휴무 · 기본 구간), 월간 근무표(6구간 × 요일별 필요 인원, 충족/부족, 이전 달 복사, 공휴일, 변경 이력, 인쇄), 전자 근로계약서(6단계 · 서명 · 확인번호 · PDF · 교부)
- 기능 3. **운영** — 공지사항 필독(룰), 수조 관리표(배지 · 먼저 사용 ① · 기록표), 이슈 노트, 월간 공지, 레시피, 원가 관리(매입 → 원가율)
- 기능 4. **기반** — 매장 전환(안산 · 안양), `?view=` 바로가기, 백업 내보내기/가져오기

### 오늘 새로 만드는 것 — 회계 (만드는 순서대로)

- 기능 5. **매출 입력** — 마감 루틴 완료 창 확장(총주문 · 매장/배달/포장 매출 · 품종별 kg · 주류). 회계 › 매출 입력 화면에서 날짜별 표 보기 · 수정 · 미입력 날 표시. **CSV 가져오기**(`sales_daily.csv` 열 이름 그대로)
- 기능 6. **매출 분석** — 기간(이번 달 · 지난 달 · 최근 90일 · 직접 지정), 카드 4개, 일별 막대, 요일별 평균, 채널 비중, 품종별 kg. 매장별로 따로
- 기능 7. **월 손익** — 매출 − 원가 − 인건비 − 고정비. 설정에 고정비(임대료 · 공과금 · 보험 · 기타, 적용 시작 월). 원가율 · 인건비율 경고, 지난달 비교
- 기능 8. **인건비 계산** — 직원 명단에 급여 형태(시급/월급) · 금액 추가. 근무표 구간 시간 합산 → 기본급, 주 15시간 이상 주휴수당, 4대보험 사업주 부담 어림(비율 설정, 기본 10%). "이달 급여 확정"은 사장님만
- 만드는 순서: 5 → 6 → 7 → 8. 오늘 안에 끝나지 않은 것은 `제출서.md`의 "아직 안 되는 것"에 적고 10/2까지 마무리한다

### 오후에 앞당겨 추가한 것 (사장님 요청)

- 기능 9. **급여명세서** — 확정 인건비로 직원별 임금명세서(지급·공제·실지급·계산 방법). 보기·인쇄/PDF, "이메일로 보내기"(직원 주소·제목·본문이 채워진 메일 앱이 열림), 발송 완료 기록. 소득세 직접 입력, 4대보험 근로자 요율은 설정. **자동 발송은 v2(서버)**
- 기능 10. **보건증 관리** — 직원별 발급일 → 만료일·상태, 유효기간 설정. 만료 30일·7일 전 할 일 화면 배너, 근무 배치 창에 만료 경고
- 기능 11. **위생교육 일정관리** — 영업자 위생교육 이수일·주기·교육기관 → 다음 기한, 직원 위생교육(선택). 30일·7일 전 배너
- 기능 12. **트러블시트** — 이슈 노트 이름 변경. 두 매장 공용 문서로 옮겨 안산·안양이 같은 목록을 보고 매장 이름 필터
- 기능 13. **갑각류 매입 인사이트** (운영) — 원가 관리 매입 기록(CSV 가져오기 포함)으로 품종별 kg당 단가 흐름, 설·추석·가정의달·연말 앞 8주 패턴, 다음 일정별 권장 매입 구간(보관 가능 일수 안에서 가장 쌌던 주)·필요량·절감액. 예측이 아니라 과거 2년 평균

- **이번에 하지 않을 것:**
  - 사장님 폰 즉시 알림(텔레그램 서버) · 기기 간 동기화 · 공용 비밀번호 → v2
  - 급여명세서 **자동** 이메일 발송, 보건증·위생교육 **텔레그램** 알림 → v2 (화면과 기록은 v1에 있음)
  - 법령 변경 소식 → v2
  - POS · 배민 매출 자동 가져오기, 세무 자료 내보내기, 두 매장 통합 대시보드, 출퇴근 기록, 사진 저장 → 나중
  - 새 디자인 · 메뉴 대청소 — 기존 앱 구조(대카테고리 › 하위 메뉴)에 "회계" 대카테고리 하나만 추가한다

## 6. 완성됐다는 걸 어떻게 확인하나요?

가짜 데이터로 시연한다.

- **시연할 예시 입력:**
  1. 안양점, 9월 14 · 15 · 16일 매출을 총매출 2,000,000 / 2,500,000 / 1,500,000원, 총주문 10 / 12 / 8, 대게 15 / 20 / 10kg으로 입력 (14일은 마감 루틴 완료 창에서, 15 · 16일은 매출 입력 화면에서)
  2. 매입 2건: 대게 900,000원, 식자재 100,000원
  3. 직원 2명(가짜 이름) 시급 10,320원, 근무표 9월 셋째 주 각 5일 × 8시간
  4. 설정 › 고정비: 임대료 2,500,000원 (2026-09부터)
  5. `sales_daily.csv` 형식 파일 1개 가져오기 (2025-08~2026-08, 가짜 값)
- **기대하는 결과:**
  - 매출 분석 "이번 달": 총매출 6,000,000원 · 일평균 2,000,000원 · 객단가 200,000원 · 총 kg 45. 일별 막대 3개, 나머지 날은 미입력으로 비어 있음
  - "최근 90일"을 고르면 CSV로 가져온 날들이 포함되어 막대가 늘어남
  - 월 손익 9월: 매출 6,000,000 · 원가 1,000,000 (16.7%) · 인건비 예상 1,089,792 (직원당 기본급 412,800 + 주휴 82,560 + 4대보험 49,536) · 고정비 2,500,000 · **남는 돈 1,410,208원**. 손으로 계산한 값과 같음
  - 인건비 화면에서 "이달 급여 확정" → 손익의 "예상" 표시가 "확정"으로 바뀜
- **잘못 입력했을 때:**
  - 같은 날짜를 다시 입력 → "이미 있어요. 덮어쓸까요?" 확인창. 취소하면 그대로
  - kg에 `-3`이나 `열`을 넣음 → 칸이 붉어지고 저장 안 됨
  - 열 이름이 다른 CSV → "총매출 열이 없어요" 안내, 한 줄도 안 들어감
  - 근무표 없는 8월의 인건비 → "근무표 없음", 손익에 0원으로 넣지 않음
  - 시급 9,000원 → 최저임금 경고(붉은 글씨)
- **다시 열었을 때 남아 있어야 할 것:**
  - 위 매출 3건 · 매입 2건 · 고정비 · 급여 기준 · 확정 상태 · CSV로 가져온 기록 전부 (브라우저 저장). 백업 내보내기 파일에도 포함됨

## 7. 다음 버전에서 더할 것 (v2: API·외부 데이터 등)

- 다음에 추가할 기능 하나: **급여명세서 자동 발송** — v1에서 확정한 인건비로 직원별 PDF를 만들어 이메일로 보내고 발송 기록을 남김
- 필요한 데이터나 외부 연결: Supabase(저장 · 동기화 · 서버 함수 · cron), Cloudflare Pages(호스팅), 텔레그램 Bot API(즉시 알림 · 요약 · 보건증/위생교육/법령 알림), 이메일 발송 서비스(명세서), 국가법령정보센터 Open API(법령 변경 소식). 직원 명단에 이메일 · 보건증 발급일, 사업장 정보에 위생교육 이수일
- 사람이 직접 판단 · 확인해야 할 부분: 급여 확정과 발송 버튼, 법령 소식이 우리 가게에 어떻게 적용되는지 해석, 즉시 알림 범위 조정

## 8. 절대 자동화하면 안 되는 것

- **급여 확정** — 앱은 예상까지만. 확정은 사장님 버튼
- **근로계약서 서명 · 날인** — 근로자 본인이 화면에서. 서명 뒤 내용 잠금
- **이미 입력한 매출을 앱이 스스로 바꾸는 것** — 사람이 고치고 이력에 남김
- **직원 삭제 · 계약서 무효 처리** — 사유 입력 + 확인 두 번
- **손님에게 가는 메시지** — 이 앱은 손님에게 아무것도 보내지 않음
