# 서버(Supabase) 연결 — 실시간 동기화

매장 아이패드 · 사장님 폰 · PC가 같은 기록을 보게 하는 v2 1단계. 한 번만 하면 됩니다.

## 사장님이 하는 것 (10분)

1. https://supabase.com → **Sign in with GitHub** → **New project**: 이름 `haemonic`, Region **Northeast Asia (Seoul)**, DB 비밀번호는 아무거나 정해 메모.
2. 만들어지면 왼쪽 **SQL Editor** → **New query** → `supabase.sql` 내용을 통째로 붙여넣고 **Run**. "Success" 가 뜨면 끝.
3. **Authentication → Users → Add user → Create new user**: 매장 공용 로그인 (이메일 아무거나, 비밀번호 정하기). **Auto Confirm User** 체크.
4. **Project Settings → API** 에서 **Project URL** 과 **anon public** 키 복사.

## 기기마다 하는 것 (2분)

앱 → 설정 → **서버 연결** 에 Project URL 과 anon 키를 붙여넣고 → **로그인** → 3번에서 만든 이메일·비밀번호 입력.
처음 연결하는 기기의 기록이 서버에 올라가고, 그 뒤 연결하는 기기는 서버 기록을 받아 옵니다.
**기록이 있는 기기(매장 아이패드)를 가장 먼저 연결하세요.**

## 알아둘 것

- anon 키는 공개용 키입니다. 진짜 비밀인 `service_role` 키는 어디에도 넣지 않습니다.
- 열쇠는 각 기기 브라우저에만 저장됩니다(코드·GitHub 에 없음).
- 인터넷이 끊기면 기기 안에 저장했다가 연결되면 올립니다. 같은 문서를 두 기기가 동시에 고치면 나중 저장이 이깁니다.
- 무료 구간: 500MB DB · 월 5GB 전송 — 두 매장 규모면 충분합니다.

## 기기를 처음 연결할 때 기록은 어떻게 되나

- 서버가 비어 있으면: 이 기기의 기록이 그대로 올라갑니다.
- 서버에도 기록이 있고 이 기기에도 기록이 있으면: **양쪽을 합칩니다.** 날짜별 체크 기록·매입·매출·직원·계약서·레시피 목록은 합집합, 같은 날 같은 항목은 진행된 쪽을 남깁니다.
- 그 뒤부터는 더 최근에 저장한 쪽이 이깁니다 (보통 실시간이라 차이가 없습니다).
- 그래도 연결 직전에 설정 › 백업 › 파일로 내보내기를 한 번 해 두면 안전합니다.

## 알림을 서버가 보내게 하기 (한 번만)

앱 설정에 텔레그램 봇 토큰·대화방이 들어 있고 서버에 로그인되어 있으면, `supabase_alerts.sql` 을 설치한 뒤부터는 알림을 서버가 보냅니다.

1. Supabase › SQL Editor › New query
2. `서버/supabase_alerts.sql` 내용을 통째로 붙여 넣고 Run (마지막 줄이 오늘 리포트 미리 보기로 나오면 성공)
3. 앱 설정 › 연결 테스트 → 휴대폰에 2통(기기에서 1통, 서버에서 1통)이 오면 끝

되는 것
- 중요 업무 완료·지연 → 사장님 폰에 즉시 한 줄 (설정에서 끌 수 있음)
- 공지·트러블 등록 → 텔레그램 방 (전과 같음, 서버 경유)
- 매일 21:30 마감 리포트 → 매장 PC가 꺼져 있어도 서버가 보냄. 실패하면 1분마다 3회 재시도
- 보낸 기록은 Table Editor › events 표에서 볼 수 있음 (sent_at 비어 있고 err 있으면 실패)

주의
- 서버 리포트 시각은 21:30 고정입니다 (앱 설정의 시각은 서버 미로그인일 때만 씀). 바꾸려면 SQL 의 `30 12 * * *`(UTC) 를 고칩니다.
- 봇 토큰은 앱 설정에 저장된 값을 서버가 읽습니다. SQL 에 토큰을 적을 필요가 없습니다.
