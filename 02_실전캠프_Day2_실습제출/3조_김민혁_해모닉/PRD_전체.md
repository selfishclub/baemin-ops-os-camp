## 1. 배경 — 최근 실제로 있었던 한 장면

- 장면: 9월 초 어느 월요일 밤. 안양점 마감 후 사장님은 집에서 직원이 카톡으로 보낸 포스 마감 사진을 보고 엑셀 `26년 9월` 시트에 그날 총주문 · 매장/배달 매출 · 대게/킹크랩/랍스터 kg을 옮겨 적었다. 지난달 손익을 내려고 한 달치 매입 영수증 사진을 카톡에서 하나씩 찾아 더하고, 근무표를 보며 계산기로 직원 급여를 뽑았다. 세 시간 뒤 나온 숫자가 맞는지 확신이 없었다. 그 사이 "오늘 수조 해수 교체는 했어?"를 확인하려고 직원에게 전화를 걸어야 했다. 매장에 없으면 무엇이 됐고 무엇이 안 됐는지 알 방법이 없었다.
- 얼마나 자주: 매출 옮겨 적기는 **매일**, 손익 계산은 **월 1회**, "했어?" 전화는 **하루 2~3번**
- 한 번에 걸리는 시간: 매출 옮겨 적기 하루 10분, 월말 손익·급여 계산 약 3시간 (어림)
- 실수·빠뜨림: 한 달에 한두 번 매출 옮겨 적기 누락이나 오타, 주휴수당 계산 놓침, 수조 청소 주기 넘김, 사장님이 지시하지 않으면 빠지는 마감 업무

## 2. 쓰는 사람과 역할

| 누가 | 언제 여나 | 무엇을 보나 | 무엇을 누르나 | 어떤 기기로 |
|---|---|---|---|---|
| 사장 (1명, 두 매장) | 아침 출근 전, 낮에 수시로, 밤 21:30 요약 받을 때, 월말 | 진행률 · 지연 · 수조 상태 · 이슈 · 매출 추이 · 월 손익 · 인건비 | 룰·루틴·메모 수정, 근무표 편성, 고정비·급여 기준 입력, 급여 확정·명세서 발송, 근로계약서 날인 | 아이폰, 매장 방문 시 공용 PC·아이패드 |
| 직원 (홀 · 주방 · 갑각류 관리자, 매장당 2~3명) | 오픈 11:00 · 미들 15:00 · 마감 20:00 시간대마다 | 오늘 할 일, 수조 관리표, 공지 룰, 레시피 | 할 일 체크(이름 선택), 수조 칸 기록, 매입 입력, 마감 매출 입력, 이슈 등록 | 매장 PC 또는 아이패드 (공용) |
| 매니저 (안양점 1명) | 직원과 같음 | 직원과 같음 + 근무표 | 직원과 같음 + 갑각류 관리자 역할 | 공용 기기 |
| 신입 직원 | 첫 출근날 | 공지사항 필독 · 레시피 · 근로계약서 | 계약서 확인·서명, 할 일 체크 | 공용 기기 |

직원 개별 로그인은 두지 않는다. 공용 기기 + **체크할 때마다 이름을 고르는 방식**으로 "누가 했는지"를 남긴다.

## 3. 흐름 — 지금 vs 도구를 쓰면

| 단계 | 지금 (쓰는 앱·파일) | 도구를 쓰면 |
|---|---|---|
| 1. 시간대별 할 일 | 사장님이 구두·카톡으로 지시, 직원 기억에 의존 | 오픈·미들·마감 40개 루틴이 매일 자동 생성. 체크하면 `이름 · 시각`이 남음 |
| 2. 수조 관리 | 수첩·기억. 해수 교체·청소 주기를 넘김 | 수조 관리표에서 칸을 누르면 기록. 주기를 넘기면 노랑·빨강 배지, 먼저 쓸 칸 표시 |
| 3. 근무표 | 엑셀 만들어 카톡 전송 | 월간 근무표 달력. 구간별 필요 인원 대비 충족/부족 자동 판정, 이전 달 복사 |
| 4. 근로계약 | 종이 계약서 또는 외부 전자계약 사이트 | 앱 안에서 6단계 작성 → 근로자 화면 서명 → PDF 교부 |
| 5. 매출 기록 | 포스 사진 보고 엑셀 월별 시트에 옮겨 적음 | 마감 루틴 완료 창에서 직원이 바로 입력. 과거 엑셀은 CSV로 한 번에 가져오기 |
| 6. 원가(매입) | 영수증 모아 월말에 정리 | 입고 때마다 매입 입력. 월 원가율 자동 |
| 7. 손익 | 엑셀 + 계산기, 월말 3시간 | 매출 − 원가 − 인건비 − 고정비가 월 손익 화면에 자동 |
| 8. 급여 | 근무표 보고 계산기, 명세서는 카톡 문자 | 근무표에서 시간 합산 → 예상 인건비 → 사장님 확정 → 명세서 PDF 이메일 발송 |
| 9. 보건증·위생교육 | 기억에 의존, 만료 후 발견 | 발급일·이수일을 적어두면 30일 전·7일 전 알림 |
| 10. 바뀐 법령 | 뉴스에서 우연히 봄 | 정해 둔 법령이 개정되면 소식 화면과 텔레그램으로 알림 |
| 11. 사장님 확인 | "했어?" 전화 | 중요 업무 완료·지연·수조 위험이 즉시 텔레그램. 21:30 요약 1통 |

## 7. 예외 — 잘못 넣거나 평소와 다를 때

- 같은 날짜 매출을 두 번 넣으면 → "이미 있어요. 덮어쓸까요?" 확인. 덮어쓰면 이전 값은 변경 이력에 남김
- 매출·kg·금액에 음수나 글자를 넣으면 → 저장하지 않고 칸을 붉게 표시
- 매출 칸을 비워 두면 → 0이 아니라 "미입력". 분석에서 일평균 계산의 분모에서 뺌
- CSV 열 이름이 양식과 다르면 → "총매출, 대게kg 열이 없어요"처럼 없는 열을 알려주고 한 줄도 넣지 않음
- 근무표가 없는 달의 인건비 → "근무표 없음"으로 표시, 0원으로 손익에 넣지 않음
- 시급이 최저임금(설정값, 2026년 10,320원)보다 낮으면 → 붉은 경고. 저장은 되지만 계약서·명세서에 경고가 따라감
- 급여 확정 뒤 근무표를 고치면 → 확정본은 그대로 두고 "확정 후 근무표가 바뀌었어요. 다시 계산할까요?" 안내
- 고정비를 한 번도 안 넣은 달의 손익 → 고정비 0이 아니라 "고정비 미설정"으로 표시
- 수조 해수 교체·청소 주기를 넘기면 → 노랑(지남) · 빨강(많이 지남) 배지, 빨강은 할 일 맨 위 알림
- 근로계약서에서 퇴근 시각이 출근보다 빠르면 → 저장하지 않고 안내. 서명 뒤에는 내용 수정 불가
- 브라우저 저장이 막힌 환경(파일로 직접 열었을 때 일부 브라우저) → 맨 위 붉은 경고 "기록이 저장되지 않아요"
- (v2) 이메일이 없는 직원의 명세서 → 발송 버튼 대신 "PDF 내려받기"만
- (v2) 이메일 발송 실패 → 3회 재시도 후 설정 화면에 실패 기록, 사장님 텔레그램에 알림
- (v2) 법령 API 응답 없음 → 소식 화면에 "마지막 확인 ○월 ○일 · 오늘 확인 실패". 옛 목록은 그대로
- (v2) 인터넷 끊김 → 기기 안 저장으로 계속 동작, 연결되면 서버와 맞춤. 21:30 요약은 서버가 보내므로 매장 PC가 꺼져 있어도 나감

## 8. 사람이 꼭 직접 해야 하는 것 (자동화 금지)

- **급여 확정**: 앱은 "예상"까지만 계산한다. 확정 버튼은 사장님만 누른다
- **급여명세서 발송**: 확정 후 사장님이 발송 버튼을 눌러야 나간다. 자동 발송·예약 발송 없음
- **근로계약서 서명·날인**: 근로자 본인이 화면에서 서명. 대표자 도장은 등록해 두되, 날인은 근로자 서명이라는 사람의 행위에 이어서만 찍힘
- **매출 확정값 수정**: 이미 입력한 매출을 앱이 스스로 바꾸지 않는다. 사람이 고치면 이력에 남김
- **직원 삭제·계약서 무효 처리**: 사유 입력 + 확인 두 번
- **법령 소식의 해석**: 앱은 "바뀌었다"와 원문 링크까지만. "우리 가게에 어떻게 적용된다"는 판단은 사장님(필요하면 세무사·노무사)
- **손님에게 가는 메시지**: 이 ERP는 손님에게 아무것도 보내지 않는다
- **텔레그램 즉시 알림 범위 조정**: 알림을 늘리고 줄이는 건 사장님이 설정에서

## 9. 성공 기준 — 숫자로

- 지금: 매출 옮겨 적기 하루 10분 · 월말 손익·급여 계산 약 3시간 · 매출 기록 누락 월 1~2회 · "했어?" 전화 하루 2~3번 · 신입이 룰을 익히는 데 며칠
- 목표:
  - 매출 입력은 마감 루틴 안에서 **1분**, 월 손익은 월말에 **10분 안에 확인** (계산은 0분)
  - 매출 기록 누락 **월 0회** (미입력 날이 표에 보이므로)
  - 인건비 계산 실수 **0건** (주휴수당 자동)
  - 일일 할 일 완료율 **95% 이상**(휴식 제외), 중요 업무 지연 하루 1건 이하
  - 수조 빨강 **주 0회**
  - 사장님 확인 시간 하루 **5분** (v2: 즉시 알림 + 21:30 요약 1통)
  - 신입이 공지사항 필독을 **5분** 안에 읽고 시작
- 시연할 예시 입력 → 기대하는 결과 (가짜 데이터):
  1. 9월 14·15·16일 매출을 각각 총매출 2,000,000 / 2,500,000 / 1,500,000원, 총주문 10 / 12 / 8로 입력 → 매출 분석 "이번 달" 카드에 총매출 6,000,000원 · 일평균 2,000,000원 · 객단가 200,000원
  2. 매입 2건(대게 900,000원, 식자재 100,000원) 입력 → 월 손익 원가 1,000,000원, 원가율 16.7%
  3. 직원 2명, 시급 10,320원, 근무표 1주(각 5일 × 8시간 = 40시간) → 인건비 화면에 각 기본급 412,800원 + 주휴수당 82,560원 = 495,360원, 4대보험 어림 49,536원
  4. 고정비 임대료 2,500,000원 → 월 손익 남는 돈 = 6,000,000 − 1,000,000 − 1,089,792 − 2,500,000 = **1,410,208원**, 손으로 계산한 값과 일치
  5. 앱을 닫았다 다시 열어도 위 숫자가 그대로

## 11. 아직 정하지 못한 것

- 고정비 항목을 임대료 · 공과금 · 보험 · 기타 4개로 시작하는데, 매장별로 더 필요한 항목(카드 수수료, 배달 수수료 등)이 있는지
- 4대보험 사업주 부담 비율 기본값 10%가 적당한지 (세무사 확인 후 설정에서 조정)
- 주휴수당 계산 기준 — 주 15시간 이상 · 1주 소정근로시간 ÷ 40 × 8 × 시급 방식으로 시작
- 즉시 알림 범위 — 중요·지연·수조·이슈만(권장) vs 40건 전부
- 법령 감시 목록 7건으로 시작하는데, 추가할 법(주류 관련, 개인정보 보호법 등)이 있는지
- 보건증 유효기간 1년 기본값이 관할 보건소 기준과 맞는지
- 수조 실제 주기 — 해수 7일 / 청소 30일이 두 매장 다 맞는지, 매장별 수조 개수
- 도메인 — 카페24 구매 여부와 이름
- 텔레그램 21:30 요약에 "누가 몇 건" 포함 여부 — 개인 지목 부담 vs 관리 필요
- 급여명세서 발송 시점 — 확정 즉시 vs 지급일에
