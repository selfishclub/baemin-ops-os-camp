## 2. 만든 과정 — 다른 사장님이 따라 할 수 있게

1. 계획을 어떻게 고쳤나요?
   - v2 PRD는 "Cloudflare + 공용 비밀번호 + Supabase"였는데, 이미 쓰던 Vercel은 그대로 두고 **저장 층만 Supabase**로 바꿨습니다. 카페24 서버도 검토했지만 실시간 동기화·무료·관리 부담에서 Supabase가 맞았습니다.
   - 사용메모에서 "낮 2명·저녁 3명" 문제가 나와서, 계획에 없던 **오전·오후 조 근무표**를 알림보다 먼저 끝냈습니다.
   - 교육은 "영상 목록"에서 **코스 + 개인 미션**으로 방향을 바꿨습니다. 봤는지 확인하는 방법을 묻다가 퀴즈 대신 "적용할 것 한 줄"로 정했습니다.
2. 만든 순서 (세 줄 안팎):
   - 서버(Supabase 표·실시간·첫 연결 합치기) → 텔레그램 알림을 서버가 보내게(SQL·cron) → 두 매장 텔레그램 연결·전체 시험
   - 근무표 오전·오후 조 → 시간대별 인원 기준 → 할 일 순서 잠금·시각·이름 편집 → 매장별 업무 구분
   - 교육 세분화 → 학습 코스 → 재생 확인 + 개인 미션
3. **AI에게 한 말 중 결과를 크게 바꾼 것** (원문 그대로):
   > "웹에서 실시간으로 보는 형식으로 하고 싶어."
   > "낮에 2명, 저녁에 3명인 경우가 있는데 현재 작성한 건 낮에도 3명인 경우로 되어 있거든. 어떻게 하면 좋을까?"
   > "퀴즈 대신 '내일 매장에서 적용할 것 한 가지'를 한 줄 적기 … 직원별 월간미션 형태로 … 교육과 연계해서 개인미션이라는것 만들어줘"
4. 막혔다가 푼 것과 푼 방법:
   - 서버 로그인이 "비밀번호가 틀렸다"고만 나옴 → 원인은 비밀번호가 아니라 **브라우저가 외부 라이브러리(CDN)를 막은 것** → 라이브러리를 사이트 안(vendor/)에 포함
   - 텔레그램 "대화방 찾기"가 안 됨 → 봇 **프라이버시 모드** 때문에 단체방의 `/hello`가 봇에 안 감 → `/hello@봇이름`처럼 봇을 지목해 보내고, 찾기 자체를 서버 경유로
   - 서버 리포트 SQL이 "malformed array literal" 오류 → 문자열을 배열에 붙일 때 `array_append`로 명시
   - 안산점 토큰 칸에 Supabase 키를 잘못 붙여 넣어 "Not Found" → 두 값의 모양을 비교해 찾아냄
