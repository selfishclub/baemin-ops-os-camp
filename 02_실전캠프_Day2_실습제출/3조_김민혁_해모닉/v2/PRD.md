# 기획안(PRD) — 해모닉 운영 ERP · v2 (초안)

- 가게 / 이름: 해모닉 (안산점 · 안양점) / 김민혁
- 조 주제: 매출 분석 대시보드
- 이 버전의 목표 한 줄: **사장님이 매장에 없어도 폰으로 즉시 알고, 급여명세서 · 보건증 · 위생교육 · 바뀐 법령처럼 "잊으면 손해 보는 일"을 앱이 대신 챙기는 도구**

> 이 문서는 **초안**이다. v1을 10/2까지 써 보고 `v1/사용메모.md` · `중간점검_1002.md`를 반영해 다시 고친다.
> 전체 그림은 [`../PRD_전체.md`](../PRD_전체.md). 이 문서는 그중 **[v2]** 꼬리표만 다룬다.

## 1. 무엇을 왜 만들고 싶나요?

v1은 매장 안에서는 잘 돌지만 세 가지가 남는다.

1. **바깥으로 아무것도 못 보낸다.** 사장님이 매장에 없으면 중요 업무가 됐는지, 수조가 빨강인지 앱을 열어 봐야 안다. 21:30 요약도 매장 PC 탭이 열려 있어야 나간다.
2. **급여를 확정해도 명세서는 손으로.** 근로기준법상 임금명세서를 서면(이메일 포함)으로 줘야 하는데, 지금은 카톡 문자로 적어 보낸다.
3. **잊으면 과태료.** 직원 보건증 만료, 영업자 위생교육 기한, 최저임금 · 식품위생법 개정 같은 것을 뉴스나 기억에 기대고 있다.

v2는 **서버를 하나 세우고** 그 위에 즉시 알림 · 급여명세서 발송 · 알리미 · 법령 소식을 올린다.

## 2. 누가 언제 쓰나요?

| 누가 | 여는 순간 | 기기 |
|---|---|---|
| 사장님 | 텔레그램 알림이 올 때(즉시 · 21:30 요약 · 만료 예고 · 법령 개정), 월초에 급여명세서 발송할 때, 소식 화면 훑을 때 | 아이폰 |
| 직원 | v1과 같음. 급여명세서는 본인 이메일로 받음 | 공용 기기, 개인 이메일 |
| 매니저 | v1과 같음 | 공용 기기 |

## 3. 지금은 어떻게 하고 있나요?

| 일 | v1까지 |
|---|---|
| 사장님 확인 | 앱을 열어 보거나 전화. 21:30 요약은 매장 PC 탭이 열려 있을 때만 텔레그램 |
| 급여명세서 | 카톡 문자로 금액 적어 보냄. 발송 기록 없음 |
| 보건증 · 위생교육 | 기억. 만료 뒤에 알게 됨 |
| 법령 | 뉴스 · 지인 · 세무사가 알려 줄 때 |
| 기기 간 기록 | 기기마다 따로 저장(클라우드판은 claude.ai 계정 로그인 필요) |

## 4. 도구를 쓰면 어떤 일이 달라지나요?

- 직원이 11:43에 "갑각류 상태 확인"을 완료하면 **3초 안에** 사장님 폰에 `[안양점] ✅ 갑각류 상태 확인 — 김직원 11:43 · 폐사 킹크랩 1` 한 줄이 온다. 21:30에는 매장 PC가 꺼져 있어도 요약 1통이 온다.
- 월초에 사장님이 인건비 화면에서 "이달 급여 확정" → 직원 › 급여명세서에 직원별 PDF가 생김 → "발송"을 누르면 각자 이메일로 PDF가 가고 `누구 · 언제 · 어디로 · 성공/실패`가 남는다.
- 직원 보건증 발급일을 넣어 두면 만료 30일 전 · 7일 전에 할 일 화면 배너와 사장님 텔레그램에 뜬다. 위생교육도 같다.
- 식품위생법 시행규칙이 개정되면 다음 날 아침 소식 화면에 `제목 · 공포일 · 시행일 · 원문 링크`가 쌓이고 텔레그램에 한 줄 온다.
- 매장 PC · 아이패드 · 사장님 아이폰이 같은 기록을 본다. 로그인은 매장 공용 비밀번호 하나.

## 5. 이번 버전에서 만들 것

### 1단계 — 서버 세우기 (v2의 바닥)

- 기능 1. **Supabase 서버** — 매장별 문서 + 이벤트 로그를 Postgres에. `store.js`(저장 층)만 Supabase 클라이언트로 바꾸고 화면은 손대지 않음. 기기 간 실시간 동기화. 앱은 Cloudflare Pages에 올리고 첫 화면에 매장 공용 비밀번호
- 기능 2. **데이터 이전** — v1 백업 파일(JSON)을 그대로 적재. 하루 병행 후 v1을 읽기 전용으로

### 2단계 — 알림

- 기능 3. **사장님 폰 즉시 알림** — 완료/지연/수조 빨강/이슈 이벤트를 `events` 표에 쓰면 서버 함수가 텔레그램으로 전송. 즉시층은 하루 10~15건(중요 업무 9건 완료 · 중요 지연 · 수조 빨강 · 이슈 등록). 실패 시 3회 재시도
- 기능 4. **21:30 요약 cron** — 서버가 보냄. 완료율 · 미완료 · 폐사 합계 · 수조 상태

### 3단계 — 직원 확장

- 기능 5. **급여명세서 자동 발송** — v1에 이미 있는 명세서 화면의 "이메일로 보내기"(메일 앱 열기)를 서버 발송으로 교체. 직원별 PDF 생성. 항목: 성명 · 임금 총액 · 기본급 · 주휴수당 · (연장 · 야간 있으면) · 계산 방법(시간 × 시급) · 공제(4대보험 근로자 부담 · 소득세는 세무사 값 입력) · 실지급액 · 지급일. 직원 명단에 이메일 추가. "발송" 버튼 → 서버가 이메일 발송 서비스로 PDF 첨부 전송 → 발송 기록. 이메일 없는 직원은 PDF 내려받기만
- 기능 6. **보건증 알림** — v1 보건증 관리 화면의 배너 알림에 텔레그램 알림을 더함. 유효기간 기본 1년(설정 변경). 만료 30일 · 7일 전 배너 + 텔레그램. 만료자를 근무표에 배치하면 경고. 만료 후에는 붉은 표시
- 기능 7. **위생교육 알림** — v1 위생교육 일정관리 화면에 텔레그램 알림을 더함. 매년 1회 기준으로 다음 기한 계산. 30일 · 7일 전 알림. 직원 위생교육도 같은 표에 넣을 수 있게(선택)

### 4단계 — 법령 소식

- 기능 8. **법령 변경 소식** — 국가법령정보센터 Open API(인증키는 서버에만). 감시 목록 기본 7건: 식품위생법 · 식품위생법 시행령 · 식품위생법 시행규칙 · 근로기준법 · 최저임금법 · 소상공인 보호 및 지원에 관한 법률 · 부가가치세법 (설정에서 추가/삭제). 서버가 매일 06:00 조회 → 새 개정이 있으면 소식 표에 저장 → 텔레그램 한 줄(`📜 식품위생법 시행규칙 개정 · 시행 2026-11-21 · 링크`). 소식 화면: 목록 · 읽음 표시 · 마지막 확인 시각. **AI 요약은 하지 않는다** — 제목 · 날짜 · 원문 링크까지만

- **이번에 하지 않을 것:**
  - POS · 배민 매출 자동 가져오기 · 세무 자료 내보내기 · 두 매장 통합 대시보드 · 출퇴근 기록 · 사진 저장 → 나중
  - 직원 개별 로그인 · 권한 → 하지 않음(공용 비밀번호 + 체크 시 이름 선택 유지)
  - 뉴스 · 블로그 수집, 법령 AI 요약 → 하지 않음(사장님 결정: 정부 공식 소스만)
  - 카카오톡 발송 → 하지 않음(개인 앱 자동 발송 불가, 알림톡은 건당 과금)

## 6. 완성됐다는 걸 어떻게 확인하나요?

가짜 데이터로 시연한다.

- **시연할 예시 입력:**
  1. 매장 PC에서 "갑각류 상태 확인" 완료(이름 김직원, 폐사 킹크랩 1)
  2. 아이폰에서 같은 앱을 열어 봄
  3. 직원 2명(가짜 이름, 테스트용 이메일 `test1@example.com`, `test2@example.com`) 9월 급여 확정 → 급여명세서 › 발송
  4. 직원 1명 보건증 발급일을 11개월 전으로 입력
  5. 법령 감시 목록에 최근 개정된 법을 1개 넣고 "지금 확인"
  6. 매장 PC를 끄고 21:30을 지나 봄
- **기대하는 결과:**
  1. 3초 안에 사장님 텔레그램에 `[안양점] ✅ 갑각류 상태 확인 — 김직원 11:43 · 폐사 킹크랩 1`
  2. 아이폰 할 일 화면에 그 항목이 완료로 보임(새로고침 없이)
  3. PDF 2장 생성, 두 테스트 이메일에 첨부 도착, 발송 기록 2줄 "성공"
  4. 할 일 화면 맨 위에 `보건증 만료 30일 전 · 박직원` 배너, 사장님 텔레그램 1통
  5. 소식 화면에 1건 이상(제목 · 공포일 · 시행일 · 링크), 텔레그램 1통
  6. 21:30 요약이 텔레그램에 도착
- **잘못 입력했을 때:**
  - 이메일이 틀린 직원 → 발송 실패, 3회 재시도 후 설정에 실패 기록 + 사장님 텔레그램
  - 이메일 없는 직원 → 발송 버튼 없음, PDF 내려받기만
  - 법령 API 응답 없음 → 소식 화면에 "마지막 확인 09-30 · 오늘 확인 실패", 옛 목록 그대로
  - 인터넷 끊김 → 기기 안 저장으로 계속, 연결되면 서버와 맞춤
  - 공용 비밀번호 5회 틀림 → 10분 잠금
- **다시 열었을 때 남아 있어야 할 것:**
  - 모든 기록이 서버에 있어 어느 기기에서 열어도 같음. 발송 기록 · 읽음 표시 · 알림 실패 기록 포함

- 사람이 직접 판단 · 확인해야 할 부분: 자동으로 가져온 매출이 포스와 맞는지 마감 때 한 번 확인

## 8. 절대 자동화하면 안 되는 것

- **급여 확정 · 명세서 발송 버튼** — 예약 발송 · 자동 발송 없음
- **법령 소식의 해석** — 앱은 "바뀌었다"와 원문 링크까지. 적용 판단은 사장님(필요하면 세무사 · 노무사)
- **근로계약서 서명 · 날인** — 근로자 본인
- **직원 삭제 · 매출 수정** — 사람이, 이력에 남김
- **손님에게 가는 메시지** — 없음
- **즉시 알림 범위 조정** — 사장님이 설정에서
