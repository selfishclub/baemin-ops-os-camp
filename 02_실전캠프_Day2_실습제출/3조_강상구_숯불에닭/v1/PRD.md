# 기획안(PRD) — 숯불에닭 한눈 손익 장부 · v1

- 가게 / 이름: 숯불에닭 / 강상구
- 조 주제: 날씨 기반 가게 운영 준비
- 이 버전의 목표 한 줄: 사장님이 매달 초 정산할 때, 은행 거래내역 엑셀을 올리고 배달앱별 실매출을 넣으면 임대료·수수료까지 들어간 "이번 달 실제로 남은 돈"을 한 장으로 보는 도구

> 전체 그림은 [`../PRD_전체.md`](../PRD_전체.md)에 있습니다. 이 문서는 그중 **[v1] 꼬리표가 붙은 것만** 옮긴 것입니다.
> 핵심 흐름 한 줄: 은행 엑셀 올리기 + 앱별 실매출 입력 → 자동 분류된 손익 한 장 → 마감 버튼으로 월별 저장.

## 1. 무엇을 왜 만들고 싶나요?

매달 초 지난달 정산을 할 때, 은행에서 내려받은 거래내역 엑셀을 **한 줄씩 보며 분류**하고 따로 만든 정리용 엑셀에 거래처별 금액을 **손으로 옮겨 적는다.** 한 번에 1~2시간이 걸리고, 거의 매달 1~2건의 실수(분류 잘못, 통장에 안 보이는 지출 누락, 옮겨 적다 틀림)를 나중에 발견한다. 틀렸는지 확인할 기준도 없다.

배달 매출은 통장에 들어온 돈(수수료가 빠진 금액)으로만 적어서, 배달앱 4곳의 **실매출 대비 수수료가 얼마인지 집계가 안 된다.** 지금 쓰는 엑셀의 손익계산서는 수식에서 임대료 합계가 빠져 있어 영업이익이 실제보다 크게 나오고 있었다.

## 2. 누가 언제 쓰나요?

사장님 혼자 쓴다. 직원은 보지 않는다.

- 매달 초 정산할 때: PC에서 은행 엑셀 올리기 → 분류 확인 → 앱별 실매출 입력 → 마감
- 수시로: 폰에서 이번 달 손익 한 장 확인

(가게: 청주율량점 1곳. 화덕 2명(사장님 + 시급제 1명) · 주방 1명(월급제) · 홀 알바 1~2명(시급제))

## 3. 지금은 어떻게 하고 있나요?

1. 은행 사이트에서 통장 거래내역을 엑셀로 내려받는다.
2. 엑셀에서 한 줄씩 보며 대분류·소분류를 머릿속으로 나눈다. (제일 오래 걸림)
3. 정리용 엑셀(월별 금전출납부 시트)의 거래처별 줄에 금액을 손으로 옮겨 적는다.
4. 홀 매출은 포스에 찍힌 숫자, 배달 매출은 통장 입금액으로 적는다. 나간 돈도 전부 통장 내역으로 본다.
5. 손익계산서 시트가 수식으로 합산한다. (임대료 누락, 새 달 시트는 수식을 손으로 이어야 함)

쓰는 것: 은행 사이트, 엑셀 파일 2개(내려받은 거래내역 · 정리용), 포스.

## 4. 도구를 쓰면 어떤 일이 달라지나요?

한 달 치 기준: **은행 거래내역 엑셀 1개 + 채널 5곳(홀·배달앱 4곳)의 월 주문금액·정산금액·건수**(주문이 발생한 달 기준)를 넣으면 →

- 거래처 이름 규칙으로 자동 분류되고, 처음 보는 거래처·큰 금액·애매한 줄만 "확인 필요"로 모여 나온다. 한 번 고르면 다음 달부터 기억한다.
- **손익 한 장**이 나온다: 총매출(홀/배달) → 매출원가 → 가맹수수료 → 영업비·임대료·세금과공과·노무관리비 → 영업이익. 항목마다 매출 대비 %, 지난달 대비. 생활비는 가게 비용에서 빼고 "내가 가져간 돈"으로 따로.
- **앱별 수수료액·수수료율(%) 비교표**가 나오고, 통장 입금(입금일 기준)은 따로 맞춰 봐서 들어와야 할 돈과 다르면 표시된다.
- "이번 달 마감"을 누르면 월별로 저장되어 폰에서 언제든 다시 본다.

옮겨 적기와 수식 관리가 없어진다.

## 5. v1에서 만들 것 — 오늘(9/17) 안에 되는 것만

- 기능 1: **은행 엑셀 올리기 + 자동 분류** — 거래처 이름 규칙으로 대분류·소분류 지정. 분류 체계는 지금 엑셀의 8개 대분류(수입·가맹수수료·매출원가·영업비·임대료·세금과공과·노무관리비·기타)와 소분류를 그대로. "확인 필요" 줄만 직접 고르고, 고른 것은 규칙으로 저장. 쌓인 규칙을 보는 목록 화면 포함.
- 기능 2: **이번 달 손익 한 장** (폰에서 잘 보이게) — 임대료 포함 영업이익·이익률, 대분류별 금액과 매출 대비 %, 지난달 대비, 생활비 따로, 마감 여부.
- 기능 3: **배달앱별 실매출 입력 + 수수료율 비교** — 채널 5곳의 월 주문금액·정산금액·건수 입력 → 앱별 수수료액·수수료율. 채널 이름은 고칠 수 있게.
  - **기준은 "주문이 발생한 달"**: 정산금액 = 그 달 주문분에서 수수료를 빼고 받을(받은) 돈. 다음 달 초에 입금되는 월말 주문분도 포함. 입금된 날 기준이 아니다.
  - 통장 입금은 따로 맞춰 본다: 지난달 말 미입금액 + 이 달 정산금액 − 이 달 말 미입금액(선택 입력) = 들어와야 할 돈. 통장과 다르면 빨간색, 월말 미입금액을 안 넣었으면 회색 "시차 포함".
  - 비용은 통장에서 돈이 나간 날 기준(지금 엑셀과 같음). 화면에 기준을 적어 둔다.
- 기능 4: **통장에 안 보이는 지출 직접 추가** — 날짜·대분류·소분류·사용내역·금액 한 줄 입력.
- 기능 5: **월 마감 버튼 + 저장** — 데이터 창고(Supabase)에 월별 저장. 마감 뒤 수정하면 기록을 남김. 같은 기간 파일을 또 올리면 막음.
- **이번에 하지 않을 것:**
  - [v2] 오늘 마감 입력(일별 채널 매출 + 시급제 직원 인별 근무시간·인건비율), 월중 누적·예상 손익과 고정비 등록, 월별 추이 그래프, 배달앱 정산 파일 올리기, 세금 대비 미리 보기, 세무사용 엑셀 내보내기, 날씨 자동 붙이기, 알림
  - [나중] 은행·카드 자동 가져오기, 포스 연결, 배달앱 자동 연결, 세무사 자동 전달, 출퇴근 기록·급여명세서
  - 로그인·직원 권한 나누기 (사장님 혼자 쓴다)

## 6. 완성됐다는 걸 어떻게 확인하나요?

- 시연할 예시 입력: 가짜 은행 거래내역 엑셀 한 달 치(약 60줄, 가짜 거래처 이름) + 채널 5곳의 가짜 월 실매출(예: 배민 주문금액 9,000,000 · 정산금액 7,650,000 · 300건 · 월말 미입금액 450,000)
- 기대하는 결과: 60줄 중 50줄 이상 자동 분류, 나머지는 "확인 필요"로 표시 → 3줄을 직접 고르면 규칙으로 저장됨 → 손익 한 장에 총매출, 대분류별 금액·%, **임대료가 들어간** 영업이익·이익률이 나옴 → 앱별 수수료율 4개가 한 표에 보임(예: 배민 15.0%) → 마감 버튼을 누르면 "마감됨"으로 바뀜
- 잘못 입력했을 때:
  - 같은 기간 파일을 또 올리면 → "이미 올린 기간이에요", 중복 저장 안 함
  - 은행 거래내역 모양이 아닌 파일 → 저장하지 않고 "날짜·내용·금액 열을 찾지 못했어요"
  - 평소의 10배인 매출, 주문금액보다 큰 정산금액, 정산금액보다 큰 월말 미입금액, 0이나 음수 금액 → 저장 전에 "맞나요?"
  - 통장 입금이 "들어와야 할 돈"과 다르면 → 차이를 빨간색으로 표시 (막지는 않음). 월말 미입금액을 안 넣었으면 회색 "시차 포함"
  - "확인 필요" 줄이 남은 채 마감을 누르면 → 한 번 더 알림
- 다시 열었을 때 남아 있어야 할 것: 분류된 거래 줄, 분류 규칙, 채널별 실매출, 직접 추가한 지출, 월 마감 기록(마감일·이후 수정), 올린 파일의 기간

## 7. v2에서 더할 것 (10/14까지 · API·외부 데이터 등)

- 그다음 순서: **정산 주기 규칙으로 입금 짝 맞추기** — 카드사·배달앱별 입금 날짜 규칙을 등록해 월말 미입금액을 자동 계산하고 실제 수수료율을 추정 (일별 매출이 있어야 가능)
- 다음에 추가할 기능 하나: **오늘 마감 입력** — 매일 마감 때 채널별 매출 5칸 + 시급제 직원(화덕A·홀A 같은 별칭) 근무시간 → 일별 인건비율, 빈 날 달력. 그다음은 배달앱 정산 파일 올리기.
- 필요한 데이터나 외부 연결 (API, 배민 데이터, 날씨 등): 배달앱 4곳의 정산 내역 파일(모양 확인 필요), 날씨 API(일별 날씨를 매출 옆에 붙여 조 주제 '날씨 기반 준비'로 이어 감), 알림 채널
- 사람이 직접 판단·확인해야 할 부분: 주휴수당·급여 확정, 세금 어림 계산 방식(세무사 확인), 애매한 거래 분류

## 8. 절대 자동화하면 안 되는 것

- 월 정산 확정(마감) 버튼 — 사장님이 눌러야 확정. 마감 뒤 수정은 기록이 남는다.
- 애매한 거래의 분류 — 처음 보는 거래처, 재료비/생활비가 갈리는 거래.
- 급여·주휴수당 확정, 세금 금액 확정 — 도구는 어림값과 "확인 필요"만.
- 세무사에게 파일 보내기 — 도구는 파일만 만든다.
- 데이터 삭제 — 한 달 치 지우기처럼 되돌릴 수 없는 일.
