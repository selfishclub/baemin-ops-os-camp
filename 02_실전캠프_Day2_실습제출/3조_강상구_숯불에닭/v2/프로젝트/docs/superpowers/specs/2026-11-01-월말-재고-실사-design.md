# 월말 재고 실사 (2026-11-01)

## 왜 만드나

10월 손익에서 매출이 9월보다 584만 적은데 영업이익이 거의 같았다. 원가율 탭을 보니 원인이 드러났다.

| | 9월 | 10월 |
| --- | --- | --- |
| 이론 원가율 (레시피) | 31.0% | 31.0% |
| 실제 원가율 (매입) | 37.1% | 31.5% |
| 차이 | +6.1%p (+2,687,131원) | +0.5%p (+205,899원) |

레시피대로 썼다면 두 달 다 31.0%인데, 9월만 269만을 더 샀다. 품목별로 보면 전부 보관되는 것이다 —
소스 142만, 냉동 원육·닭발 110만, 비장탄·참나무숯 23만, 후레쉬 박스·김가루 40만. 9월에 쌓고 10월에
쓴 것으로 보이지만, 재고를 세지 않으니 **추측에서 멈춘다.** 로스(폐기·과사용)였을 수도 있고, 둘은 대응이
완전히 다르다.

지금 원가율 탭은 이 셋을 나누지 못한다고 스스로 적어 두고 있다: "① 시세 ② 로스 ③ 재고 — 다음 버전에서
입고·실사를 붙이면 셋을 나눠 보여 드려요."

## 무엇을 만드나

월말에 품목별 수량을 한 번 적으면 그 달 재고 금액이 나오고, 거기서 세 숫자가 따라 나온다.

- **재고 반영 원가** = 매입 + 전월말 재고 − 당월말 재고
- **재고 늘고 줄은 것** = 당월말 − 전월말 (쌓았나 꺼내 썼나)
- **로스** = 재고 반영 원가 − 레시피 이론 사용량

## 정한 것

1. **손익은 안 건드린다.** 손익 탭의 매출원가는 세무사 장부와 같은 매입 기준으로 둔다. 재고 반영 원가는
   원가율 탭에만 한 줄 더 보여 준다. 실사를 한두 달 해 보고 믿을 만해지면 그때 손익으로 올린다.
   (첫 달은 전월말 재고가 없어 보정 자체가 안 되는 것도 이유다.)
2. **셀 품목은 사장님이 고른다.** 품목마다 「월말에 세는 품목」 스위치를 둔다. 금액 큰 것·보관되는 것을
   한 번에 켜는 버튼을 주고, 그 뒤엔 사장님이 넣고 뺀다. 매달 같은 목록이어야 달끼리 비교가 된다.
3. **박스 + 낱개 두 칸으로 센다.** "2박스 3kg"처럼 적으면 장부가 baseUnit으로 바꾼다. 1박스가 몇
   kg·몇 개인지는 최근 매입 영수증에서 자동으로 뽑는다 (`itemQty ÷ qty`: 찍어소스 "5팩(10kg)" 1박스
   = 10kg, 비장탄 5박스 45kg = 9kg, 양념안창살 2박스 20팩 = 10팩). 틀리면 고칠 수 있다.

## 데이터

`lib/costing/types.ts`

```ts
// Item 에 더하는 것
countable?: boolean; // 월말에 세는 품목인가
packSize?: number;   // 1박스가 baseUnit 몇 개인가. 없으면 최근 매입에서 짐작
packName?: string;   // 박스를 부르는 말 ("박스" 기본, "팩"·"포"·"판")

export interface StockCountLine {
  itemId: string;
  packs: number | null; // 박스 수
  units: number | null; // 낱개 (baseUnit)
}
export interface StockCount {
  month: string;     // "2026-10" — 그 달 말 재고
  countedOn: string; // 실제로 센 날
  lines: StockCountLine[];
  note?: string;
}
export const STOCK_KEY_PREFIX = "stock_count_"; // + month
```

`packs`와 `units`가 **둘 다 null인 줄은 "안 셌다"**로 본다. 0은 "세 봤는데 없다"다. 둘을 섞으면 안 센
품목이 재고 0으로 들어가 원가가 부풀어 보인다.

재고 금액은 수량 × 기준단가(`standardCost`)로 매긴다. **수율로 나누지 않는다** — 냉장고에 있는 것은
뼈·껍질을 발라내기 전 상태다. (레시피 원가만 `usableCost`로 수율을 반영한다.)

## 계산 — `lib/costing/stock.ts` (새로)

순수 함수 네 개. 저장소도 화면도 모르게 두고 테스트한다.

- `guessPackSizes(purchases)` → `Map<itemId, size>`. 가장 최근 매입 줄의 `itemQty ÷ qty`.
  1 이하는 박스 개념이 없는 것(낱개로 사는 것)이라 넣지 않는다.
- `countedQuantity(line, packSize)` → baseUnit 수량 또는 `null`(안 센 줄)
- `valueStock(count, items, packSizes)` → 합계·줄별 금액·센 품목 수·**셀 품목인데 안 센 것**
- `stockAdjustedCost({ purchased, opening, closing, revenue, theoretical })` → 위의 세 숫자

## 안 하는 것

- 재고 원장(입고·출고 건별). 출고를 포스 판매로 추정해야 해서 품이 몇 배인데 얻는 것은 위와 거의 같다.
- 손익·손익분기점·카톡 요약·세무사 엑셀 변경. 전부 매입 기준 그대로 둔다.
- 10월 원가 확정. 9/30 재고를 셀 기회가 지났다. 10/31을 세면 11월부터 정확해지고, 10월에 대해서는
  "냉동고가 평소보다 비었나"로 9월 269만의 성격(재고냐 로스냐)을 가늠하는 단서만 얻는다.
