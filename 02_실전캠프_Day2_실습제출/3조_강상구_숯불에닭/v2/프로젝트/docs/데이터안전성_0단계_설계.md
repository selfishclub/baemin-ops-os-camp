## 1. 기존 데이터의 위험 수준: **높음**

이유 세 가지.

1. **원본이 한 벌뿐.** 사장님 PC, 그 브라우저, 키 하나(`sootdak-ledger-v1`)에 거래·일별 매출·근무·정산 규칙·원가율 품목·고정비 설정까지 전부 들어 있습니다. 복사본은 사장님이 손으로 받은 백업 파일뿐입니다. **[확인: `lib/storage/local.ts` LocalData]**
2. **조용히 망가지는 길이 두 개.**
   - 저장된 글이 깨지면 `readLocal()` 이 빈 장부를 돌려주고, 그 뒤 첫 저장이 원본을 빈 장부로 덮어씁니다. **[확인: readLocal의 `catch { return emptyData() }` + update]**
   - 저장이 실패하면(용량 초과 등) `writeLocal()` 이 예외를 던지는데, 저장을 부르는 23곳 중 실패를 받아서 화면에 알리는 곳이 절반이 안 됩니다. 정산 탭·지출 입력·정산 규칙 저장은 받는 곳이 없어, 사장님은 저장된 줄 알고 넘어갑니다. **[확인: grep 결과. channels/page.tsx·ExpenseSection.tsx·useSettlement.ts 는 catch 0개]**
3. **복원이 묻지 않고 덮어씁니다.** 파일을 고르면 바로 `writeLocal()`. 미리보기·확인창·되돌리기가 없습니다. **[확인: `app/rules/page.tsx` restore, `lib/storage/backup.ts` importBackup]**

지금 당장 터질 확률은 낮지만, 터지면 전부 잃는 구조라 "높음"입니다.

## 3. 데이터 손상 방지 설계

### A. 저장 데이터를 못 읽을 때
현재: 빈 장부 반환 → 다음 저장 때 원본 덮어씀.
설계:

```
readLocal() → { ok: true, data } | { ok: false, raw: string, error: string }
```
- 파싱 실패 시 **원본 글(raw)을 그대로 들고** 실패를 돌려준다. 절대 `emptyData()` 로 바꾸지 않는다.
- `LocalStore` 는 실패 상태를 기억하고, **모든 쓰기 함수에서 `StorageDamagedError` 를 던진다.** 읽기 함수는 빈 배열을 돌려주되 화면에는 "손상" 띠가 뜬다.
- `AppShell` 의 모드 띠(초록 "내 PC 모드")가 **빨간 "저장소가 손상됐어요 — 입력이 잠겼어요"** 로 바뀌고 규칙 탭으로 안내한다. 띠는 모든 화면에 있으므로 어디서든 보인다.
- 규칙 탭에 두 버튼: **"손상된 원본 내려받기"**(raw 그대로 .txt 로 저장, 나중에 사람이 고칠 수 있게) · **"백업 파일로 복원"**(4절 절차).
- 원본 키는 복원이 성공하기 전까지 어떤 코드도 쓰지 않는다.
- 선택: 쓰기 직전에 `sootdak-ledger-v1.prev` 키에 **직전 상태 한 벌**을 복사해 두는 그림자 복사본. 깨졌을 때 한 번 되돌릴 여지가 생긴다. 대신 용량을 두 배 쓴다. 사용량이 한도의 40% 아래일 때만 켜는 것으로 제안. **[승인 필요]**

### B. 저장 공간 부족·쓰기 실패
현재: `setItem` 예외가 호출한 곳까지 올라가고, 받는 곳이 없으면 아무 일 없는 듯 보임.
설계:

- `writeLocal()` 안에서 `setItem` 을 try/catch. 실패하면 **`StorageFullError(현재 크기, 시도한 크기)`** 로 바꿔 던진다. 브라우저마다 다른 예외 이름(QuotaExceededError 등)을 여기서 한 번에 흡수한다.
- **쓰기 전 크기 계산**: 저장할 JSON 길이를 재서 경고선(한도 추정 5MB의 80%)을 넘으면 띠에 노란 경고 "저장 공간이 80% 찼어요. 백업 후 오래된 달 정리". 한도 자체는 브라우저가 안 알려 주므로 추정치임을 화면에 적는다.
- **실패를 한곳에서 받기**: 23곳을 모두 고치는 대신, `LocalStore.update()` 가 실패하면 `window.dispatchEvent(new CustomEvent("ledger:save-failed", { detail }))` 를 쏘고 `AppShell` 이 받아 빨간 토스트 "저장되지 않았어요 — 원인: 공간 부족(4.9MB/5MB)" 를 띄운다. 그러면 catch 가 없는 화면에서도 알림이 뜬다. 예외는 그대로 다시 던져 기존 catch 동작도 유지한다.
- 실패 시 **기존 데이터는 그대로**: `setItem` 은 실패하면 이전 값을 유지하므로 추가 조치 없이 보존된다. 그림자 복사본(A)을 켠 경우, 본 키 쓰기 실패 뒤 그림자 키를 지워 공간을 비우고 1회 재시도하는 것도 가능하나, 단순함을 위해 1차 범위에서는 뺀다.
- 규칙 탭에 **사용량 막대** (예: 1.3MB / 약 5MB).
- 진단용: 실패 이벤트 detail 에 크기·키·예외 이름만 넣는다. **장부 내용은 절대 넣지 않는다**(원칙 6).

### 사진(IndexedDB)
범위 밖이지만 한 줄: 백업에 안 들어가므로, 규칙 탭 백업 설명에 "사진은 포함되지 않아요" 문구를 추가하는 것만 제안한다.

## 4. 안전한 복원 기능 설계

새 흐름 (규칙 탭 "백업 불러오기"):

1. **파일 읽기 → 구조 검사** (`inspectBackup(text)` 새 함수, 아직 아무것도 쓰지 않음)
   - JSON 파싱 가능한가
   - `app === "sootdak-ledger"`
   - `version` 이 숫자이고 현재 앱이 아는 버전(1) 이하인가. 더 크면 "새 버전 파일이라 못 불러와요" 로 거절
   - `data` 안의 각 항목이 배열인가, 없는 항목은 빈 배열로 채울 것인지 표시
   - 날짜 꼴(`YYYY-MM-DD`)·금액이 숫자인지 표본 검사 (전수는 느릴 수 있어 앞 200줄)
2. **요약 표시** (모달)
   - 백업 저장 시각(savedAt), 거래 N건(첫 달~끝 달), 일별 매출 N일, 직원 N명, 설정 N개
   - **현재 장부**도 같은 항목으로 나란히: "현재 거래 N건 → 파일 거래 M건"
   - 파일 쪽이 현재보다 오래됐거나 적으면 **주황 경고** "현재보다 오래된 백업이에요. 그 뒤 입력이 사라져요"
3. **덮어쓰기 경고 + 명시적 확인**
   - 현재 장부가 비어 있지 않으면 입력칸에 **"복원"** 을 직접 쳐야 버튼이 켜진다.
   - 확인 전 **현재 상태를 자동으로 내려받는다** (`sootdak-ledger-before-restore-날짜.json`). 실수해도 한 단계 되돌릴 수 있다.
4. **쓰기**
   - 전체 JSON 문자열을 만든 뒤 `setItem` 한 번. 중간 상태가 없다(이미 그렇게 동작).
   - 실패(`StorageFullError` 등)하면 원본은 그대로이고 "복원되지 않았어요. 현재 장부는 그대로예요" 표시.
5. **취소**: 모달의 어느 단계에서든 닫으면 아무것도 바뀌지 않는다. 파일 input 값은 비운다(지금도 그렇게 함).

`importBackup()` 은 "검사"와 "쓰기"로 나눈다. 검사 함수는 순수 함수라 테스트하기 쉽다.

## 6. 운영·개발 환경 분리 방법

### 핵심 사실
브라우저 저장소는 **출처(origin) = 프로토콜 + 호스트 + 포트** 단위로 완전히 분리됩니다. `http://localhost:3200` 과 `http://localhost:3201` 은 서로의 localStorage 를 전혀 볼 수 없습니다. **[확인: 웹 표준 동작]** 따라서 **포트만 다르면 실제 데이터와 테스트 데이터가 섞일 수 없습니다.** 브라우저 프로필 분리는 추가 안전장치이지 필수는 아닙니다.

### 주의: 같은 폴더에서 dev 서버 두 개는 안 됩니다
Next.js dev 서버는 `.next` 폴더를 씁니다. 3200이 돌고 있는 이 폴더에서 3201을 또 띄우면 둘이 같은 `.next` 를 건드려 **운영 쪽(3200)이 깨질 수 있습니다.** 그래서 **별도 체크아웃**이 필요합니다.

### 구성
| 항목 | 운영 (지금) | 개발 |
|---|---|---|
| 폴더 | 이 폴더 | `git worktree add ../프로젝트-dev feature/data-safety` 로 만든 **형제 폴더** (같은 저장소, 다른 작업 폴더). `npm install` 따로 |
| 가지 | main | feature/data-safety |
| 포트 | 3200 | 3201 (`npx next dev -p 3201`) |
| 브라우저 | 사장님 평소 브라우저 | 같은 브라우저여도 포트가 달라 안전. 더 조심하려면 엣지/크롬 **다른 프로필** 또는 다른 브라우저 |
| 데이터 | 실제 | 오늘 탭 "가짜 예시 자료 넣기" · 올리기 탭 "가짜 9월 파일" · 원가율 탭 가짜 품목 (`lib/seed.ts`, `lib/sampleDaily.json`, `lib/costing/sample.json`) **[확인: 이미 있음]** |

- 개발 폴더에서는 **실제 백업 파일을 절대 열지 않습니다.** 가짜 백업만 씁니다.
- 3200 서버는 끝까지 건드리지 않습니다. 운영 반영은 main 에 합친 뒤 사장님이 평소처럼 3200 을 새로고침하는 것으로 끝납니다(dev 서버가 코드 변경을 자동 반영).
- 서버 측 백업(5절 3번)을 개발 폴더에서 시험할 때는 **다른 폴더** (`...\손익장부백업-테스트\`)로 보내게 환경변수로 구분합니다.
