## 2. 운영 폴더의 추적되지 않은 파일과 `.env.local` 보존

운영 앱 폴더(`v2/프로젝트`)의 git 이 무시하는 파일:

| 파일 | 용도 | 병합·revert 시 |
|---|---|---|
| `.env.local` | `VERCEL_OIDC_TOKEN` 1줄 (값 미열람) | **그대로 남음** (`.gitignore` 의 `.env.*`) |
| `.env.backup-for-migration` (9/30) | 내용 미열람 | 그대로 남음 |
| `.vercel/` | Vercel CLI 연결 정보 | 그대로 남음 |
| `next-env.d.ts`, `.next/`, `node_modules/`, `*.tsbuildinfo` | 생성물 | 그대로 남음 |

- `git merge`·`git revert`·`git checkout <커밋>` 은 **추적되는 파일만** 바꾼다. 위 파일은 건드리지 않는다.
- **절대 쓰지 않을 명령**: `git clean`(무시 파일까지 지울 수 있음), `git stash -u`, `git reset --hard` 뒤 `clean`.
- **[Claude]** 적용 직전 `.env.local` 을 같은 폴더 밖(`C:\Users\ksg39\Documents\손익장부백업\env.local.before-G.txt`)에 복사해 두고, 적용 후 `git status --ignored` 로 4개 파일이 그대로인지 확인. **[사장님]** 복사본 위치만 알고 계시면 됨.
- `BACKUP_DIR` 줄은 `.env.local` 에 **추가**만 한다(기존 줄 삭제·수정 없음).

## 3. 3200 서버 실행 방식과 변경 후 명령

**지금 (10/05 20:33 시작, PID 19012):**
```
바탕화면 "숯불에닭 장부 켜기.bat" (더블클릭)
 └ cd C:\Users\ksg39\claude-projects\baemin-1st\tools\ledger-v2   ← 운영 앱 폴더로 가는 정션(바로가기 폴더)
   └ npm run dev   →   package.json "dev": "next dev -p 3200"
```
- 바탕화면 bat 는 이미 켜져 있으면 브라우저만 열고, 아니면 15초 뒤 `http://localhost:3200/today` 를 열며 `npm run dev` 를 실행한다. **창을 닫으면 서버가 꺼진다**(bat 에 적혀 있음).
- 작업 스케줄러·시작 프로그램에 등록된 것은 **없다**. 즉 서버를 켜는 길은 이 bat 하나.
- 현재 바인딩: `0.0.0.0:3200` 과 `[::]:3200` (같은 와이파이의 다른 기기가 접속 가능).

**변경 후:** bat 파일은 그대로 두고 `package.json` 의 `dev` 만 바꾼다.
```
"dev": "next dev -H 127.0.0.1 -p 3200"
```
- `http://localhost:3200` 주소는 그대로 동작한다(localhost = 127.0.0.1).
- 이 한 줄 변경은 아직 가지에 **없다**. G 승인 시 가지에 커밋한 뒤 병합한다 **[Claude]**.
- 서버 재시작 절차 **[사장님]**: "Sootdak Ledger" 제목의 검은 창에서 Ctrl-C → `Y` → 창 닫기 → 바탕화면 bat 더블클릭. (Claude 가 대신 끄려면 PID 19012 와 부모 13284 를 종료해야 하는데, 사장님 창에서 끄는 쪽이 안전)
- 재시작 전후로 `netstat -ano | findstr :3200` 결과가 `127.0.0.1:3200` 하나만 남는지 확인 **[Claude]**.

## 9. 자동 백업 중복 누적·디스크 용량 주의

**(G-1 뒤 사장님 요청으로 가지에 반영한 용량 절약 — 커밋 전 테스트 459개 통과, 3201 에서 확인)**
- **브라우저**: 사진 ZIP 은 **사진을 추가·삭제한 날에만** 보낸다. 안 바뀌어도 **7일에 한 번**은 보험으로 전체를 보낸다(전엔 매일).
- **서버**: 받은 ZIP 의 사진 내용 해시(`contentHash`, 사진 id+바이트 해시를 정렬해 합친 것)가 직전 검증본과 같으면 **새 파일을 만들지 않고** manifest 가 직전 ZIP 파일을 가리킨다(`reusedFrom`). 카드의 용량 합계도 한 번만 센다. 직전 ZIP 을 사장님이 지웠으면 다시 저장한다.
- 그래서 실제로 쌓이는 건 "사진이 바뀐 날의 ZIP" 뿐이다. 영수증을 주 2회 찍는다면 사진 200장(60MB) 기준 한 달 약 0.5GB, 1년 약 6GB **[추정]**. 디스크 여유 337GB.
- 자동 백업은 여전히 **지우지 않는다.** 장부 JSON(수십 KB~수 MB)은 바뀔 때마다 쌓이지만 작다.
- **[사장님]** 정리 규칙 제안(반년마다): 백업 폴더에서 `photos-…zip` 은 **최근 5개 + 매달 1일 것**만 남기고 삭제. 단, 지우려는 ZIP 을 가리키는 manifest 가 그 뒤에도 있을 수 있으니(재사용), **가장 최근 manifest 가 가리키는 ZIP 은 반드시 남긴다** — 카드가 "마지막 사진 백업 성공" 으로 보여 주는 시각의 파일. 지우는 건 사람이 탐색기에서.
- 카드의 "백업 파일 N개 · 용량" 과 "불완전 N개 · 임시 N개" 가 늘면 알려 주기. `.part` 가 계속 남으면 브라우저가 전송 중 닫힌 것.
- 디스크 여유는 앱이 보여 주지 않는다. 자동 백업 실패 메시지 "디스크 공간이 부족해요" 가 첫 신호.
