# 기획안(PRD) — 숯불에닭 한눈 손익 장부 · v2
> 초안 — v1을 써 본 뒤 고칩니다 (9/18: 꼭 할 것 ①② + 원가율 탭 A안까지 1차 구현 완료. 10/2 중간 점검에서 확정)

- 가게 / 이름: 숯불에닭 / 강상구
- 조 주제: 날씨 기반 가게 운영 준비
- 이 버전의 목표 한 줄: 사장님이 매일 마감할 때 1분 입력으로 일별 매출·인건비를 쌓고, 카드사·배달앱별 정산 주기 규칙으로 통장 입금을 자동으로 짝 맞춰 실제 수수료율을 집계하며, 포스 판매 자료와 레시피로 원가율이 왜 변했는지까지 보는 도구

> 전체 그림은 [`../PRD_전체.md`](../PRD_전체.md)에 있습니다. 이 문서는 그중 **[v2] 꼬리표가 붙은 것만** 옮긴 초안입니다.
> v1을 10/2까지 써 보며 적은 `../v1/사용메모.md`를 보고 범위를 다시 정합니다.

## 1. 무엇을 왜 만들고 싶나요?

v1은 매달 초에 "지난달 얼마 남았나"를 빠르고 정확하게 보는 도구다. 하지만 결과를 **달이 끝난 뒤에야** 안다. 월 합계만 있어서 요일별·날씨별·채널별 패턴도 안 보이고, 시급제 직원(화덕 1명 + 홀 알바 1~2명)을 하루에 몇 명 부르는 게 맞는지 판단할 근거가 없다. 배달앱 실매출도 v1에서는 사장님 사이트 화면을 보고 손으로 옮겨 적어야 한다.

## 2. 누가 언제 쓰나요?

사장님 혼자 쓴다.

- 매일 마감 때 1분: 폰으로 오늘 채널별 매출과 시급제 직원 근무시간 입력
- 수시로: 폰으로 이번 달 누적·예상 손익, 일별 인건비율 확인
- 매달 초: PC로 v1의 월 정산 + 배달앱 정산 파일 올리기

## 3. 지금은 어떻게 하고 있나요?

(v1을 쓰고 있다는 전제) 월 1회 은행 엑셀을 올려 손익을 본다. 일별 매출은 포스와 각 배달앱 사이트에 흩어져 있고 따로 모으지 않는다. 시급제 직원 근무시간은 도구 밖에서 챙기고, 인건비는 월말 통장 이체액으로만 본다. 배달앱 실매출은 앱 4곳의 화면을 돌며 월 합계를 손으로 입력한다.

## 4. 도구를 쓰면 어떤 일이 달라지나요?

하루 기준: **채널별 매출 5칸 + 시급제 직원 별칭과 근무시간**을 넣으면 → 그날 매출 합계, 어림 인건비, **인건비율**이 나오고 → 이번 달 누적과 "이 속도면 이번 달 이만큼 남는다"는 예상이 갱신된다.

한 달 기준: 배달앱 정산 파일을 올리면 주문금액·수수료·입금액이 자동으로 채워지고, 월말에는 도구가 계산한 시급제 인건비와 통장에서 실제 나간 급여를 나란히 보여 준다.

## 5. v2에서 만들 것 — 10/2 1차 마감 · 10/17 최종 (API 연동·외부 데이터 등 v1에서 미룬 것)

**꼭 할 것** (①이 있어야 ②가 된다 — 순서대로)

- 기능 1: **오늘 마감 입력** — 매일 마감 때 폰으로 채널별 매출(홀 카드·홀 현금·배달앱 4곳)과 시급제 직원(화덕A·홀A 등 별칭) 근무시간 입력 → 등록해 둔 시급을 곱한 어림 인건비, 일별 인건비율, 이번 달 누적. 빠뜨린 날은 달력에 표시하고 나중에 채움. 사람별 주간 근무시간이 15시간에 가까우면 "확인 필요" 표시. 포스에 카드사별 매출 집계가 있으면 카드를 카드사별로 나눠 넣을 수 있게 한다(없으면 "카드 전체" 한 줄).
- 기능 2: **정산 주기 규칙 + 통장 입금 짝 맞추기 + 수수료 집계** — 카드사별·배달앱별 정산 규칙(예: 매출일 + 2영업일, 주문일 + 4영업일, 주 단위 정산)을 한 번 등록 → 은행 엑셀의 입금 한 건 한 건을 "어느 날짜 주문분"인지 자동으로 짝지음 → 채널별 실제 수수료액·수수료율(주문금액 − 실제 입금)을 **정산금액을 손으로 넣지 않고** 집계. 월말 미입금액도 자동 계산. 짝이 안 맞는 입금(누락·추가 공제)은 따로 표시. v1의 "정산금액 직접 입력"은 규칙이 없는 채널의 대체 수단으로 남긴다.

**여유 있으면** (순서대로. 1순위는 10/2에 되는 데까지, 10/17까지 마무리)

- 1순위 **원가율 탭 (A안)** — 매달 포스(오케이포스) "상품ABC분석" 엑셀을 올리면 메뉴별 판매량 × 레시피 원가(품목별 기준단가)로 **이론 재료비·이론 원가율**을 구하고, 통장의 실제 재료비(매출원가)와 나란히 놓아 차이를 보여 준다. 메뉴별 원가율·마진 순위도. 계산 로직은 `ai-store-manager`(포스 파서·레시피 사용량·원가차이 분석, 테스트 76개)에서 가져온다. 시세 요인/로스 요인 분해는 입고 단가·실사 재고가 있어야 해서 B안(별도 매장관리자, v2 이후)으로. 준비물: 품목별 기준단가(대략값), 미등록 메뉴 레시피. **실제 레시피·단가·포스 파일은 저장소에 올리지 않고 시연은 가짜 값으로.**
- 월중 누적·예상 손익 + 고정비 등록 (월세·주방 월급처럼 매달 같은 돈을 등록해 일할로 반영)
- 배달앱 정산 파일 올리기 — 앱별 정산 파일로 광고비·배달비·결제수수료를 구분해 진짜 수수료율 확정. 준비물: 앱 4곳 정산 파일 모양 확인
- 월별 추이 그래프 (매출·재료비율·인건비율·수수료율·영업이익)
- 날씨 자동 붙이기 — 일별 매출·인건비 옆에 그날 날씨. 준비물: 날씨 API 키 발급. 조 주제 '날씨 기반 준비'로 이어 가는 첫걸음
- 세무사에게 넘길 엑셀 내보내기 — 준비물: 세무사가 원하는 파일 모양 물어보기
- 세금 대비 미리 보기 — 준비물: 어림 계산 방식을 세무사에게 확인
- 알림 ("어제 마감 입력 안 했어요", "재료비율이 평소보다 높아요") — 준비물: 알림 채널 가입·심사. 안 되면 화면 표시로 대신

- **이번에 하지 않을 것:** 은행·카드 자동 가져오기, 포스 연결, 배달앱 자동 연결(파일 올리기 없이), 세무사 자동 전달, 출퇴근 기록·급여명세서, 직원 로그인, 재고 원장·발주·실사(B안 매장관리자)

## 6. 완성됐다는 걸 어떻게 확인하나요?

- 시연할 예시 입력: 가짜 일별 데이터 2주 치(채널별 매출 + 화덕A·홀A·홀B 근무시간), 가짜 은행 엑셀(카드사·앱별 입금이 정산 주기대로 찍힌 것), 정산 규칙 5개, 가짜 포스 상품ABC분석 엑셀 + 가짜 레시피·기준단가
- 기대하는 결과: 날짜별 매출·인건비·인건비율 표가 나오고 빈 날 2일이 달력에 표시됨 → 채우면 누적이 바뀜 → 규칙을 등록하면 통장 입금이 날짜 주문분에 자동으로 짝지어져 채널별 실제 수수료율이 나오고, 짝이 안 맞는 입금 1건이 따로 뜸 → 월말 미입금액이 자동 계산되어 v1의 대조표와 일치 → (원가율 탭) 포스 엑셀을 올리면 이론 재료비·이론 원가율과 실제 재료비가 나란히 보이고 메뉴별 원가율 순위가 나옴
- 잘못 입력했을 때: 평소의 10배인 매출이나 하루 24시간이 넘는 근무시간 → 저장 전에 "맞나요?" / 같은 날을 두 번 입력 → 덮어쓸지 묻기 / 모양이 다른 포스·정산 파일 → 저장하지 않고 안내 / 포스 엑셀의 합계 행과 읽은 합이 다르면 → 올리기 막음 / 레시피가 없는 메뉴 → "미등록"으로 따로 표시(원가율에서 빠졌다고 알림)
- 다시 열었을 때 남아 있어야 할 것: 일별 채널 매출, 일별 시급제 근무(별칭·시간·시급), 정산 주기 규칙, 입금 짝 맞춤 결과, 메뉴·레시피·기준단가, 올린 포스 파일의 기간, 고정비, v1의 모든 데이터

## 7. 그 다음에 더하고 싶은 것

- 다음에 추가할 기능 하나: **B안 매장관리자** — 입고(이동평균 단가)·실사 재고 원장을 붙여 원가율 변화를 시세 요인/로스 요인으로 분해, 오늘 확인할 품목 3~5개 추천 (`ai-store-manager` 설계대로). 그리고 날씨·요일별 매출 패턴으로 "내일 준비량·부를 인원" 추천 (조 주제와 합치기)
- 필요한 데이터나 외부 연결 (API, 배민 데이터, 날씨 등): 은행·카드 자동 가져오기, 포스 연결, 배달앱 자동 연결 — 승인·비용을 먼저 알아봐야 함
- 사람이 직접 판단·확인해야 할 부분: 추천 준비량·인원은 참고만, 결정은 사장님

## 8. 절대 자동화하면 안 되는 것

- 월 정산 확정(마감) 버튼
- 애매한 거래의 분류
- 급여·주휴수당 확정, 세금 금액 확정 — 도구는 근무시간 × 시급의 어림값과 "확인 필요"만 보여 준다. 실제 이체는 사장님이.
- 세무사에게 파일 보내기, 직원·손님에게 가는 모든 메시지 전송
- 데이터 삭제
