## 4. 어떻게 개선했나 — 네 가지 방향 중 해 본 것

| 방향 | 받은 것 · 찾은 것 | 그래서 고친 것 |
|---|---|---|
| **젬마쌤 피드백** | 원포인트 — "**손으로 옮기는 단계 줄이기**": 카드사·통장 내역 자동 가져오기, 쿠팡·네이버 구매내역을 영수증 대신, 세금계산서는 볼타(Volta) | **통장 자동 가져오기를 실제로 조사·착수**했습니다. 팝빌 계좌조회 연동을 서버까지 만들었는데 **링크허브 파트너 심사**가 필요해 캠프 안에는 못 끝내고 코드를 들어냈습니다([기록](통장_자동으로_가져오기.md)).<br>대신 **손으로 옮기다 생기는 실수** 쪽을 막았습니다 — ① "통장을 어디까지 받아 뒀어요 → 다음은 ○일" 안내 ② **통장엔 들어왔는데 매출에 없는 날**을 먼저 찾아 주기. 볼타·코드에프는 캠프 뒤로 |

| **AI 대화 기반 인사이트** | "수수료율이 말이 안 되는 숫자면, 그 사이에서 매출이 엉뚱한 칸에 들어가 있는 것" — 한쪽이 과대, 한쪽이 과소면 그 둘 사이를 보라는 것 | 간편결제 수수료율 **23.0%**, 삼성카드 **−43.9%** → 토스페이로 받은 **7만 5천원**이 포스엔 "간편결제", 돈은 삼성카드로 들어오고 있었습니다. 옮기니 **1.3%·1.7%**로 동시에 정상.<br>이제 입금이 매출보다 많으면 앱이 먼저 **"간편결제·배달대행 카드결제부터 확인하세요"** 라고 띄웁니다.<br>같은 식으로 **9월 급여 13만원 차이**의 원인이 **15분 단위 반올림**인 걸 찾아 분 단위로 고쳐 0원까지 맞췄습니다 |
| **QA (가상 페르소나 · 실제 사용자)** | 가상 페르소나 대신 **실사용으로 QA**했습니다 | 9/18부터 **거의 매일** 제가 직접 씁니다. 9월을 장부로 끝까지 마감(10/1, 미분류 0줄)하고, 10/1~10/8을 하루도 빠짐없이 넣었습니다. 여기서 나온 버그를 그대로 고쳤습니다 — 정산 탭의 "매출 미입력" 오표시, 카드사가 나눠 보낸 정산이 헛경고로 뜨던 것, 환급만 단독으로 들어온 입금이 "짝이 안 맞는 입금"으로 뜨던 것 |

- 반영하지 않은 의견과 이유:
  - **팝빌 연동** — 통장 자동 가져오기는 맞는 방향인데, 팝빌만 가입해서는 안 되고 **링크허브 파트너 심사**를 따로 받아야 합니다. 캠프 기간에 끝낼 수 없어 코드를 들어냈습니다. 캠프 뒤에 **코드에프·볼타**를 다시 봅니다
  - **카카오톡 알림** — 젬마쌤도 권하지 않았고, 공식 지원이 없어 우회가 불안정합니다. 지금은 손익 탭의 "카톡으로 보낼 요약 복사"로 제가 직접 붙여넣습니다
  - **배달앱 자동 가져오기 · 영수증 사진 자동 인식** — 로그인과 사장님 전용 저장소가 있어야 합니다. 캠프 뒤 개인용 버전에서
  - **직원도 보는 화면 · 알림 · 세금 미리 보기** — 3주 써 보는 동안 필요하다는 기록이 한 번도 없었습니다

  - 커밋 전에 `git diff --cached`로 훑어보고, **API 키·비밀번호·`.env`·직원/손님 실명·실제 매출 파일**은 빼기. 전역 gitignore와 pre-commit 훅으로도 막고, 훅에 걸리면 `--no-verify`로 우회하지 않기

  - **실제 매출·영업이익 금액** — 가게 숫자입니다. 발표자료에도 비율(원가율·수수료율·인건비율)과 "찾아낸 금액"만 넣었습니다

  - **백업 JSON** — 실제 숫자가 통째로 들어 있어 저장소에 올리지 않고 `문서\숯불에닭_장부백업\`에만 둡니다
