# 김씨육면 월말 정산

대시보드 / 월 정산 두 화면. Supabase·Vercel 없이 로컬에서만 돌아간다.
데이터는 브라우저 localStorage에 월별로 저장된다.

> 공개용 사본 — 실제 금액·건수는 ○○○로 가렸습니다. 구조와 검증 방식은 원본과 같습니다.

## 화면

- **대시보드** — 연간. 누적 KPI 5개, 월별 매출·비용 막대, 연간 비용 구성,
  월별 정산 표(눌러서 그 달로 이동), 계정과목 연간 상위와 월평균
- **월 요약** — 선택한 달. KPI 5개, 지표(프라임코스트·식재료비율·인건비율·임차료율)와 전월 대비 %p,
  계정과목 전월 대비 표, 비용 구성, 채널별 매출, 확인 필요, 계정과목 상위, 고정·변동
- **월 정산** — 4단계: 불러오기 → 고정비 → 변동지출 분류·검수 → 매출. 마감은 맨 아래 버튼
- **설정** — 계정과목·소분류 추가·수정·삭제, 고정비 템플릿, 인건비 고정·변동, 월별 데이터 초기화

분석은 따로 두지 않는다. 계정과목 전월 대비·지표·누락 경고·이상값 경고는 모두 **월 요약**에 있다.
달을 보면서 바로 확인하는 게 맞지, 따로 탭을 열 이유가 없다.

화면은 **항상 라이트로 시작**한다. OS가 다크여도 따라가지 않으며, 헤더의 ◐로 바꾼 값만 기억한다.

## 카드 파일 넣기

카드사에서 **승인일(이용일) 기준**으로 1일~말일을 지정해 CSV로 내려받는다. 청구기간이 아니다.

카드사마다 머리글 이름과 열 순서가 다르므로 위치를 고정하지 않고 **이름으로 찾는다.**
필요한 건 이 정도다.

| 필드 | 받아들이는 머리글 |
| --- | --- |
| 날짜 | 승인일 / 이용일 / 이용일자 / 거래일자 / 거래일 / 매출일자 / 사용일자 … |
| 가맹점명 | 가맹점명 / 이용가맹점 / 가맹점상호 / 가맹점 / 이용하신곳 / 상호 … |
| 금액 | 승인금액 / 이용금액 / 거래금액 / 청구금액 / 결제금액 … |
| 취소일 | 취소일자 / 취소일시 / 취소일 |
| 할부개월 | 할부개월 / 할부기간 / 개월 / 할부 |
| 승인번호 | 승인번호 / 거래번호 |

- **EUC-KR / CP949**로 저장된 파일도 그대로 읽는다. 카드사 CSV는 UTF-8이 아닌 경우가 많다
- 머리글 칸 안에 줄바꿈이 들어 있어도 읽는다 (`"국내이용금액\n (원)"`)
- 국내·해외 금액 열이 같이 오면 **국내**를 쓴다
- 할부 개월은 전용 열에서 읽고, 없으면 결제방법에서 뽑는다 (`부분무이자10` → 10개월)
- 엑셀이 열 너비 때문에 금액을 `######` 로 내보낸 칸은 **0으로 넘기지 않고 따로 표시한다**
- 안내문이 위에 몇 줄 붙어 있어도 머리글 줄을 찾아낸다
- 못 찾으면 **열을 직접 고르는 화면**이 뜬다
- `2026년 07월 31일`, `2026.7.3`, `20260703` 모두 날짜로 읽는다
- 파일 맨 아래 `OO 소계 N건` 같은 집계 줄은 거래에서 뺀다. 버리지 않고 대조에 쓴다
- 같은 파일을 겹쳐 올려도 **승인일 + 승인번호**로 걸러진다.
  카드번호는 `4***-****-****-601*`처럼 마스킹돼 내려오므로 뒷4자리를 쓸 수 없다
- **취소 건**(승인구분에 취소 / 취소일이 채워짐 / 금액이 음수)은 지출 집계에서 뺀다.
  버리지 않고 접힌 영역에 날짜·가맹점·금액을 남긴다
- **할부 건**은 승인금액을 원본 그대로 넣고 `할부` 표시만 한다. 월 안분은 아직 하지 않는다
- 가맹점명 원문은 어떤 경우에도 지우거나 가공하지 않는다
- 계정 분류는 다음 단계이므로 불러온 직후에는 **전부 미분류**다

### 파일 합계와 대조

카드사가 파일에 적어둔 합계와 파서 집계를 맞춰본다. 정답 숫자를 코드에 박지 않는다.
합계는 두 자리에 온다 — **아래쪽 소계 줄**(현대카드)과 **위쪽 요약 블록**(국민카드) 둘 다 읽는다.

```bash
npm run verify:card <파일>
```

2026년 7월 현대카드 파일에서 잡힌 것:

| | 건수 | 금액 |
| --- | ---: | ---: |
| 파일 합계 (총 합계 소계) | 128 (취소 포함) | ○○○,○○○,○○○ |
| 파서 집계 | 127 (유효 124 + 취소 3) | ○○○,○○○,○○○ |
| **차이** | **−1** | **−6,500** |

**파일에 ○,○○○원짜리 1건이 빠져 있다.** 그리고 파일 안에서도 집계가 안 맞는다 —
개별 소계 합 ○○○,○○○,○○○ vs 총 합계 ○○○,○○○,○○○, 차이 ○○○,○○○이 정확히 취소 3건 합계다.
개별 소계는 **취소 포함 승인 기준**, 총 합계는 **취소 차감 청구 기준**이다.

2026년 7월 국민카드 파일에서 잡힌 것:

| | 건수 | 금액 |
| --- | ---: | ---: |
| 파일 요약 (정상/취소) | 50 | ○○○,○○○,○○○ |
| 파서 집계 | 50 | ○○○,○○○ |
| **차이** | **0** | **○○○,○○○,○○○** |

건수는 맞는데 금액만 어긋났고, 금액을 못 읽은 건이 딱 하나였다.
그래서 **`(특정 거래처)`의 금액이 ○○○,○○○,○○○원**이라고 역산해 알려준다.
원인은 엑셀 열 너비로 `########` 가 된 것이다.

### 기존 가계부 시트

구글시트 가계부(월별 탭) CSV도 그대로 받는다. 과거 데이터 이관과 검증용이다.

## 분류·검수

계정 → 소분류 → 거래처 → 건, 4단 트리다. **금액 3만원 미만은 접힌다** —
건수로 접으면 1건짜리 큰 지출(우삼겹 258만, 알바 241만)이 숨기 때문이다.

- 거래처를 골라 한 번에 계정·소분류를 지정하고, `거래처 기억`을 켜면 다음 달 자동 적용
- 소분류 **이름 바꾸기**(딸린 건 전부) / 고른 건을 **새 소분류로 묶기**
- 소분류와 건에 **메모**를 남길 수 있다
- 쿠팡·세븐일레븐·배민은 계정이 채워져 있어도 [매장]/[집]을 묻는다
- `다시 분류`는 배운 규칙으로 다시 돌린다. 사람이 확정한 건은 건드리지 않는다

## 분할 — 할부와 안분

지출내용에 적힌 `종소세 ( 2/12 )` 같은 표기를 읽어 필드로 옮긴다.

- **할부** — 카드사가 나눠 청구. 실지출월 = 귀속월
- **안분** — 한 번에 나갔지만 나눠서 본다. 세금·대출이자·4대보험 (PRD §7)

마지막 회차인 건은 "이번 달로 끝나는 분할"로 표시된다.

## 규칙 보관

검수하며 만든 매핑·소분류 정리 이력은 브라우저에만 두면 지우는 순간 날아간다.
`규칙 내보내기`로 받은 파일을 `config/mappings.json`에 덮어쓰고 커밋한다.
앱은 그 파일을 바닥에 깔고 시작한다.

## 실제 자료는 저장소에 없습니다

`data/` 폴더에는 실제 카드 내역과 가계부가 들어갑니다. 공개 저장소라 올리지 않습니다.
받아서 돌려 보실 때는 비어 있는 게 정상이고, 화면에서 직접 카드 CSV를 올리면 됩니다.
파서만 먼저 보시려면 `fixtures/`의 가짜 파일을 쓰세요.

```bash
npm run verify:card fixtures/hyundai-2026-08.csv
```

## 7월 검증 결과 (기존 시트 대조)

`data/2026-07-ledger.csv`(기존 가계부 시트 7월 탭)를 넣은 결과다.

| 항목 | 툴 집계 | PRD §3 상단 목업 |
| --- | ---: | ---: |
| 매출 | ○○○,○○○,○○○ | ○○○,○○○,○○○ |
| 비용 | ○○○,○○○,○○○ | ○○○,○○○,○○○ |
| 영업이익 | ○○○,○○○ (3.4%) | ○○○,○○○ (3.4%) |
| 프라임코스트 | 54.1% | 54.1% |

계정과목별 합계는 시트의 각 소계와 전부 일치한다(식자재비·인건비·임대료·마케팅비·공과금·고정운영비·일회용품·매장운영비·설비/비품비). 개인지출 ○○○,○○○,○○○, 고정비내역 ○○○,○○○,○○○도 일치.

### 툴이 잡아낸 기존 시트의 문제

1. **변동비 소계가 ○○○,○○○원 적다.** 시트의 `변동비 소계 ○○○,○○○,○○○`는 세금 중 부가세(○○○,○○○)만 더하고 지방세(○○○,○○○)·종소세(○○○,○○○)를 빠뜨렸다. 바로잡으면 ○○○,○○○,○○○.
2. **`세금 소계` 라벨이 두 번 나온다.** 77행의 ○○○,○○○는 실제로 대출이자 금액이고, 101행은 0이다. 세금의 진짜 소계 ○○○,○○○는 시트 어디에도 없다.
3. `대출이자 소계`·`기부 소계` 행이 없다.
4. **날짜 입력률 0.4%** (○○○건 중 1건). 일별 집계가 불가능하다.

## 계산 규칙

- **수수료**는 계정 하나로 신설했고 `매출액 − 입금액`으로 자동 계산한다(7월 ○○○,○○○,○○○). 시트의 `지출 총 합계`에는 수수료가 없으므로, 시트와 대조할 때는 수수료를 뺀 ○○○,○○○,○○○와 비교한다.
- **기타수입**(환급금·보험금)과 **개인지출**은 손익에서 빼고 합계만 따로 보여준다.
- **고정/변동**은 계정 플래그를 읽어서 계산한다. 인건비는 소분류별로 플래그가 다르다(직원·4대보험 고정 / 알바·복리후생 변동).
- **월 귀속**은 카드 청구기간이 아니라 거래일(승인일) 기준. 날짜가 없으면 시트/선택한 월로 귀속된다.

## 설정에서 할 수 있는 것

- **계정과목** — 이름 바꾸기, 추가·삭제, 고정/변동 지정, 소분류 추가·이름 변경·삭제
- **인건비 고정·변동** — 소분류(직원·알바·4대보험·복리후생)마다 따로. 손익분기점이 이 값을 읽는다
- **고정비 템플릿** — 항목·금액·월별 변동 여부·범위. '템플릿에서 시작'이 이 목록을 쓴다
- **데이터** — 달별로 지우거나 전부 지우기. **정산 데이터만 지워지고 계정과목·고정비 설정은 남는다**
- `설정 내보내기`로 받은 파일은 `data/settings.json`에 커밋해 기준으로 삼는다

## 아직 없는 것

- Supabase 연동, Vercel 배포

## 소분류는 아직 정리하지 않는다

지금 소분류는 거래처 축(투웰브·모노마트·마트/또와)과 품목 축(고기·새우·김치)이 섞여 있다.
7월 한 달 근거로 축을 갈아엎으면 위험하므로, **이름만 정리하며 두세 달 쌓은 뒤** 다시 본다.
그동안 바꾼 이름은 `config/mappings.json`의 `subRenames`에 이력으로 남는다.
