# 전체 기획안(PRD) — 김씨육면 손익관리

- 가게 / 이름: 김씨육면 / 오지영
- 조 주제: 매장 월말정산 (인건비 계산, 손익관리)
- 한 줄 목표: **사장이 월말에 카드 내역 파일을 넣으면, 분류만 하고 그 달 손익이 바로 보이는 도구**
- 마지막 수정: 2026-09-17

> **이 문서는 "다 만들었을 때의 모습"입니다.** 먼저 여기에 전체를 그린 뒤, 4번 기능 목록에 꼬리표를 붙여
> 오늘 만들 것은 `v1/PRD.md`로, 나중에 더할 것은 `v2/PRD.md`로 나눕니다.
> v1을 써 본 뒤에는 `v1/사용메모.md`를 보고 이 문서와 v2를 다시 고칩니다.

> 금액은 **예시값**입니다. 실제 매출·급여 금액은 공개 저장소에 올리지 않습니다.
> 비율·구조는 실제 진단(2026.2~7, 6개월치) 결과 그대로입니다.

## 1. 배경 — 최근 실제로 있었던 한 장면

월말에 구글시트 가계부를 열고 카드 내역을 한 줄씩 옮겨 적는다. 6개월을 그렇게 했더니 이런 일이 생겼다.

- 장면: 처음 두 달은 날짜를 다 채웠는데, 여름이 되자 **거의 안 채우게 됐다.** 일별 매출 캘린더도 첫 달만 채워지고 그 뒤로 방치됐다. 날짜가 없으니 "이번 주가 지난주보다 나은가"를 볼 수 없다.
- 장면 2: 어느 달에 `판관비`라고 잘못 적은 건들이 마케팅비에서 빠졌다. **그달 마케팅비가 실제보다 한참 적게 집계**됐고, 그걸 보고 광고를 줄일 뻔했다.
- 얼마나 자주: 월 1회 (월말 정산)
- 한 번에 걸리는 시간: **반나절 이상 (4시간+)** — 날 잡아서 해야 끝나는 일이었다
- 실수·빠뜨림: 계정과목 오타로 인한 오분류, 날짜 누락, 변동비 소계에 세금 일부 누락

## 2. 쓰는 사람과 역할

| 누가 | 언제 여나 | 무엇을 보나 | 무엇을 누르나 | 어떤 기기로 |
|---|---|---|---|---|
| 사장 (나, 집) | 월말 정산할 때 | 월 정산 4단계, 검수 필요 건 | 파일 올리기, 계정 지정, 고정비 복사, 매출 입력, 마감 | 집 노트북 |
| 사장 (남편, 홀) | 정산 뒤 확인할 때 · 중간에 손익 궁금할 때 | 월 요약, 대시보드 | 확인, 빠진 것 추가 | 홀에서 폰·태블릿 |
| 세무사 | 정산 끝난 뒤 | 계정과목별 합계 | (파일로 받기만) | 내보낸 파일 |

**사장 둘이 쓴다.** 동시에 작업하지는 않는다 — 한 사람이 정산해 두면 다른 사람이 확인하거나 추가한다. 그래서 같은 데이터를 두 기기에서 열 수 있어야 한다(→ v2 Supabase). 직원은 쓰지 않는다.

## 3. 흐름 — 지금 vs 도구를 쓰면

| 단계 | 지금 (쓰는 앱·파일) | 도구를 쓰면 |
|---|---|---|
| 1 | 카드사 홈페이지에서 내역 받아 구글시트에 붙여넣기 | 카드 CSV를 화면에 올리면 자동으로 읽힘 (카드사마다 형식 달라도) |
| 2 | 계정과목을 손으로 타이핑 (오타 발생) | 거래처로 자동 분류, 드롭다운만 — 자유입력 없음 |
| 3 | 전부 다 훑어봄 | **검수 필요한 건만** 뜸 (쿠팡·세븐일레븐·배민 + 신규 거래처) |
| 4 | 고정비를 매달 다시 입력 | 전월 템플릿 복사 → 달라진 금액만 수정 |
| 5 | 수식으로 소계 계산 (틀려도 모름) | 마감 누르면 손익·지표 자동 계산 |
| 6 | 지난달과 비교하려면 탭을 왔다갔다 | 월 요약에 전월 대비가 같이 보임 |

**다시 열었을 때 남아 있어야 할 것**: 위 전부. 지금은 브라우저 localStorage에 월별로 저장되고, 규칙은 `mappings.json`으로 내보내 저장소에 커밋한다. (v2에서 Supabase로 옮김)

실제 직원 이름·연락처는 넣지 않는다. 인건비는 **소분류(직원/알바/4대보험/복리후생) 단위**로만 다룬다.

## 7. 예외 — 잘못 넣거나 평소와 다를 때

- 같은 파일을 겹쳐 올림 → **승인일+승인번호**로 중복 제거. 카드번호는 마스킹돼 내려와서 뒷4자리를 쓸 수 없다
- 취소 건 (승인구분 취소 / 취소일 있음 / 금액 음수) → 지출 집계에서 빼되 **버리지 않고** 접힌 영역에 남김
- 엑셀이 금액을 `######`로 내보냄 → **0으로 넘기지 않고** 따로 표시해서 사람이 보게 함
- 머리글을 못 찾음 → 열을 직접 고르는 화면이 뜸 (조용히 실패하지 않음)
- 파일 맨 아래 `OO 소계 N건` 집계 줄 → 거래에서 빼되 **파일 합계 대조에 씀**
- 지난달에 있던 고정비가 이번 달에 없음 → 누락 경고 (막지 않고 표시만)
- 수수료율이 범위를 벗어남 (홀 1~4%, 배달 20~35%) → 이상값 경고
- **막지 말고 표시한다.** 입력을 강제로 차단하면 안 쓰게 된다

## 8. 사람이 꼭 직접 해야 하는 것 (자동화 금지)

- **급여 확정** — 계산은 보조할 수 있어도 "이 금액으로 지급" 결정은 사람이. 주휴수당·최저임금은 노무 확인 필요
- **세무 신고** — 계정과목 분류는 도와도 신고 자체는 세무사
- **쿠팡·세븐일레븐·배민 건의 [매장]/[집] 판단** — 같은 가맹점에서 둘 다 나오므로 기계가 정할 수 없음
- **마감 버튼** — 자동으로 마감하지 않는다. 사람이 확인하고 누른다

## 9. 성공 기준 — 숫자로

- 지금: 월말 정산 한 번에 **반나절 이상 (4시간+)**
- 목표: **1시간 이내** (v1). 분류·소계·지표 계산이 자동이므로 사람이 하는 일은 검수·고정비 금액 수정·매출 입력만 남는다
- 그다음: 카드 전표만 넣어도 바로 분석되게 다듬어 **30분 → 20분**으로 (v2 이후)
- 목표 2: 계정과목 오타로 인한 오분류 0건 (자유입력 없이 드롭다운만)
- 시연할 예시 입력 → 기대하는 결과:
  - 카드 CSV 한 달치를 올린다 → 전부 미분류 상태로 들어옴 → 자동 분류 → 검수 대상만 뜸 → 고정비 복사 → 매출 입력 → 마감 → **월 요약에 매출·비용·영업이익·프라임코스트가 뜬다**
- **검증 방식**: 숫자가 맞는지가 아니라 **기존 시트의 오류를 툴이 잡아내는지**를 본다
  - 실제로 7월 데이터로 대조한 결과, 툴이 기존 시트의 문제 4가지를 찾아냈다 —
    변동비 소계 누락(세금 일부), `세금 소계` 라벨 중복, `대출이자 소계`·`기부 소계` 행 없음, 날짜가 거의 안 적힘

## 11. 아직 정하지 못한 것

- **툴로 실제로 몇 분 걸리는지** 아직 안 재봄 → 9번 목표(1시간)가 맞는지는 다음 정산 때 확인
- **홀 매출을 t'order·POS에서 끌어올 수 있는지** — 공개 자료로는 확인 안 됨(2026-09-17 검색). 확인 방법: ① `티오더 사장님` 앱·웹 관리자의 매출/정산 메뉴에 **엑셀·CSV 다운로드** 버튼이 있는지 본다 ② 없으면 티오더에 연결된 **POS 관리자**(POS 쪽은 대부분 내보내기 있음)에서 ③ 둘 다 없으면 고객센터 문의. 될 때까지는 손입력
- **손익분기점의 '목표 매출'을 누가 정하나** — 지난달 기준 자동 제안인지, 사장이 직접 넣는지
- **일별 흐름은 카드 승인일 기준** — 홀 매출이 손입력(월 합계)인 동안은 일별 매출이 배달만 보임. 홀 매출 끌어오기가 되면 완성
- **소분류 축이 섞여 있음** — 거래처 축(투웰브·모노마트)과 품목 축(고기·새우·김치)이 혼재. 7월 한 달 근거로 갈아엎으면 위험 → **이름만 정리하며 두세 달 쌓은 뒤** 다시 본다
- **홀 매출액 < 입금액인 달**이 있었음 (6월) → 어느 쪽 기준으로 넣을지 다음 정산 때 판단
- **4대보험 월 편차 7배** → 안분 옵션 적용 후 재확인
- **4→7월 매출 하락 원인** → 연간 흐름 보고 판단
- **스케줄러와 잇는 방식** — 스케줄러가 계산한 인건비를 어떻게 가져올지(파일/링크/같은 DB). 급여 확정은 여전히 사람이(8번)
- **(나중에 따로)** 가게 홍보 AI 과제 — 인스타 콘텐츠 기획은 별도 PRD가 이미 있음. 운영 도구가 아니라 이 문서에는 넣지 않는다
