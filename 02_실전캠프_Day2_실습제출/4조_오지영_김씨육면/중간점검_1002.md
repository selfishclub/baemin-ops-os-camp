## 2. 만든 과정 — 다른 사장님이 따라 할 수 있게

1. 계획을 어떻게 고쳤나요?
   7월 실제 자료를 넣어 보니 **기존 가계부 분류 체계가 카드 전표에 맞지 않았습니다.** 그래서 "분류 체계를 먼저 세우고 데이터를 맞춘다"를 뒤집어, **"먼저 다 보고 손으로 분류하면서 서너 달 쌓은 뒤에 체계를 세운다"**로 바꿨습니다. 단계도 5개(불러오기·고정비·분류·매출·마감)에서 **4개(불러오기·지출 분류·개인 지출·입금 내역)**로 줄였습니다.

2. 만든 순서 (세 줄 안팎):
   - 분류한 것이 달을 넘어 살아남게 고치고 → 1일~말일 일자별 표를 만들고 → 자동 분류를 '제안'으로 낮춰 사장이 확정하게 했습니다
   - 통장·쿠팡 전표·페이히어 매출표를 차례로 붙여 자료 원천을 넓혔습니다
   - 실제 7월 자료로 쓰면서 불편한 것을 하나씩 고쳤습니다(검색·체크박스·필터·표 모양·할부 나누기)

3. **AI에게 한 말 중 결과를 크게 바꾼 것** (원문 그대로):
   > 일단 우리가 맨 처음에 얘기한 것처럼 7, 8, 9, 10월 이렇게 몇 개월 치 지출 분석을 먼저 해보는 거야. 카드 내역을 넣고 앞으로 비슷한 단어가 있는 것들을 대분류, 소분류로 분류하는 거지. 그렇게 데이터가 쌓인 상태에서 나중에 고정비나 실수령액 같은 항목도 제외할 수 있게 데이터를 정돈해 줄 수 있을까?

   > 어쨌든 우리가 카드 내역을 모두 담았잖아. 그럼 카드 내역 안에 고정비 부분도 들어가 있을 텐데, 이 부분을 어떻게 처리하는 게 좋을까 고민해 봤거든.

   > 애매하다 싶은 부분은 다시 나한테 물어봐 주고, 물어본 다음에 결정해 줘. 최종적인 나의 검토가 있어야 해.

4. 막혔다가 푼 것과 푼 방법:
   - **같은 가게가 둘로 갈렸다** — 카드사가 이름을 잘라 보내 `우지커피 의정부송`과 `우지커피의정부송산초점`이 다른 거래처로 집계됐습니다. 원문을 고치면 중복 거르기와 전표 대조가 깨져서, **원문은 두고 보이는 이름만 입히는** 방식으로 풀었습니다
   - **설정을 바꿔도 숫자가 안 바뀌었다** — 집계가 설정이 아니라 코드에 박힌 기본값을 읽고 있었습니다. 제 CLAUDE.md에 "하드코딩 금지"라고 적어둔 것을 코드가 어기고 있었습니다
   - **개인 계정을 하나로 합치자 개인지출이 통째로 비용에 섞였다** — 옛 계정명이 레지스트리에서 사라져 미분류로 떨어졌고, 미분류는 비용에 들어가 영업이익이 흑자에서 적자로 뒤집혔습니다. **검산 스크립트(`npm run verify`)가 잡아냈습니다**

## 4. 아직 막힌 것 — 점검 때 같이 풀 것

- **정산을 진행할 때 어디까지 자동화가 가능할까.** 지금은 손으로 가르치는 중입니다. 몇 달 쌓여야, 어느 정도 맞아야 "이제 자동으로 붙여도 된다"고 할 수 있을까요. 그리고 **똑같은 이름으로 찍히는 거래**(토스페이처럼 실제 쓴 곳이 매번 다른 것)는 애초에 자동으로 가릴 수 있는 것인지도 궁금합니다
- **브라우저에만 저장되는 것.** 실제 금융 자료라 밖에 두기 꺼려지는데, 브라우저를 정리하면 날아갑니다. 내보내기 파일로 충분할지
- **소분류 축이 섞여 있다.** 거래처(투웰브·모노마트)와 품목(고기·새우)이 한 층에 있습니다. 어떻게 가르는 게 나을지
