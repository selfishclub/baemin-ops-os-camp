## 1. 무엇을 왜 만들고 싶나요?

v1은 돌아가지만 **이 노트북 안에서만** 돌아간다. 데이터가 브라우저 localStorage에 있어서 브라우저를 지우면 날아가고, 폰에서 "이번 달 어떻게 가고 있지"를 볼 수 없고, 세무사에게 줄 파일을 만들려면 화면을 캡처해야 한다. 무엇보다 **남편이 홀에서 열어 볼 수가 없다.**

## 2. 누가 언제 쓰나요?

- 나 — 집 노트북으로 월말 정산
- 남편 — 홀에서 확인·추가 (같은 데이터, 동시에 작업하지는 않음)
- 세무사 — 내보낸 CSV·엑셀 파일을 받아봄

## 3. 지금은 어떻게 하고 있나요?

v1대로. 단, 결과를 전달하려면 화면 캡처, 다른 기기에서는 못 봄, 규칙은 `mappings.json`을 수동으로 내보내 커밋.

## 4. 도구를 쓰면 어떤 일이 달라지나요?

인터넷 주소를 열면 → 간단 비밀번호 → 집에서 정산해 둔 걸 남편이 홀에서 그대로 봄 → `내보내기`로 세무사 파일 → 손익을 더 깊이 보는 화면 → 마지막에 스케줄러가 계산한 인건비가 자동으로 들어옴.

## 5. v2에서 만들 것 — 10/17까지 (API 연동·외부 데이터 등 v1에서 미룬 것)

**꼭 할 것**

- 기능 1 — **인터넷에서 열기**: Supabase에 정산 데이터·규칙 저장 (localStorage 대체), Vercel 배포, 링크 + 간단 비밀번호. 두 사람이 각자 기기에서 같은 데이터 (동시 편집은 필요 없음 — 한 사람이 해 두면 다른 사람이 확인·추가)
  - 준비물: Supabase 프로젝트 생성 · 키 발급 (**`.env`에만, 저장소에 올리지 않음**) · Vercel에 GitHub 저장소 연결 · 기존 localStorage 데이터 옮기기
- 기능 2 — **CSV · 엑셀 내보내기**: 월 요약(계정과목별 합계·채널별 매출·지표)을 파일로. 세무사 전달용
  - 준비물: 세무사가 원하는 열 순서 한 번 물어보기

**여유 있으면**

- **손익관리 심화** — ① 손익분기점·목표 대비 ② 채널별 수익성(수수료 뺀 실제 이익) ③ 일별·주별 흐름. 계산 재료(고정/변동 플래그·날짜)는 v1에 이미 있음. 목표 매출을 누가 정할지는 전체 PRD 11번
- 거래처 · 계정 검색 — 헤더에 자리는 있음. "이 거래처 올해 얼마 썼지"
- 홀 매출 끌어오기 — t'order·POS에서. 끌어올 수 있는지 확인 후. 될 때까지 손입력
- 할부 월 안분 — 표기는 읽고 있음. 나눠서 보는 옵션만 추가
- **알바 스케줄러 연동 (인건비 자동)** — 이미 만들어 둔 스케줄러(kimsnoodles-scheduler)와 연결해 그달 인건비가 자동으로 잡힘. **손익관리가 다 갖춰진 뒤 마지막에.** 급여 확정은 사람이

- **이번에 하지 않을 것:** 범용화·로그인·다른 사장님 온보딩 → 나중 / 카드사 API 연동 → 범위 밖

## 6. 완성됐다는 걸 어떻게 확인하나요?

- 시연할 예시 입력: 노트북에서 가짜 CSV 한 달치 마감 → 폰에서 같은 주소 열기
- 기대하는 결과: 남편 폰에서 같은 월 요약이 뜸. `내보내기` 누르면 엑셀에서 열리는 파일이 받아짐
- 잘못 입력했을 때: 비밀번호 틀리면 안 열림. 인터넷 끊긴 상태에서 올리면 "저장 안 됨" 표시 (조용히 잃지 않음)
- 다시 열었을 때 남아 있어야 할 것: v1의 전부 + 다른 기기에서도 같은 것. **브라우저를 지워도 남아 있어야 함**
