# 김씨육면 손익관리 — 이 프로젝트의 규칙

카드 내역서를 올리면 계정과목별로 분류해 그 달 손익을 보여주는 도구.
Next.js + 브라우저 저장소(localStorage). 서버도 DB도 없다.

깃 작업 규칙은 전역 `~/.claude/CLAUDE.md`에 있다. 여기 다시 쓰지 않는다.

---

## 1. 실제 돈 자료를 다룬다 — 이게 최우선

사장님의 진짜 카드 내역과 매출이다. 한 번 공개되면 되돌릴 수 없다.

- **`data/` 안은 전부 실제 자료다. 커밋하지 않는다.**
  확장자를 늘리지 말고 폴더째 막는다 (`data/*`). CSV만 막다가 PDF가 올라갈 뻔했다
- **문서에 실제 금액을 쓰지 않는다.**
  `README.md` · `CLAUDE.md` · 제출서 전부. 이 프로젝트는 캠프 공용 저장소로 통째로
  복사되므로 문서도 같이 공개된다. 검증 결과는 **무엇을 어떻게 잡아냈는지**만 쓰고 숫자는 뺀다
- **코드에 실제 금액을 박지 않는다.**
  고정비 템플릿 금액은 0이고, 실제 값은 설정 화면에서 넣는다
- **`public/`에 실제 파일을 두지 않는다.** 배포하면 그대로 공개된다.
  시험하려고 임시로 뒀으면 **그 자리에서 지운다**
- 시연·테스트는 `fixtures/`의 가짜 파일로 한다

---

## 2. 검증은 "숫자가 맞나"가 아니라 "틀린 걸 잡아내나"

- **정답 숫자를 코드에 박지 않는다.** 파일이 스스로 검산하게 한다.
  카드사가 파일에 적어둔 합계와 파서 집계를 맞춰보는 방식
- 파서를 고쳤으면 회귀를 확인한다

  ```bash
  npm run verify                      # 기존 가계부 시트 대조
  npm run verify:card <파일>           # 카드 파일 대조
  npm run verify -- --save-baseline   # 기준값 새로 저장 (data/baseline.json, git 제외)
  ```

- 기준값은 `data/baseline.json`에 있고 git에 올라가지 않는다. 문서에 적지 않는다
- 이 방식으로 실제로 잡아낸 것: 기존 시트의 소계 누락 · 카드사 파일에 거래 한 줄이 빠진 것 ·
  엑셀이 `########`로 내보내 금액을 못 읽은 칸

---

## 3. 파서

- **특정 카드사 기준으로 만들지 않는다.** 열 위치를 고정하지 말고 **머리글 이름으로 찾는다.**
  현대카드 전용으로 만들었다가 전부 되돌린 적이 있다
- 필요한 필드만 본다 — 날짜 · 가맹점명 · 금액 · 취소일 · 할부개월 · 승인번호
- **인코딩을 판별한다.** 카드사 CSV는 UTF-8이 아닌 경우가 많다 (EUC-KR / CP949)
- **값을 조용히 0으로 만들지 않는다.** 엑셀이 `########`로 내보낸 칸은 0이 아니라
  "못 읽음"으로 따로 센다. 그냥 0으로 넘기면 금액이 소리 없이 사라진다
- **가맹점명 원문은 어떤 경우에도 가공하지 않는다**
- 집계 행(소계·합계·총계)은 거래가 아니다. 목록에서 빼되 **버리지 않고 대조에 쓴다**
- 취소 건은 집계에서 빼되 목록에 남긴다
- 같은 파일을 두 번 올려도 건수가 늘지 않아야 한다

---

## 4. 화면

- **막지 말고 표시한다.** 이상값은 경고만 하고 입력을 차단하지 않는다.
  막으면 안 쓰게 된다
- **접는 기준은 건수가 아니라 금액이다.** 건수로 접으면 1건짜리 큰 지출이 숨는다
- **접은 것은 반드시 펼칠 수 있어야 한다.** 접혀서 분류 자체가 막힌 적이 있다
- **계정과목은 자유입력 금지, 드롭다운만.** 오타 하나가 판단을 뒤집는다
- 분류하는 동안 금액이 움직이는 게 보여야 한다

---

## 5. 도메인

- 프라임코스트 = 식자재비 + 인건비
- 수수료 = 매출액 − 입금액 (계정으로 자동 생성)
- **개인지출과 기타수입은 손익에서 제외**하고 합계만 따로 보여준다
- **고정/변동은 계정 플래그를 읽어서 계산한다. 코드에 하드코딩 금지.**
  인건비는 소분류(직원·알바·4대보험·복리후생)마다 따로 간다
- 월 귀속은 카드 청구기간이 아니라 **거래일(승인일)** 기준

---

## 6. 개발 환경 함정 — 전부 실제로 당한 것들

- **개발 서버가 도는 중에 빌드를 돌리지 않는다.**
  `.next` 폴더를 서로 덮어써서 청크가 404 → 화면이 빈 채로 뜨고 클릭이 안 먹는다.
  `npm run build`는 `NEXT_DIST_DIR=.next-build`로 분리돼 있어 안전하지만,
  **`vercel build`는 그 설정을 안 따르고 기본 `.next`를 쓴다.** 배포한 뒤에는
  개발 서버를 재시작해야 한다
- **파일을 지우거나 옮겼으면 개발 서버를 재시작한다.** 삭제된 모듈을 붙들고 있다
- Node에서 **`fs.readFileSync().buffer`를 그대로 쓰지 않는다.**
  공용 풀이라 옆 데이터가 딸려온다. `.slice(byteOffset, byteOffset + byteLength)`
- 이 폴더에서 **`git add -A`를 쓰지 않는다.** 아래 캠프 저장소가 서브모듈로 들어간다

## 7. baemin-ops-os-camp/

12명이 함께 쓰는 **별도 공개 저장소**다. 이 프로젝트와 다른 저장소다.

- 남의 폴더는 **읽고 복사만**. 고치지 않는다
- **push 전 반드시 사람에게 확인받는다**
- 로컬과 원격이 갈라져 있으면 임의로 합치지 말고 상황을 설명한 뒤 물어본다
- 제출 폴더: `02_실전캠프_Day2_실습제출/4조_오지영_김씨육면/`
- 복사할 때 `data/` · `node_modules` · `.next` · `.git`을 뺀다

## 8. 아직 안 된 것 / 알려진 문제

- **학습 규칙이 달마다 갇혀 있다** (`state.learned`). 7월에 배운 걸 8월이 모른다.
  전역 저장소로 옮겨야 "카드 내역서만 넣으면 바로 분류"가 된다
- **고유키에 카드 구분이 없다** (`card:날짜:승인번호`).
  카드가 늘면 다른 카드사의 같은 승인번호가 충돌할 수 있다
- 분류 결과가 브라우저에만 있다. 내보내기·되불러오기가 없어 브라우저를 정리하면 날아간다
- 쿠팡은 가맹점명이 `쿠팡(쿠페이)`뿐이라 상품명 없이는 분류가 안 된다.
  전표 PDF에 **승인번호**가 있어 카드 내역과 1:1로 붙는다 (브라우저에서 pdf.js로 확인 완료).
  다만 매달 80%가 새 상품이라 **전표는 매달 필요하다**
- 소분류가 거래처 축(투웰브·모노마트)과 품목 축(고기·새우)으로 섞여 있다.
  **두세 달 데이터를 쌓은 뒤 정리하기로 했다. 지금 손대지 않는다**
