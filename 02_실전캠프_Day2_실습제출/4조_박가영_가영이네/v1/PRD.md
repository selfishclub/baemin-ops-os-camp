# 기획안(PRD) — Gayoungene Menu Finder · v1

- 가게 / 이름: 가영이네 / 박가영
- 조 주제: 없음 (4조는 개인 주제로 진행) · 개인 주제: 외국인 손님용 다국어 메뉴 선택 도우미
- 이 버전의 목표 한 줄: **외국인 손님이** **키오스크·테이블오더 앞에서 뭘 시킬지 모르는 순간에** **피하는 재료·맵기에 맞는 메뉴를 고르고 번호로 찾아 주문하는 일을** 편하게 처리하는 도구

> **상세 요구사항은 [`../PRD_원본_GPT_v1.2.md`](../PRD_원본_GPT_v1.2.md)를 따른다.** 화면 순서(S01~S07), 영어 문구, 필터 규칙(7장), 메뉴 번호 규칙(8장), 데이터 구조(9장), 접근성 기준(12장), 검수 시나리오(13장)는 그 문서가 기준이고, 이 파일은 그중 **오늘(9/17) 만들 범위**만 고른 것이다. 두 문서가 다르면 범위는 이 파일, 세부 동작은 원본을 따른다.
> MVP 사이트(chatgpt.site)는 화면 참고용이며 코드는 없음. 사전 과제로 낸 "질문 3개 추천형" 기획은 이 문서로 대체함. 전체 그림과 v1/v2 나눔은 `../PRD_전체.md`.

## 1. 무엇을 왜 만들고 싶나요?

외국인 손님이 키오스크 앞에서 한참 서 있다가 "고기 들어가요? 맵나요?"를 몸짓·번역기로 묻습니다. 직원이 답하고, 육수·소스 재료는 주방에 확인하러 갔다 옵니다. 매운 걸 못 먹는 손님이 떡볶이를 시켰다가 거의 남긴 적이 있고, 순대·어묵은 뭔지 몰라서 주문이 안 들어옵니다. 겨우 골라도 키오스크 한글 화면에서 그 메뉴를 다시 못 찾아 직원이 옆에서 눌러 줍니다.

외국인 손님은 주 3~5팀(영어권이 제일 많음), 팀당 설명 3~5분. 시간보다 **잘못 시켜 남기는 일**과 **겉만 보고 "고기 없어요"라고 답할 위험**이 문제입니다.

## 2. 누가 언제 쓰나요?

- **손님:** 본인 폰으로. 설치·로그인 없음. 매장에서는 테이블·키오스크 옆 QR, 방문 전에는 구글 비즈니스 가게 소개 링크나 공유받은 링크로 엶. (QR 인쇄물·구글 비즈니스 등록은 공개 주소가 생긴 뒤 → v2, 링크 공유는 바로 가능)
- **사장·어머니:** 손님이 막힐 때 화면을 같이 봄.
- **사장 (관리):** 메뉴·가격·재료·번역 값을 데이터 파일에 채움. **값은 나중에 한 번에 올림.** 오늘은 샘플 표시가 붙은 가짜 데이터.

## 3. 지금은 어떻게 하고 있나요?

1. 손님이 키오스크 한글 화면·종이 메뉴판을 봄
2. 손짓·번역기 앱으로 재료·맵기를 물음
3. 직원이 주방에 재료 확인하고 다시 나와 답함
4. 직원이 키오스크에서 대신 눌러 줌

## 4. 도구를 쓰면 어떤 일이 달라지나요?

한 손님 기준:

| | 넣는 것 | 나오는 것 |
|---|---|---|
| 1 | 사이트 열기 (영어 기본, 언어 선택) | 첫 화면에 "피하는 재료 · 맵기 · 음식 종류" 선택이 펼쳐져 있음 |
| 2 | 피하는 재료(여러 개) · 맵기 상한 · 종류 고르기 | 맞는 메뉴만 남은 2열 카드 + 개수 + "미확인이라 빠진 메뉴 있음" 안내 |
| 3 | 카드 누르기 | 상세: 번호, 언어별·한국어 이름, 재료별 포함/없음 확인됨/미확인, 맵기, 충족한 조건 |
| 4 | "Find this dish in store" | 번호·사진·한국어 이름 큰 화면 + "키오스크·테이블오더에서 주문·결제하세요" |

직원 설명 없이 손님이 스스로 고르고, 키오스크에서 번호로 찾습니다. 사이트는 아무것도 주문하지 않습니다.

## 5. v1에서 만들 것 — 오늘(9/17) 안에 되는 것만

- **기능 1: 조건 선택 필터** — 피하는 재료(Pork · Beef · Chicken · Fish & seafood · Egg · Dairy, 여러 개), 맵기 상한(Any / Not spicy / Up to mildly / Up to spicy / Very spicy OK), 음식 종류(All / Rice / Noodles / Chicken / Snacks). 첫 화면에 펼쳐져 있고 고르면 목록이 바로 바뀜. 조건 요약·개수·"Clear filters · Show all dishes".
- **기능 2: 재료 3상태 판정** — 재료마다 `contains` / `absent_verified` / `unknown`. 고른 재료가 `absent_verified`인 메뉴만 결과에 포함. `unknown`은 빠지고 안내. 고르지 않은 재료의 unknown은 영향 없음. 맵기는 0~3/null, "Not spicy"면 0만.
- **기능 3: 메뉴 목록 · 상세** — 2열 카드(사진 자리 · 번호 · 언어별 이름 · 한국어 이름 · 맵기 · 가격). 상세에 재료 상태·설명·충족 조건·알러지 면책 문구. 뒤로 가면 조건·위치 유지.
- **기능 4: 매장에서 찾기 화면** — 번호·사진·한국어 이름 크게. "Use the number, photo, and Korean name to find the dish." / "Order and pay at the in-store kiosk or table ordering device." 장바구니·담기·주문 버튼 없음.
- **기능 5: 결과 없음 · 초기화** — 조건 모순(치킨 종류 + 닭 제외)이면 완화하지 않고 "No dishes match all your choices." + 조건 고치기·전체 보기.
- **기능 6: 영어 기본 + 한국어 병기** — 첫 접속 영어. 언어 선택은 7개 그대로 두되 영어 외 6개는 "Draft translations" 표시. 번호·한국어 이름·가격·재료 값은 언어와 무관.
- **기능 7: 데이터 파일 분리** — 메뉴·매장 안내·추천·번역을 코드와 분리한 JSON(`menus.json`, `store.json`, `recommendations.json`, `ui-text.json`). 사장님이 값을 한 번에 채우면 화면이 바뀜. `publicationStatus: draft`·`availability: inactive`는 안 보임. 오늘은 샘플 10개(실제 메뉴 이름, "Sample" 표시).
- **기능 8: 사장님 추천** — Recommendations 화면에 사장님 추천 + 이유. 조건 필터가 추천에도 적용. 나라별 탭은 자리만("준비 중").
- **기능 9: How to order · Visit 자리** — 주문 순서 4단계·주소·영업시간 화면. 값은 "확인 예정" 문구, 데이터 업로드 때 채움.

- **이번에 하지 않을 것:**
  - 영어 외 6개 언어 검수 (초안 표시로 둠) → v2
  - 나라별 손님 추천(베트남 순대·몽골 오뎅·일본 갈비만두·김밥) 실제 연결 → v2
  - 메뉴 사진 (회색 자리) → v2
  - 구글 시트 → 점검 → 게시 절차, 품절 켜고 끄기, 관리 화면 → v2
  - 키오스크·테이블오더에 번호 붙이기 확인 → v2 (매장에서 사람이)
  - 구글 비즈니스 링크, QR 인쇄물 → v2 (공개 주소 확보 뒤)
  - 온라인 주문·결제·장바구니·MY PICKS, 실시간 AI 추천·자유 대화, 손님 정보 저장 → 하지 않음

## 6. 완성됐다는 걸 어떻게 확인하나요?

- **시연할 예시 입력:** English → 피하는 재료 "Pork" → 맵기 "Not spicy"
- **기대하는 결과:** 돼지고기 `absent_verified` + 맵기 0인 메뉴만 남고, 표시된 개수와 카드 수가 같음. "Some dishes are excluded because a selected ingredient or spice level is unverified." 안내. 카드 → 상세에서 Pork "Verified absent" · Not spicy 근거 표시 → "Find this dish in store" → 번호·한국어 이름 큰 화면.
- **잘못 입력했을 때:**
  - 음식 종류 "Chicken" + 피하는 재료 "Chicken" → 결과 없음 안내, 조건을 임의로 풀지 않음
  - 고른 재료가 `unknown`인 메뉴 → 결과에서 빠짐. 고르지 않은 재료의 unknown → 영향 없음
  - "Not spicy"일 때 맵기 null 메뉴 → 빠짐
  - 번역이 빈 칸 → 영어로 대체 + 초안 표시. 코드 이름(`menu.name`)이 그대로 보이면 안 됨
  - 잘못된 메뉴 주소 → 목록으로 안내
- **다시 열었을 때 남아 있어야 할 것:** 손님 쪽은 아무것도 안 남음(다음 손님이 앞사람 조건을 보면 안 됨). 사장님이 JSON 값을 바꾸면 다음 접속에 반영.
- **추가 확인:** 320·390·430px 폭에서 가로 스크롤·겹침 없음. 버튼 44px 이상. 어머니 폰에서 글씨 읽히는지.

## 7. v2에서 더할 것 (10/17까지 · API·외부 데이터 등)

- **다음에 추가할 기능 하나:** 구글 시트에 쓴 메뉴·매장·추천·번역을 읽어 점검 → 미리보기 → 게시하는 절차. 사장님이 "한 번에 올리기"를 코드 없이 하게 됨.
- **필요한 데이터나 외부 연결:** 구글 시트 읽기 권한 · 6개 언어 검수자 · 메뉴 사진 · 공개 주소(Vercel) → 구글 비즈니스·QR
- **사람이 직접 판단·확인해야 할 부분:** 재료 `absent_verified`는 육수·소스까지 확인한 뒤 · 번역 검수 · 키오스크·테이블오더 번호 대조 · 품절 표시

## 8. 절대 자동화하면 안 되는 것

- **알러지·안전 판정** — "포함 / 없음 확인됨 / 미확인"까지만. "안전합니다"라고 단정하지 않음. 교차 접촉은 직원에게 묻도록 안내. 육류 없음 ≠ 비건·할랄.
- **실제 주문·결제** — 키오스크·테이블오더에서. 사이트는 아무것도 보내지 않음.
- **번역 확정** — 검수 전 언어는 "초안" 표시 유지. 번역 누락을 "미포함·안 매움"으로 처리하지 않음.
- **가격·품절·메뉴 게시** — 사장님이 확인하고 반영.
- **손님 개인정보·국적 추정** — 저장·추정하지 않음. 언어 선택 ≠ 국적.
- **근거 없는 "1위·인기·베스트"** — 숫자 없이 만들지 않음.
