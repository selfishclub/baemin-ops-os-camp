# 기획안(PRD) — 가영이네 다국어 메뉴 가이드 · v1

- 가게 / 이름: 가영이네 / 박가영
- 조 주제: AI면접관 (개인 주제: 외국인 고객용 다국어 메뉴 추천)
- 이 버전의 목표 한 줄: **외국인 손님이** **메뉴판 앞에서 고민하는 순간에** **자기 입맛에 맞는 분식 메뉴 고르기를** 편하게 처리하는 도구

## 1. 무엇을 왜 만들고 싶나요?

외국인 손님이 늘었는데, 메뉴판 앞에서 한참 멈춰 서 있다가 결국 "김밥"이나 사진이 제일 익숙해 보이는 것 하나만 시키고 나갑니다.

실제로 자주 벌어지는 일:
- "떡볶이가 맵나요?"를 몸짓으로 물어보는데, 바쁜 시간에는 설명할 시간이 없습니다.
- 매운 걸 못 먹는 손님이 떡볶이를 시켰다가 거의 남기고 갑니다.
- 순대·어묵처럼 설명이 필요한 메뉴는 아예 주문이 안 들어옵니다. 맛이 없어서가 아니라 **뭔지 몰라서**입니다.
- 채식이나 못 먹는 재료를 물어보면 주방까지 확인하러 갔다 와야 합니다.

메뉴가 안 팔리는 게 아니라, **설명할 사람이 없어서 못 고르는 것**입니다.

## 2. 누가 언제 쓰나요?

- **쓰는 사람:** 매장에 온 외국인 손님 (본인 휴대폰으로 직접)
- **여는 순간:** 자리에 앉아 메뉴판을 볼 때. 테이블/메뉴판에 붙은 QR을 찍으면 바로 열립니다.
- **직원(저와 어머니):** 설명이 막힐 때 화면을 같이 보며 손가락으로 가리킵니다. 말이 안 통해도 화면이 대신 설명해 줍니다.
- 설치·로그인·앱 다운로드 없이, 브라우저에서 바로 열립니다.

## 3. 지금은 어떻게 하고 있나요?

- 종이 메뉴판 (한글 + 사진, 영어 이름 일부만)
- 손짓과 번역기 앱으로 그때그때 설명
- 맵기는 손가락으로 표시 (통하지 않을 때가 많음)
- 재료·알러지 질문은 주방에 물어보고 다시 나와서 답변

## 4. 도구를 쓰면 어떤 일이 달라지나요?

한 명의 손님 기준으로:

| | 넣는 것 | 나오는 것 |
|---|---|---|
| 1 | 언어 고르기 (English / 中文 / 日本語 / 한국어) | 화면 전체가 그 언어로 바뀜 |
| 2 | 질문 3개에 답하기 — 맵기 / 못 먹는 재료 / 배고픈 정도 | — |
| 3 | — | **추천 메뉴 3개 카드** — 사진, 메뉴 이름(한글 + 읽는 법 + 번역), 한 줄 설명, 맵기 아이콘, 들어간 재료 |
| 4 | 카드 누르기 | 자세한 설명 + "이렇게 주문하세요" 한국어 문장 (직원에게 보여주면 됨) |

직원이 설명하러 가는 대신, 손님이 **스스로 이해하고 고르는 데** 1~2분이면 됩니다.

## 5. v1에서 만들 것 — 오늘(9/17) 안에 되는 것만

- **기능 1: 언어 선택** — 영어 / 중국어 / 일본어 / 한국어 4개. 첫 화면에서 고르면 전체 화면이 바뀝니다.
- **기능 2: 취향 질문 3개** — ① 매운 음식 괜찮으세요? (0~3단계) ② 못 먹는 재료가 있나요? (돼지고기 / 해산물 / 계란 / 밀가루 / 없음, 여러 개 선택) ③ 얼마나 배고프세요? (가볍게 / 보통 / 든든하게)
- **기능 3: 메뉴 카드 결과 화면** — 답에 맞는 메뉴 3개를 카드로 보여줍니다. 각 카드에는 사진, 메뉴 이름 3종(한글 / 로마자 발음 / 번역), 한 줄 맛 설명, 맵기 고추 아이콘, 주요 재료 아이콘, 그리고 **직원에게 보여주는 한국어 주문 문장**이 들어갑니다.
- **기능 4: QR로 접속** — 테이블에 붙일 QR 하나. 찍으면 바로 첫 화면.

- **이번에 하지 않을 것:**
  - 실제 주문·결제·장바구니 (직원에게 보여주고 말로 주문합니다)
  - 로그인, 회원가입, 손님 정보 저장
  - 배민·POS 연동, 실시간 품절 표시
  - 실제 가격 표시 — 가격이 바뀌면 화면도 고쳐야 하므로 v1에서는 뺍니다
  - 번역 API 자동 번역 — 4개 언어 문구를 **직접 확인해서 넣습니다** (분식 이름은 자동 번역이 자주 틀립니다)

## 6. 완성됐다는 걸 어떻게 확인하나요?

- **시연할 예시 입력:** English 선택 → 맵기 "조금만(1단계)" → 못 먹는 재료 "해산물" → "든든하게"
- **기대하는 결과:** 안 매운 편이면서 해산물이 안 들어간 든든한 메뉴 3개가 나옵니다. (예: 김치볶음밥, 돈까스, 잔치국수) 각 카드에 영어 설명과 맵기 아이콘, "김치볶음밥 주세요" 한국어 문장이 함께 보입니다.
- **잘못 입력했을 때:**
  - 못 먹는 재료를 다 고르면 → "조건에 맞는 메뉴가 없어요. 직원에게 물어봐 주세요" + 직원 호출 안내를 한국어로 함께 표시
  - 아무것도 안 고르고 넘기면 → "하나만 골라 주세요" 안내, 다음으로 안 넘어감
  - 뒤로 가기로 답을 고쳐도 결과가 다시 계산돼야 함
- **다시 열었을 때 남아 있어야 할 것:** 아무것도 남지 않아도 됩니다. 손님마다 새로 시작하는 게 맞습니다. (다음 손님이 앞사람 답을 보면 안 됨)
- **추가 확인:** 어머니 휴대폰에서 열어 봐서, 글씨가 읽을 만한 크기이고 버튼이 손가락으로 눌리는지 봅니다.

## 7. v2에서 더할 것 (10/17까지 · API·외부 데이터 등)

- **다음에 추가할 기능 하나:** 손님이 고른 메뉴를 **직원 화면으로 바로 보내기** — 손님이 "이거요" 버튼을 누르면 카운터 화면에 메뉴 이름이 한국어로 뜹니다. (주문 확정은 아니고, 직원이 보고 확인하는 용도)
- **필요한 데이터나 외부 연결:**
  - 메뉴·가격을 한 곳에서 고치면 화면에 반영되게 하기 (Supabase)
  - 어떤 메뉴가 많이 추천되고 실제로 안 나갔는지 기록 → 메뉴 개선에 사용
  - 배민 리뷰 중 외국인 리뷰를 모아 번역해서 카드에 붙이기
  - 언어 추가 (베트남어, 태국어)
- **사람이 직접 판단·확인해야 할 부분:**
  - 번역 문구는 올리기 전에 반드시 사람이 읽어 보고 확정합니다
  - 알러지·재료 정보는 **최종 확인은 직원이** 합니다. 화면은 참고용입니다
  - 품절 표시는 직원이 직접 켜고 끕니다

## 8. 절대 자동화하면 안 되는 것

- **알러지 안전 판정** — "이건 드셔도 안전합니다"라고 화면이 단정하면 안 됩니다. "이 재료가 들어 있습니다"까지만 보여주고, 확인은 직원이 합니다.
- **실제 주문 전송·결제** — 손님 휴대폰에서 바로 주문이 들어가면 안 됩니다. 사람이 받습니다.
- **가격 확정·할인 적용**
- **자동 번역 결과를 확인 없이 그대로 올리기** — 가게 이름과 메뉴 이름은 특히 사람이 봅니다.
- **손님 개인정보 저장** — 이름, 연락처, 답변 기록을 남기지 않습니다.
