# Gayoungene Menu Finder

가영이네 외국인 고객 메뉴 선택 도우미 개발 PRD v1.2

- 문서 목적: 실제 접속 가능한 공개 사이트 제작을 위한 제품 요구사항 정의
- 제품 책임자·정보 확인자: 박가영
- 고객 화면 언어: 다국어. 영어를 기본값으로 두고 언어 선택 제공. 한국어 메뉴명은 모든 언어에서 함께 표시
- 문서 언어: 한국어
- 상태: 제품 방향 확정. 상세 콘텐츠와 배포 환경은 개발·공개 단계에서 확인
- 적용 우선순위: 이번 대화의 최종 결정 → 이 PRD → 이전 화면 시안

## 1. 제품 정의

**외국인 고객이 피하는 재료, 매운 정도, 음식 종류를 선택하면 확인된 메뉴 정보에 근거해 조건에 맞는 음식을 찾도록 돕는 가영이네 전용 사이트다.**

고객은 편한 언어로 조건별 결과, 사장님 추천, 나라별 손님 추천을 살펴보고 메뉴를 결정한 뒤, 매장 키오스크 또는 테이블오더에서 실제 주문·결제를 진행한다. 사이트가 맡는 핵심 역할은 메뉴 선택 지원이다. 전체 메뉴 열람은 이를 보완하는 기능이다.

### 영어 제목과 기본 문구

| 위치 | 영어 문구 |
| --- | --- |
| 사이트 제목 | Gayoungene Menu Finder |
| 첫 화면 제목 | Find food that suits you |
| 첫 화면 설명 | Choose ingredients you avoid, your spice level, and the type of food you want. |
| 주문 장소 안내 | Order and pay at the in-store kiosk or table ordering device. |
| 조건 충족 결과 | Dishes that match your choices |
| 전체 메뉴 | All dishes |
| 추천 메뉴 | Recommendations |
| 사장님 추천 | Owner's picks |
| 나라별 손님 추천 | Guest favorites by country |
| 최종 메뉴 확인 버튼 | Find this dish in store |

고객용 브랜드 영문 표기는 위 제목을 개발 기준으로 사용하되, 공개 전에 공식 표기와 대조한다. 위 문구는 영어 기준 문구이며 선택 언어에 맞춰 번역한다. 서비스 제목은 Gayoungene Menu Finder를 유지하고 설명·조작 문구는 현지화한다. 실제 음식 설명·운영 안내는 자료 검토 후 작성한다.

## 2. 해결할 문제와 대상

### 확인된 문제

- 고기 포함 여부와 맵기 관련 질문을 고객마다 반복 설명해야 한다.
- 음식이 낯설고 언어가 달라 고객이 메뉴를 선택하기 어렵다.
- 육수·소스·가공 재료의 성분은 사진이나 메뉴명만으로 판단하기 어렵다.
- 사이트에서 고른 메뉴를 매장 주문 기기에서 다시 찾기 어렵다.
- 장바구니와 담기 기능은 사이트에서 주문이 완료되는 것처럼 오해하게 할 수 있다.

### 대상과 사용 상황

- 영어 또는 추가 지원 언어로 메뉴를 확인하려는 외국인 고객.
- 먹지 않는 재료가 있거나 매운 음식에 제한이 있는 고객.
- 한국 음식에 익숙하지 않아 음식 종류와 설명을 보고 고르려는 고객.
- 방문 전 구글 비즈니스 등의 링크로 접속하는 고객, 매장 안에서 메뉴를 고르는 고객.

고객을 국적이나 외모로 자동 분류하지 않는다. 나라별 손님 추천은 가영이네에서 관찰한 고객 경험을 고객이 자발적으로 둘러보는 콘텐츠다. 언어 선택을 국적·종교·식사 조건으로 해석하지 않는다.

## 3. 확정 사항과 변경 이력

| 항목 | 최종 결정 |
| --- | --- |
| 첫 화면 | 메뉴 탐색 화면으로 바로 접속. 별도 소개·로그인 화면 없음 |
| 메뉴 선택 도움 | 첫 화면에서 가장 눈에 띄게 표시. 재료·맵기 영역 기본 펼침 |
| 메뉴 목록 | 휴대전화 2열 카드. 메뉴 선택 시 큰 상세 화면 |
| 재료 선택 | 육류·생선/해산물·달걀·유제품 포함 |
| 음식 취향 | 밥·면·치킨 등 음식 종류. 식감 조건은 첫 버전 제외 |
| 전체 메뉴 | 조건을 적용하지 않고 전체 메뉴를 보는 경로 제공 |
| 메뉴 식별 | 고정 메뉴 번호·사진·한국어 이름으로 매장 기기와 대조 |
| 정보 관리 | 구글 시트 작성 → 미리보기 확인 → 사이트 반영 |
| 언어 | 첫 공개 7개 언어 확정: 영어·일본어·베트남어·몽골어·중국어·인도네시아어·프랑스어 |
| 추천 메뉴 | 일반 추천과 나라별 손님 추천 추가. 일반 추천은 사장님 추천 운영안 제안 |
| 메뉴 수 | 미정. 자료 확인 후 결정. 전체 메뉴 수록 목표 유지 |

### 이전 시안에서 폐기한 내용

v1.1에서 영어 단독 제공과 추가 언어 전체 보류 방침을 변경했다. v1.2에서는 사용자 확인에 따라 첫 공개 언어를 영어·일본어·베트남어·몽골어·중국어·인도네시아어·프랑스어 총 7개로 확정했다. 다국어 지원과 추천 카테고리를 이번 개발 범위에 포함한다.

다음 기능은 한때 검토·제작했지만 마지막 제품 방향 변경으로 제외됐다.

- MY PICKS / 고른 메뉴 모아보기
- 장바구니, 수량 조절, 메뉴 담기
- ADD TO MY PICKS 및 상세 화면 상단 장바구니＋ 버튼
- Clear all / Undo를 이용한 선택 목록 관리

이전 시안의 해당 기능을 개발 코드나 완료 기준으로 가져오지 않는다. 재료·맵기 등 **검색 조건 초기화**는 계속 필요하며, 장바구니 전체 삭제와 구분한다.

## 4. 첫 버전 범위

### 포함

1. 언어를 선택할 수 있는 메뉴 선택 도움 화면과 전체 메뉴 목록.
2. 재료·맵기·음식 종류의 복합 조건 선택.
3. 조건에 맞는 결과, 확인 가능한 선택 근거, 결과 없음 안내.
4. 메뉴 상세 및 큰 사진 보기.
5. 번호·한국어 이름·사진을 크게 보여주는 매장 메뉴 찾기 화면.
6. 확인된 주문·결제·수령·셀프바·반납 안내.
7. 확인된 위치·영업시간·길찾기 연결.
8. 구글 시트 원본에서 검토된 데이터만 사이트에 반영하는 관리 절차.
9. 모바일 대응 및 공개 URL 배포.
10. 사장님 추천과 나라별 손님 추천, 추천 근거 표시.
11. 언어별 번역 상태·누락 처리와 공통 메뉴 번호 유지.

### 제외

온라인 주문·결제, 장바구니, 주문 접수, 테이블 번호 전송, POS 연동, 고객 회원가입, 확정 목록 밖의 모든 언어에 대한 무제한 번역, 재료 변경 요청, AI 자유 대화, 고객별 식사 이력 저장, 선결제 신청, AI 면접관, 범용 다매장 서비스.

첫 버전 개발 기본안은 확인된 데이터에 따른 규칙 기반 필터다. 실제 AI 호출은 사용하지 않는다. AI는 개발 과정에서 번역 초안을 돕는 도구로 사용할 수 있으나, 이를 고객용 실시간 AI 추천으로 표시하지 않는다.

## 5. 고객 이용 흐름

```text
사이트 접속
  ↓
펼쳐진 메뉴 선택 도움 영역 + 전체 메뉴
  ├─ 조건 선택 → 조건에 맞는 메뉴
  ├─ 전체 메뉴 탐색
  └─ 추천 메뉴 → 사장님 추천 / 나라별 손님 추천
  ↓
메뉴 상세에서 재료·맵기·설명 확인
  ↓
번호·한국어 이름·사진 크게 보기
  ↓
매장 키오스크 또는 테이블오더에서 주문·결제
```

고객은 어느 단계에서도 언어 변경·이용 안내·방문 안내로 이동할 수 있다. 상세 화면에서 뒤로 가면 선택 조건·추천 카테고리·목록의 위치를 유지한다. 언어를 바꾸어도 현재 메뉴와 식사 조건을 유지한다. 다른 메뉴를 고르기 위해 질문을 처음부터 다시 입력하지 않아야 한다.

## 6. 화면 요구사항

### S01. Menu Finder / 첫 화면

표시 순서:

1. 로고 또는 가영이네 이름, 영어 서비스 제목, 눈에 띄는 언어 선택.
2. 간결한 탐색 메뉴: Menu / Recommendations / How to order / Visit. 좁은 화면에서는 줄바꿈.
3. 강조된 `Find food that suits you` 제목과 짧은 사용 설명.
4. 기본으로 펼쳐진 재료·맵기 선택 영역.
5. 음식 종류 선택.
6. 적용 조건 요약·결과 개수·조건 초기화.
7. 2열 메뉴 카드 목록.

디자인 기준:

- 선택 도움 제목은 본문보다 명확히 크게 표시한다. 초기 설계 목표 20~24px, 중간 이상 굵기.
- 영역 전체 폭과 충분한 여백, 구분되는 배경으로 기능의 위치를 드러낸다.
- 첫 접속 시 고객이 영역을 클릭해야만 질문을 발견하는 구조를 사용하지 않는다.
- 메뉴 목록까지 도달하기 쉽도록 소개 문구와 질문을 짧게 쓴다.
- 조건 버튼과 카테고리는 줄바꿈한다. 가로 스크롤 메뉴를 만들지 않는다.
- 사진·재료 정보가 없는 개발 단계에는 회색 이미지 영역과 샘플 표기를 쓴다.

카드 정보: 사진, Menu No., 선택 언어 메뉴명, 한국어 메뉴명, 원화 가격. 맵기 등 보조 정보는 과밀하지 않은 범위에서 추가한다. 모바일 2열에서 긴 이름은 줄바꿈하고 잘라서 구별 불가능하게 만들지 않는다. 언어에 따라 가격을 환산하지 않으며 실제 판매 가격과 통화는 KRW로 유지한다.

### S02. 메뉴 상세

- 큰 음식 사진, 메뉴 번호, 선택 언어·한국어 메뉴명, 가격·판매 단위.
- 선택 언어의 짧은 설명, 확인된 재료 정보, 맵기와 설명.
- 조건을 적용해 들어온 경우 해당 메뉴가 충족한 조건을 표시.
- 육수·소스·가공 재료는 고객의 선택에 필요한 성분 수준으로 설명.
- 미확인 정보는 확인된 것과 분리해 표시.
- `Find this dish in store` 버튼과 `How to order` 연결 제공.
- 장바구니 아이콘, 담기, 수량, 결제 버튼 없음.

### S03. 매장 메뉴 찾기

- 메뉴 번호·사진·한국어 메뉴명을 크게 표시하고 선택 언어의 이름을 보조 표시.
- 확인된 경우 키오스크/테이블오더 카테고리도 표시.
- `Use this number, photo, and Korean name to find the dish.` 안내.
- `Order and pay at the in-store kiosk or table ordering device.` 안내.
- 주문 완료, 주문번호 생성, 직원 전송 등 실제로 하지 않는 동작을 암시하지 않음.
- 상세 화면으로 되돌아갈 수 있음.

기기별 번호 적용 상태가 다르면 해당 기기에서 실제 사용할 수 있는 식별 정보만 표시한다. 번호만 확인 수단으로 강제하지 않는다.

### S04. How to order / 매장 이용 안내

외국어 변경, 메뉴 선택, 결제, 음식 수령, 셀프바, 식기 반납 순서로 안내한다. 키오스크와 테이블오더의 절차가 다르면 각각 구분한다. 실제 지원 언어·결제 수단·수령 방식을 추정하지 않는다.

### S05. Visit / 방문 안내

확인된 주소·영업시간·휴게시간·마지막 주문·정기/임시 휴무, 지도와 길찾기 링크를 제공한다. 초기에는 지도 삽입 대신 검증한 외부 지도 링크를 사용할 수 있다. 전화·화장실·주차는 자료가 확인되고 필요할 때만 추가한다.

### S06. Recommendations / 추천 메뉴

추천은 두 카테고리로 구분한다. 일반 추천의 운영 기본안으로 사장님 추천을 제안하며, 구체적인 선정 방식은 추후 확정한다.

- `Owner's picks`: 가영님이 직접 선정하고 추천 이유를 확인한 메뉴. 구체적인 메뉴 목록은 미정이다.
- `Guest favorites by country`: 가영이네에 방문한 나라별 손님들이 좋아했던 메뉴. 고객이 원하는 나라를 직접 골라 둘러본다.

나라 목록은 개인 국적을 묻는 설문이 아니다. 누구나 모든 나라의 추천을 볼 수 있다. 음식 종류와 별개인 추천 탐색 기준으로 저장한다. 나라를 선택해도 언어를 바꾸지 않고, 언어를 바꾸어도 추천 나라를 자동 선택하지 않는다.

#### 가영님이 제공한 초기 관찰 사례

| 나라 | 좋아했던 메뉴 | 근거·공개 전 확인 |
| --- | --- | --- |
| 베트남 | 순대 | 가영님이 이 대화에서 제공한 방문 고객 관찰. 실제 상품 id 연결 필요 |
| 몽골 | 오뎅 | 가영님이 이 대화에서 제공한 방문 고객 관찰. 실제 판매명과 상품 구성 확인 필요 |
| 일본 | 갈비만두, 김밥 | 가영님이 이 대화에서 제공한 방문 고객 관찰. 각각 실제 상품 id 연결 필요 |

김밥 종류, 오뎅의 실제 메뉴명·국물/단품 여부 등은 임의로 확정하지 않는다. 갈비만두와 김밥을 자동으로 세트 상품으로 만들지 않는다. 이 연결은 추천 콘텐츠 초안이며 판매 가능·가격·성분이 검증됐다는 의미가 아니다.

고객 문구는 “일본인은 김밥을 좋아합니다” 같은 전체 집단 단정 대신 “가영이네를 찾은 일본 손님들이 좋아했던 메뉴”와 같이 관찰 범위를 드러낸다. 관찰 기간·인원·판매 순위는 자료가 없으므로 만들지 않는다. 숫자 근거 없이 “1위”, “가장 인기”를 표시하지 않는다.

영어 공통 설명 초안: `Dishes enjoyed by guests from different countries who visited Gayoungene.`

#### 추천에도 식사 조건 우선 적용

- 현재 선택한 제외 재료·맵기·음식 종류를 추천 화면에서도 유지하고 상단에 표시한다.
- 승인된 추천 후보와 조건 필터 결과의 교집합만 추천한다.
- 조건에 맞지 않는 메뉴를 나라별 추천이라는 이유로 다시 보여주지 않는다.
- 조건을 선택하지 않았다면 식사 적합성을 판정한 것으로 표시하지 않는다. 원본의 미확인 재료·맵기 표시는 유지한다.
- 추천이 비면 `No recommendations match your choices.`와 `View all matching dishes`를 제공한다. 후자는 식사 조건을 보존하고 추천 카테고리 제한만 해제한다.
- 모든 조건을 없애는 `Clear filters · Show all dishes`와 구분한다.
- 메뉴가 품절·비공개·판매 중단 상태이면 추천에서 제외한다.
- 나라나 추천 이유가 바뀌어도 메뉴 번호와 상세 데이터는 동일 메뉴 원본을 참조한다.

### S07. Language / 다국어 지원

**첫 공개 언어는 영어·일본어·베트남어·몽골어·중국어·인도네시아어·프랑스어 총 7개로 확정했다.**

영어·일본어·베트남어·몽골어 우선안에 중국어·인도네시아어·프랑스어도 첫 공개에 포함한다는 사용자 답변을 반영했다. 한국어는 정보 확인용 원본과 메뉴명 병기로 유지한다. 언어 범위 확정은 번역·구현 완료와 구분하며, 지원 언어가 늘었다는 이유로 나라별 추천 사례를 만들어 넣지 않는다.

| 첫 공개 언어 | 코드 기본안 | 언어 선택 표시 |
| --- | --- | --- |
| 영어 | en | English |
| 일본어 | ja | 日本語 |
| 베트남어 | vi | Tiếng Việt |
| 몽골어 | mn | Монгол |
| 중국어 간체 | zh-Hans | 简体中文 |
| 인도네시아어 | id | Bahasa Indonesia |
| 프랑스어 | fr | Français |

중국어는 간체, 몽골어는 키릴 문자 표기를 구현 기본안으로 둔다. 표기 변형의 필요성은 실제 자료 검토 때 확인하며, 7개 언어를 지원한다는 결정과 구분한다. 위 표는 모든 번역이 작성됐다는 의미가 아니다.

- 첫 접속 기본값은 영어. 상단에서 언어 이름을 눌러 변경할 수 있게 한다.
- 국기만으로 언어를 표시하지 않는다. 언어 자체 이름을 표시한다.
- 언어 변경 시 제목·탐색·조건·결과·재료·맵기·추천 이유·운영 안내까지 일관되게 전환한다.
- 음식 번호·한국어 메뉴명·실제 가격·재료 판정 값은 언어와 무관하게 동일하다.
- 번역은 한국어 원문을 기준으로 검토·승인한 정적 번역을 사용한다. 고객 접속 시 AI가 실시간으로 성분 안내를 새로 생성하지 않는다.
- 공개할 언어는 모든 필수 조작 문구와 공개 메뉴·식사 조건·매장 안내의 번역 검토를 완료해야 한다. 누락이 있으면 해당 언어를 출시 완료로 표시하지 않는다.
- 공개 후 예상치 못한 번역 누락이 발생하면 승인된 영어로 대체하고 대체 표시를 한다. 영어도 없으면 미확인 안내를 표시한다. 빈 문구나 원시 번역 키를 노출하지 않는다.
- 번역의 누락을 미포함·맵지 않음으로 처리하지 않는다. 필터 계산은 번역 텍스트가 아닌 공통 구조화 데이터에서 실행한다.
- 확정한 7개 언어 모두 필수 문구·메뉴·추천·운영 안내 번역과 핵심 흐름 검수를 통과해야 첫 공개의 다국어 요구 완료로 판정한다. 일부 언어만 구현한 버전은 개발/시연 단계이며, 승인된 영어 대체 표시만으로 해당 언어 검수를 완료 처리하지 않는다.

## 7. 조건 선택과 결과 처리

### 7.1 선택 항목

| 조건 | 영어 표시 | 동작 |
| --- | --- | --- |
| 피하는 재료 | Ingredients you avoid | 여러 재료를 동시에 선택·해제 |
| 매운 정도 | Spice level | 허용하는 최대 맵기 하나 선택 |
| 음식 종류 | Food type | 한 종류 또는 All 선택 |

재료: Pork, Beef, Chicken, Fish & seafood, Egg, Dairy. 기타 육류를 사용하는 경우 Other meat를 추가하고 데이터로 관리한다. 단순히 앞의 세 육류가 없다는 이유로 육류 전체가 없다고 표시하지 않는다.

음식 종류의 예: Rice, Noodles, Chicken, Snacks. 실제 판매 메뉴와 맞지 않는 카테고리는 공개하지 않는다. Chicken 음식 종류와 Chicken 제외 조건을 동시에 고르면 모순을 임의로 해소하지 않고 결과 없음으로 처리한다.

맵기는 `0 맵지 않음 / 1 약간 매움 / 2 매움 / 3 매우 매움 / null 미확인`으로 관리한다. 이 값은 내부 분류이며 객관적 매운맛 측정치로 주장하지 않는다. 고객은 Any spice level, Not spicy, Up to mildly spicy, Up to spicy, Very spicy is OK 중 선택한다.

### 7.2 재료 판정 상태

각 재료마다 다음 세 상태를 별도로 저장한다.

- `contains`: 포함이 확인됨.
- `absent_verified`: 기본 조리 전체에서 미포함이 확인됨.
- `unknown`: 성분 정보가 부족하거나 아직 확인하지 않음.

`absent_verified`는 눈에 보이는 재료뿐 아니라 육수·소스·양념·가공 재료의 확인도 포함한다. 서로 충돌하는 자료가 있으면 확인 전까지 `unknown`으로 둔다.

육류 미포함을 비건·채식·할랄 적합 또는 알레르기 안전으로 확대 해석하지 않는다. 재료 필터는 확인된 레시피 성분을 안내하며, 교차 접촉까지 없다는 보증이 아니다. 고객에게 필요한 범위에서 이를 간결하게 안내한다.

### 7.3 필터 규칙

```text
기본 대상 = 공개 승인된 실제 판매 메뉴

조건을 적용한 결과:
  선택한 모든 제외 재료가 absent_verified
  AND 확인된 맵기가 선택한 상한 이하
  AND 선택한 음식 종류와 일치

선택하지 않은 조건은 판정에 사용하지 않음
조건을 충족하는지 미확인이면 결과에서 제외
미확인 메뉴는 전체 메뉴에서 확인 필요 표시
```

- 선택한 조건을 모두 충족해야 결과에 포함한다.
- 달걀만 피하는 고객의 결과를 유제품 미확인만으로 제외하지 않는다. 실제 선택한 항목별로 평가한다.
- 조건을 선택하면 같은 화면의 목록을 갱신한다. 별도 회원가입·필수 설문 없음.
- 전체 메뉴의 조건 결과는 기본 표시 순서로 제공한다. 추천 화면에서는 6장의 승인된 추천 연결과 표시 순서를 함께 적용한다. 근거 없는 인기·베스트·적합도 점수를 만들지 않는다.
- 결과가 없으면 `No dishes match all your choices.`와 조건 수정·전체 보기 경로를 제공한다.
- `Clear filters · Show all dishes`는 제외 재료·맵기·음식 종류와 추천 카테고리 제한을 모두 초기화해 전체 메뉴로 이동한다. 선택한 화면 언어는 유지한다.
- 결과 개수는 실제 화면에 표시되는 메뉴 수와 일치해야 한다.
- 미확인 안내는 현재 선택 조건 때문에 제외된 항목이 있을 때 표시한다.

### 7.4 선택 근거

결과의 근거는 필터에 사용한 동일 데이터에서 생성한다. 예를 들어 달걀 제외·맵지 않음을 선택했다면 달걀 미포함 확인과 맵기 0을 근거로 안내한다. 모든 재료가 안전하다거나 해당 고객에게 반드시 적합하다고 단정하지 않는다.

## 8. 메뉴 번호와 기기 대조

- 고객용 번호는 문자열 `001`처럼 관리해 앞자리 0이 사라지지 않게 한다.
- 번호는 메뉴마다 고유하며 정렬·카테고리·가격 변경과 무관하게 유지한다.
- 판매 중단 번호를 다른 메뉴에 재사용하지 않는다.
- 기기에서 별도 상품인 크기·세트는 별도 번호, 상품 내부 옵션은 기본 번호와 옵션명을 사용한다.
- 고객에게는 `Menu No.`로 표시하고 결제 후의 주문번호와 구분한다.
- 가영님은 키오스크 메뉴명 수정·사진 교체가 가능하다고 확인했다. 기존 고객용 번호는 없다.
- 테이블오더의 메뉴명·사진 변경 가능 여부와 번호 동기화 방식은 아직 확인하지 않았다.
- 현재 입력 시트의 `M001` 등은 작성 구역 식별자다. 실제 메뉴와 대조 후 고객용 번호를 부여한다.

이미지 원본은 번호 없이 보관한다. 사이트는 화면 요소로 번호를 올린다. 키오스크 등록용은 필요 시 번호를 넣은 사본을 만든다. 실제 기기에서 잘림·가독성·번호 일치 여부를 확인한다.

## 9. 데이터 구조

### 9.1 메뉴 원본

| 필드 | 형식 | 목적 |

| id | string | 변하지 않는 내부 식별자 |
| menuNumber | string | 고객용 고정 번호 |
| nameKo | string | 기기 대조에 쓰는 한국어 메뉴명 |
| translations | 언어 코드별 객체 | 검토 상태를 포함한 다국어 고객 설명 |
| categoryId | string | 음식 종류 연결 |
| priceKrw | integer 또는 null | 원화 가격. 미입력과 0을 구분 |
| servingKo | string | 판매 단위·구성 원문 |
| descriptionKo | string | 메뉴 설명 원문 |
| imageAsset / imageAltKo | string | 승인된 사진과 대체 텍스트 원문 |

| spiceLevel | 0~3 또는 null | 확인된 맵기 |
| spiceNoteKo | string | 맵기에 대한 보조 설명 원문 |
| salesNoteKo | string | 시간·계절 등 확인된 판매 조건 원문 |
| kiosk / tableOrder | 기기별 객체 | 표시명·카테고리·번호 적용 확인 |
| publicationStatus | draft / approved | 고객 공개 승인 상태 |
| availability | available / sold_out / inactive | 판매 상태 |
| verifiedAt | 날짜 또는 null | 원본 정보를 확인한 날짜 |
| revision | string | 검토·공개한 데이터 버전 |

translations의 언어별 항목은 name, serving, description, ingredientNote, spiceNote, salesNote, imageAlt다. 관리 원본에는 언어별 draft/approved 상태, 검토일, sourceRevision을 둔다. 원문이 바뀌면 관련 번역을 재검토 대상으로 전환하고, 새로운 재료 정보에 이전 번역을 붙여 공개하지 않는다. 언어에 관계없이 가격·번호·재료 상태·맵기 값은 공통 데이터를 사용한다.

내부 관리 원본에는 제품 라벨·공급업체 답변 등 확인 근거와 사진 사용 확인, 미해결 질문, 승인 메모를 보관한다. 고객용 데이터에는 공개할 필드만 추려 넣는다. 원본 시트 전체, 연락용 개인 정보, 비밀 레시피, 인증 정보는 고객 화면이나 공개 데이터에 포함하지 않는다.

### 9.2 공개 판정

- 실제 판매 메뉴의 번호·이름·가격·사진·한국어 설명과 공개 언어별 번역을 확인하고 공개 승인해야 전체 메뉴에 표시한다.
- 재료·맵기가 미확인인 메뉴도 그 상태를 명확히 표시하면 전체 메뉴 열람 대상으로 승인할 수 있다.
- 단, 해당 미확인 조건이 적용된 추천 결과에는 포함하지 않는다.
- `sold_out`은 전체 메뉴에서 품절을 표시하고 추천 결과에서는 제외한다. 자동 실시간 재고 연동은 하지 않는다.
- `inactive`와 `draft`는 고객 화면에 표시하지 않는다.

### 9.3 매장 정보

한국어 원문과 언어별 번역으로 매장명, 소개, 주소, 기기별 주문 안내, 수령·셀프바·반납 안내를 관리한다. 지도 링크, 요일별 영업시간, 휴게·마지막 주문, 임시 휴무, 확인일은 공통 사실로 저장한다. 미확인 값은 개발 미리보기에서만 입력 예정으로 표시하고, 고객 공개 전 필수 방문·이용 정보를 확인한다.

### 9.4 추천과 언어 데이터

| 필드 | 목적 |
| --- | --- |
| recommendationId | 추천 항목의 고유 식별자 |
| type | owner 또는 country_guest |
| countryCode | 나라별 추천의 VN / MN / JP 등. 일반 추천은 null |
| menuId | 승인된 실제 메뉴와 연결 |
| reasonKo / reasonTranslations | 추천 이유 원문과 검토된 번역 |
| sourceType | owner_observation 등 확인된 근거 종류 |
| observationNote | 사장님의 관찰 기록. 횟수·기간은 알려진 경우만 기록 |
| sortOrder | 직접 정한 표시 순서. 판매 순위로 해석하지 않음 |
| status | draft / approved |

순대·오뎅·갈비만두·김밥이라는 관찰 기록을 실제 메뉴 id에 연결하기 전에는 추천 초안으로 보관한다. 유사한 이름만으로 임의 연결하거나 공개하지 않는다. 동일 메뉴는 여러 나라 추천에 연결할 수 있다.

메뉴 설명과 별도로 언어별 UI 사전을 두고 탐색·필터·음식 종류·나라 이름·재료 이름·오류·빈 결과 문구를 관리한다. 공개 언어 목록에는 검토를 완료한 언어만 등록한다.

## 11. 구현 기본안

### 구조

- 정적 반응형 웹을 기본으로 한다. HTML·CSS·JavaScript와 별도 메뉴·매장·추천·번역 JSON 데이터로 구현 가능하다.
- 메뉴 조건 판정은 독립된 순수 함수로 작성해 화면과 분리한다.
- 메뉴 상세는 고정 메뉴 id 또는 번호에 연결한다. URL의 메뉴 식별자가 잘못되면 메뉴 목록으로 돌아가는 안내를 제공한다.
- 언어·조건·추천 나라·목록 위치는 현재 방문 중의 상태로 유지하고, 상세에서 돌아왔을 때 복원한다. 언어 변경으로 필터를 초기화하지 않는다. 고객 계정·식사 이력·추정 국적 프로필은 저장하지 않는다.
- 메뉴 데이터가 바뀌어도 화면 코드를 메뉴마다 다시 수정하지 않도록 구성한다.
- 공개 데이터는 승인된 스냅샷이며, 고객 브라우저에서 비공개 구글 시트에 직접 접근하지 않는다.

### 호스팅과 비용

- 호스팅은 공개 HTTPS 링크와 모바일 접속, 버전 교체·복구가 가능한 방식으로 선택한다.
- 이 환경에서 개발하는 경우 Sites를 우선 구현 경로로 검토한다. 캠프의 다른 개발 도구에도 적용할 수 있도록 제품 요구사항과 데이터 구조를 분리한다.
- 실제 호스팅 제공자·공개 접근 설정·요금·사용량 한도는 배포 시 확인한다. 현재 비용이나 무료 제공을 확정하지 않는다.
- 첫 버전은 실시간 AI API·온라인 결제·런타임 DB를 필수로 요구하지 않는다.
- 구글 비즈니스에 넣을 링크 위치와 설정은 실제 배포 URL 확보 후 확인한다.
- 계정 이메일·비밀번호·API 키는 PRD나 고객용 데이터에 기입하지 않는다.

## 12. UI·접근성·품질 기준

- 영어를 첫 접속 기본 언어로 두고 언어 선택을 제공한다. 선택 언어에 맞게 문서 lang과 고객 문구를 변경하고, 한국어 메뉴명은 항상 병기한다.
- 언어별 글꼴 대체와 줄바꿈을 확인한다. 한글·라틴 문자·일본어·키릴 문자 등 공개 언어의 문자가 누락되지 않아야 한다.
- 사진·메뉴명·가격을 읽기 위해 가로 스크롤이 필요하지 않아야 한다.
- 320px, 390px, 430px 폭과 데스크톱에서 버튼·문구가 겹치거나 잘리지 않아야 한다.
- 2열 목록을 유지하되 글자 확대 환경에서는 내용 손실 없이 재배치할 수 있게 한다.
- 터치 버튼은 약 44px 이상의 조작 영역을 확보한다.
- 선택 상태를 색만으로 표현하지 않고 체크·텍스트·테두리 등으로 함께 구분한다.
- 키보드로 조건 선택, 상세 열기, 뒤로 이동이 가능해야 한다.
- 결과 변경과 결과 없음은 보조기기에도 전달한다.
- 이미지에 대체 텍스트를 제공하고, 이미지가 늦게 로드돼도 번호·이름·가격을 확인할 수 있게 한다.
- 브랜드 로고·색상·폰트는 전달·확인된 원본을 적용한다. 이번 대화에서 미확정인 디자인 값을 과거 자료로 채워 넣지 않는다.
- 외부 지도 외 핵심 메뉴 선택 흐름은 불필요한 외부 서비스 응답을 기다리지 않도록 한다.

## 15. 성과 확인

첫 버전은 임의의 매출·전환 목표를 만들지 않고 아래 항목을 실제 고객 관찰로 확인한다.

- 고객이 화면 언어와 추천 나라를 각각 선택하고 추천에도 자신의 식사 조건이 적용됨을 이해하는가.

운영 전후 관찰 기준을 동일하게 두고, 구체적인 수치 목표는 기준값을 확보한 뒤 정한다. 고객 추적 도구와 개인별 행동 수집은 이번 범위에 넣지 않는다.

### 완료 또는 확정

- 목적·대상·메뉴 선택 중심의 제품 방향과 첫 공개 7개 언어 지원 범위.
- 일반 추천과 나라별 손님 추천 추가. 나라별 관찰 사례는 베트남 순대, 몽골 오뎅, 일본 갈비만두·김밥.
- 2열 목록·큰 상세·재료/맵기/음식 종류 조건.
- 장바구니 제외와 실제 주문 장소 구분.
- 키오스크 공통 메뉴 번호 운영 방향.
- 입력용 구글 시트 생성.
- 본 개발 PRD 작성.

### 아직 완료되지 않음

- 기존 화면 시안의 최종 방향 반영. 현재 이전 시안에는 장바구니 기능이 남아 있다.
- 실제 메뉴·가격·사진·재료·맵기 검증 및 첫 버전 메뉴 수 결정.
- 확정한 7개 언어의 번역 작성·검토와 표기 방식 점검.
- 일반 추천의 구체적인 운영 방식과 메뉴 목록 확정, 나라별 관찰의 실제 메뉴 id 연결.
- 기기별 메뉴 번호 적용 및 테이블오더 대조 방식 확인.
- 구글 시트의 다국어·추천·번호·승인 항목 보완과 데이터 반영 절차 구현.
- 브랜드 원본 적용, 실제 운영 안내·위치·시간 확인.
- 공개 사이트 구현·배포, 구글 비즈니스 연결, 실제 고객 검증.

### 개발을 시작할 때 지켜야 할 지시

```text
이 PRD를 최종 기준으로 사용한다.
영어 제목은 Gayoungene Menu Finder다.
다국어 선택과 일반·나라별 손님 추천을 구현한다.
언어를 국적이나 식사 조건으로 추정하지 않는다.
나라별 추천에도 선택한 재료·맵기 조건을 우선 적용한다.
메뉴 선택 도움 영역은 처음부터 펼쳐 보여준다.
장바구니·MY PICKS·담기·수량 기능을 만들지 않는다.
실제 주문은 키오스크·테이블오더에서 진행한다.
실제 자료가 없으면 명확히 표시한 테스트 데이터를 쓴다.
확인되지 않은 성분·맵기·운영 정보를 추정하지 않는다.
메뉴 개수는 입력 양식의 칸 수로 확정하지 않는다.
문서·시연 화면·공개 운영 사이트의 완료를 구분한다.
```
