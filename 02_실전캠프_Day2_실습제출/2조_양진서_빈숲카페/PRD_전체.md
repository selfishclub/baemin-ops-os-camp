## 0. 기능보다 앞서는 조건 — 레시피 유출 방지

- **실제 레시피는 저장소·시연에 절대 넣지 않는다.** 캠프 저장소와 개인 Public 저장소, Vercel 시연 주소에는 가짜 데이터만. 실제 레시피는 데이터 창고(Supabase)에만 둔다
- **로그인한 직원만 본다.** 인터넷 주소를 알아도 로그인 없이는 메뉴 이름조차 보이지 않는다. 퇴사하면 사장이 계정을 끈다
- 이미지·영상에는 "빈숲카페 · 보는 직원 이름 · 날짜" 워터마크 층을 얹는다 (스크린샷으로 유출되면 누가 찍었는지 남게)
- 알림은 카톡·문자가 아니라 포스기의 빈숲OS 화면에 띄운다 (밖으로 나가는 연결 없음)
- **유출 금지 안내를 둔다.** 모든 페이지 맨 아래에 "레시피 등 카페 정보 유출 금지" 버튼을 두고, 누르면 전문(모든 권리는 빈숲카페에 있음 · 무단 촬영·복사·반출 금지 · 위반 시 조치)이 펼쳐진다. 인쇄물 하단에도 표시한다. 레시피뿐 아니라 화면·문구·디자인·프로그램도 포함한다

## 1. 배경 — 최근 실제로 있었던 한 장면

- 장면: 새로 온 직원이 아메리카노 비율을 몰라서 카톡방을 뒤지다가, 예전 버전 레시피 사진을 보고 잘못 만듦. 더 큰 문제는 직원이 헷갈릴 때 찾아보지 않고 **본인이 외운(잘못된) 방식대로 그냥 만들고, 그걸 신입에게도 그대로 전달**하는 것
- 발견한 뒤에 한 일: 그 직원에게만 직접 알려줌. 다른 직원은 같은 방식으로 만들고 있어도 모르고 지나감. 기록도 남지 않음
- 글로 된 레시피(엑셀)는 있음. 빠진 건 "손으로 어떻게 하는지"가 보이는 영상이라 지금 직접 찍고 있음
- 얼마나 자주: 레시피를 다시 찾아보는 건 직원당 주 1~2회. "잘못된 자기 방식대로" 만드는 게 발견되는 건 한 달에 2~3번
- 한 번에 걸리는 시간: 찾아볼 때는 1분 이내(짧게 확인하고 넘어감) — 그래서 안 찾아보고 그냥 만드는 게 더 문제
- 실수·빠뜨림: 잘못된 레시피가 신입에게 그대로 전달돼 굳어지는 것이 핵심 리스크

## 2. 쓰는 사람과 역할

- 매장 1곳 · 정직원 3명 + 파트타임 4명
- 매장 포스기에는 사장이 HTML로 만든 **빈숲OS**가 이미 떠 있음. 레시피북 알림은 그 화면에 붙임

| 누가 | 언제 여나 | 무엇을 보나 | 무엇을 누르나 | 어떤 기기로 |
|---|---|---|---|---|
| 사장(양진서) | 레시피를 새로 등록·수정할 때, 누가 안 봤는지 볼 때 | 레시피 편집 화면, 확인 현황, 직원 계정 관리 | 저장, "직원 확인 필요" 체크, 계정 켜기/끄기, 신입 체크 "확인함" | PC |
| 직원(정직원·파트타임) | 근무 중 메뉴 제조가 헷갈릴 때, 빈숲OS에 "바뀐 레시피" 알림이 떴을 때 | 로그인 → 레시피 검색·상세, 바뀐 레시피 목록 | 검색, "확인했어요", 프롬프트 생성 버튼 | 포스기·매장 태블릿·직원 휴대폰 |
| 신입 | 첫 2주 교육 기간 | 신입 체크리스트, 퀴즈 | 메뉴별 "만들어 봤음" 체크, 퀴즈 풀기 | 매장 태블릿·휴대폰 |

## 3. 흐름 — 지금 vs 도구를 쓰면

| 단계 | 지금 (쓰는 앱·파일) | 도구를 쓰면 |
|---|---|---|
| 1 | 카톡방·엑셀·사진에서 레시피 찾기 | 로그인 → 레시피북에서 메뉴 이름 검색 |
| 2 | 여러 버전 중 어떤 게 최신인지 헷갈림 | 하나로 정리된 최신 레시피(재료·비율·순서·최종 수정일) 확인. 영상·사진과 "자주 틀리는 포인트"도 같은 화면에 |
| 3 | 잘못 만든 걸 발견하면 그 직원에게만 말로 알려줌 | 사장이 레시피를 고치고 "직원 확인 필요" 체크 → 빈숲OS에 "바뀐 레시피 1건" → 직원마다 "확인했어요" → 사장은 안 본 사람이 누군지 봄 |
| 4 | 신입 교육은 옆에서 보여 주고 기억에 맡김 | 신입이 메뉴별로 "만들어 봤음" 체크 → 사장이 "확인함" → 퀴즈로 마무리 |
| 5 | (레시피 영상은 직접 기획·촬영) | 레시피 상세에서 영상 프롬프트 자동 생성 → 찍은 영상을 레시피에 붙임 → 챗봇에게 물어서 바로 답 받기 |

## 7. 예외 — 잘못 넣거나 평소와 다를 때

- 없는 메뉴를 검색하면 → "레시피를 찾을 수 없습니다" 안내
- 로그인 없이 주소로 들어오면 → 로그인 화면만 보임. 메뉴 이름도 안 보임
- 퇴사 직원 계정을 사장이 끄면 → 그 순간부터 로그인 안 됨
- 레시피 저장 시 재료·비율이 비어 있으면 → 저장하지 않고 안내
- 사장이 오타만 고쳤을 때 → "직원 확인 필요"를 체크하지 않으면 알림·읽음 확인 없이 저장 [가정]
- 직원이 읽지 않고 "확인했어요"만 누르면 → 도구가 막을 수 없음. 퀴즈와 사장 확인으로 보완 (8번)
- 레시피북에 없는 메뉴를 챗봇에 물으면(v2) → 임의로 답하지 않고 "레시피북에 없는 메뉴입니다"라고 답변
- 레시피 데이터가 비어 있는 상태로 프롬프트 생성 버튼을 누르면 → 생성하지 않고 안내

## 9. 성공 기준 — 숫자로

- 지금: 레시피를 찾아보는 것 자체는 1분 이내로 짧지만, 안 찾아보고 "외운 대로" 잘못 만드는 경우가 한 달에 2~3번. 발견해도 그 직원에게만 말로 알려줘서 기록이 없음
- 목표(v1): 검색·최종 수정일 확인으로 30초 이내에 최신 레시피 확인, "자기 방식대로" 잘못 만들어 신입에게 전달되는 사례 0건
- 목표(v2): 레시피를 바꾼 뒤 3일 안에 직원 7명 전원 읽음 확인 [가정] · 신입은 첫 2주 안에 핵심 메뉴 체크리스트 완료 [가정] · 로그인 없이 레시피가 보이는 경로 0개
- 시연할 예시 입력 → 기대하는 결과: "아메리카노" 검색 → 재료·비율·순서 표시, 프롬프트 버튼 클릭 → 해당 레시피 기반 영상 프롬프트 문장 생성. (v2) 사장이 아메리카노 물 양을 고치고 "직원 확인 필요" 체크 → 빈숲OS에 "바뀐 레시피 1건" → 알바A가 확인 → 사장 화면에 "안 본 사람 6명"

## 11. 아직 정하지 못한 것

- **최종 목표(나중에 따로, 단계적으로):** 챗봇이 있는 카페 전체 매뉴얼 포털 "빈숲 OS" — 빈숲의 기준, 오픈·미들·마감, 신입 30일 교육, 고객응대·주문·결제, 위생·안전, 바리스타 기초, 레시피, 재고·정산, 기기, 비상 대응 + 역할별 권한, 체크리스트·영업일지, 시험·인증·승급, 알림, 다지점. 이 공개용 버전에는 구조와 가짜 예시만 두고 실제 운영 내용·수치·정책 값은 넣지 않는다. 캠프 과제 범위는 레시피 영역까지
- ~~"준비 중" 영역을 어떤 순서로 열지, 매뉴얼 문서 틀을 언제 만들지~~ → 9/20 문서형 영역 8개를 한 번에 열고 문서 틀을 만듦. 남은 것: 문서에 **연결된 체크리스트(오픈·마감 체크 기록)·시험**을 붙일지, 매뉴얼이 바뀌었을 때도 레시피처럼 "확인했어요"를 받을지(공지·변경 이력 영역), 문서에 사진·영상을 붙일지
- 교육 경로의 실제 기간·단계(며칠차에 무엇을)와 "확인함"을 누가 누를 수 있는지(사장만 vs 매니저도) — 지금은 사장만. 수습·평가와 연결되는 부분은 노무 기준 확인 필요
- 실제 데이터 넣는 길: 관리자 편집에 "엑셀·표 붙여넣기로 가져오기"(미리보기·검증 후 초안으로만, 게시는 사장이) — 아직 안 만듦. 실제 데이터는 저장소에 넣지 않고 로그인을 다시 켠 뒤 데이터 창고에만
- 대외비 안내 문구의 법적 효력 — 확인 필요. 근로계약서·비밀유지 서약서에 같은 취지의 조항을 넣을지, 노무사·변호사 확인을 받을지
- 빈숲OS와 레시피북을 한 앱으로 합칠지, 빈숲OS 첫 화면에 배지+링크만 붙일지 [가정: 배지+링크]
- 빈숲OS 배지가 "안 읽은 건수"를 어떻게 알아 오나 (데이터 창고에서 직접 읽기 vs 레시피북이 주는 주소 하나) — 구현 때 정함
- 오타만 고쳤을 때도 직원 확인을 받을지 [가정: 사장이 체크할 때만]
- 영상 파일을 어디 둘지 (데이터 창고 파일함 vs 유튜브 '일부 공개' 링크). 유출 기준으로 판단
- 워터마크 층만으로 충분한지, 파일에 새겨야 할지 (써 본 뒤)
- 직원 폰에서도 열게 했을 때 매장 밖에서 보는 걸 막을지 (지금은 로그인만으로 충분하다고 봄)
- 챗봇 답변에 참고 레시피 링크 외에 이미지까지 보여줄지
- 자주 틀리는 포인트 칸을 오늘 v1에 당길지
