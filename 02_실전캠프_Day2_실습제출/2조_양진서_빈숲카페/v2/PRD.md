# 기획안(PRD) — 빈숲 레시피북 · v2

> 초안 — v1을 써 본 뒤 고칩니다

- 가게 / 이름: 빈숲카페 / 양진서
- 조 주제: 직원 교육 매뉴얼 온라인 북 — 레시피북
- 이 버전의 목표 한 줄: 로그인한 직원만 보는 레시피북. 사장이 레시피를 고치면 포스기 빈숲OS에 알림이 뜨고, 직원 7명 중 누가 확인했는지 보이는 도구

> 아래 칸을 채우기 어려우면 AI에게 이렇게 말하세요.
> "내가 하는 일은 ○○인데 매번 ○○이 힘들어. 이 PRD.md 양식대로 v1과 v2를 나눠서 기획안을 써 줘."

## 1. 무엇을 왜 만들고 싶나요?

v1은 최신 레시피를 검색해 보는 데까지입니다. 그런데 실제 사고는 "찾아보는" 순간이 아니라 그 뒤에 납니다. 직원이 자기 방식대로 잘못 만든 걸 발견하면 지금은 그 직원에게만 말로 알려주고 끝나서, 다른 직원이 같은 방식으로 만들고 있어도 모르고, 기록도 남지 않습니다. 사장이 레시피를 고치면 **직원 전원이 봤는지 확인되게** 만들고 싶습니다.

그리고 레시피는 영업 비밀이라 **밖으로 새는 게 절대 싫습니다.** 인터넷 주소로 열더라도 로그인한 직원만 보게 하고, 퇴사하면 바로 막을 수 있어야 합니다.

## 2. 누가 언제 쓰나요?

- 사장: PC에서 레시피를 고칠 때, "직원 확인 필요"를 체크해서 저장하고, 누가 아직 안 봤는지 확인
- 직원(정직원 3명 + 파트타임 4명): 포스기의 빈숲OS 첫 화면에 "바뀐 레시피 N건" 배지가 뜨면 눌러서 보고 "확인했어요". 매장 태블릿·휴대폰에서는 로그인 뒤 검색
- 신입(여유 있으면): 첫 2주 동안 메뉴별 체크리스트와 퀴즈

## 3. 지금은 어떻게 하고 있나요?

v1 레시피북을 메뉴 이름으로 검색해서 확인하고 있습니다. 레시피가 바뀌면 카톡방에 올리거나 말로 전하고, 누가 봤는지는 모릅니다. 포스기에는 사장이 HTML로 만든 빈숲OS가 떠 있지만 레시피북과는 연결돼 있지 않습니다.

## 4. 도구를 쓰면 어떤 일이 달라지나요?

사장이 아메리카노 물 양을 고치고 "직원 확인 필요"를 체크해 저장하면 → 빈숲OS 첫 화면에 "바뀐 레시피 1건" → 직원이 눌러서 보고 "확인했어요" → 사장 화면에 "확인 1명 · 안 본 사람 6명". 로그인 없이 주소로 들어오면 메뉴 이름조차 보이지 않습니다.

## 5. v2에서 만들 것 — 10/2 1차 마감 · 10/17 최종 (API 연동·외부 데이터 등 v1에서 미룬 것)

**꼭 할 것** (10/2까지)
- 기능 1: **직원 로그인·권한 + 사장 편집 화면** — 직원별 아이디·비밀번호. 사장만 편집(등록·수정, 저장 시 최종 수정일 자동, "직원 확인 필요" 체크), 직원은 보기만. 퇴사자는 사장이 계정을 꺼서 즉시 차단. 직원 계정 관리 화면 포함
- 기능 2: **바뀐 레시피 읽음 확인 + 빈숲OS 알림** — "직원 확인 필요"로 저장된 레시피마다 직원이 "확인했어요". 사장 화면(확인 현황)에 안 본 사람 표시. 포스기 빈숲OS 첫 화면에 "바뀐 레시피 N건" 배지를 붙이고 누르면 레시피북으로

**여유 있으면** (순서대로. 10/17까지)
- 1순위: 신입 메뉴 체크리스트(신입 "만들어 봤음" → 사장 "확인함") + 레시피 퀴즈(레시피 데이터로 문제 자동 생성)
- 2순위: 영상·사진 붙이기 + 워터마크 층("빈숲카페 · 보는 직원 이름 · 날짜" 반투명, 우클릭 저장·다운로드 버튼 없음) + 자주 틀리는 포인트 칸
- 3순위: 변경 이력 보기 (이전 비율 ↔ 지금 비율 비교)
- 4순위: 챗봇 UI + AI 응답 — 로그인 뒤에서만. 레시피북에 없는 메뉴는 "없는 메뉴입니다"라고만 답함. 답변에 원본 레시피 링크·최종 수정일

**준비물**
- 데이터 창고(Supabase) 가입 — 사장님이 직접. 열쇠(Project URL, anon 키)는 `.env.local`과 Vercel 환경변수에만, PRD·채팅에 적지 않음. 접근 규칙(RLS)으로 로그인한 사람만 읽게
- 빈숲OS HTML 파일 — 배지 한 줄을 붙일 자리 확인 (파일은 캠프 저장소에 올리지 않음)
- (4순위) AI 응답 API 키 발급 — 사장님이 직접

**시연·저장소 규칙**
- 캠프 저장소·개인 Public 저장소·Vercel 시연 주소에는 **가짜 레시피만**. 실제 레시피는 데이터 창고에만
- 직원 이름은 "알바A"처럼 가짜로

- **이번에 하지 않을 것:** 카톡·문자 알림(빈숲OS 알림으로 대신), 음성 검색, 재료 원가 계산, 워터마크를 파일에 새기기, 실제 영상 생성

## 6. 완성됐다는 걸 어떻게 확인하나요?

- 시연할 예시 입력: 사장 로그인 → 아메리카노 물 150ml → 170ml로 고치고 "직원 확인 필요" 체크 → 저장
- 기대하는 결과: 빈숲OS 첫 화면에 "바뀐 레시피 1건" → 알바A로 로그인해 확인 → 사장 확인 현황에 "확인 1명(알바A) · 안 본 사람 6명"
- 잘못 입력했을 때: 로그인 없이 주소로 들어오면 로그인 화면만 / 재료·비율이 비면 저장 안 됨 / 꺼진 계정으로 로그인하면 거부
- 다시 열었을 때 남아 있어야 할 것: 레시피 전체, 직원 계정과 상태, 누가 언제 확인했는지 기록

## 7. 그 다음에 더하고 싶은 것

- 다음에 추가할 기능 하나: 카톡·문자 변경 알림 — 직원이 매장 밖에서도 바뀐 걸 알아야 할 때. 알림톡 심사 필요
- 필요한 데이터나 외부 연결 (API, 배민 데이터, 날씨 등): 카톡 알림톡 / 영상 생성 API
- 사람이 직접 판단·확인해야 할 부분: 알림 보내기 버튼은 사장이 직접. 생성된 영상이 실제 레시피와 맞는지 확인

## 8. 절대 자동화하면 안 되는 것

- 레시피 원가·판매가 확정
- 레시피 수정 확정과 "직원 확인 필요" 판단 (사장)
- 직원 계정 만들기·끄기 (사장)
- 신입 체크리스트의 "확인함" 판정 (사장이 직접 보고)
- 실제 영상 파일 생성·게시
- 직원에게 보내는 메시지 발송
